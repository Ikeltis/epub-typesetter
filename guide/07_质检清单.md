## 0. 规则字段与约定

### 0.1 字段

| 字段 | 取值与含义 |
|---|---|
| ID | `{类别}-{三位序号}`。类别：STR 打包与结构、SEM 内容文档良构与语义、STY CSS 样式、TYP 排版质量、RES 资源、TXT 文本规范化、A11Y 无障碍。**编号永不复用**；废弃的规则保留编号并写「（已废弃）」 |
| 优先级 | P0 = MVP 必做；P1 = 第二阶段（多需启发式或确认）；P2 = 可选/低频/依赖大模型 |
| 说明 | 问题本身是什么（判定标准）。只描述问题，不写怎么改 |
| 严重度 | `error` 违反规范或几乎必然导致阅读异常；`warning` 合规但质量缺陷或兼容风险；`info` 提示/统计，不计入失败 |
| 修复等级 | `auto` 确定性、可回滚、无需确认，默认直接执行；`suggest` 规则可算出修改但有误伤风险，生成补丁并要求用户确认；`llm` 需大模型判断（见 §3），产出补丁后同样要确认；`manual` 只报告 |
| 规范 | 这条规则对应的规范条目（04/02/01/03/05/06），见上方「引用写法」；没有写「—」 |
| 检测 | 程序怎么判定（XPath、正则、统计），供实现用 |
| 修改提示 | **一句话告诉用户或程序怎么改**，独立于说明。报告里单独成字段 `hint`（SE 把提示塞在描述里，我们分开，便于机器处理和多语言） |
| 修复方法 | 引擎生成补丁的具体做法（`auto`/`suggest` 才有）；与「修改提示」的区别：提示给人看，修复方法给实现看 |
| epubcheck | 对应 5.x 消息码；`—` 表示 epubcheck 不检查（自研） |
| 来源 | 仅新增规则与新增的细则标注：来自 se lint、04 新增条目或 08 决策 |

### 0.2 运行约定

1. 引擎分两阶段：**检测**（只读，输出问题列表，结构见 §6.1：同一规则同一文件的多处命中合并成一条，带命中位置列表）与**修复**（按 rule 顺序应用补丁，再整体重跑检测）。
2. 修复顺序固定：STR-023（读取阶段转码，最先）→ STR（容器/OPF）→ RES（重命名/转码，需同步更新引用）→ SEM → STY → TXT → TYP → STR 导航重建（STR-010）→ A11Y。重命名类修复必须全局更新 OPF、nav、内容文档、CSS 中的引用，并记入豁免用的改名映射（§7.4）。
3. 修复必须幂等：对已修复文件再次运行应产生零补丁。
4. 任何 `auto` 修复前保留原包；修复结果须通过 epubcheck（§1）才算成功，否则回滚该条规则的补丁。
5. **豁免**：按书的旁路 JSON 文件，不写进输出的 EPUB；每条 = 规则编号 + 文件（可通配）+ 定位（选择器或文字锚点，不用行号）+ 必填理由；被豁免的问题显示为「已豁免」并跳过对应的自动修复。格式与匹配规则见 §7。
6. **配置项**（不同出版风格的分歧一律做成配置，不做硬规则），默认值如下：

| 配置 | 默认 | 说明 |
|---|---|---|
| `doc.max_bytes` | 256 KB（warning） | 单个内容文档体积，超出建议按标题拆分。EPUB 规范无硬限制；原书的 120 KB 来自特定平台规范，与 `02_内容文档与语义结构.md` §2 统一为 256 KB【需实测】 |
| `nav.max_depth` | 3 | 目录层级建议上限 |
| `indent.em` | 2 | 中文正文首行缩进 em 数；`0` 表示无缩进风格（块间距分段） |
| `css.class_style` | `kebab` | 输出类名一律小写连字符，以 04 §4.1.1 类名注册表为准（04 4.1.1.3；原书中的驼峰命名来自厂商规范，已舍弃）；取 `keep` 时保留输入书的类名 |
| `img.max_bytes` | 1 MB warning / 3 MB error | 书中两个来源的数值，取严作 warning、宽作 error |
| `img.max_px_long_side` | 4096 | 【补】 |
| `img.max_pixels` | 16 MP | RES-006 总像素上限 |
| `lang.primary` | 自动探测 | 中文书以原书 `dc:language` 为准；新生成时简体 `zh-Hans`、繁体 `zh-Hant`，须全书一致（04 4.1.3.2） |
| `punct.profile` | `cn-mainland` | 标点规范见 `06_中文文本规范化.md` |
| `contrast.min` | 4.5 | WCAG AA 正文 |
| `id.prune` | `false` | 开启后 SEM-023 才允许批量删除未被引用的 id（已有 id 默认一律保留，04 4.1.5.2） |
| `poem.page_break` | `false` | 诗集每首是否另起一页（04 4.7.5.4） |
| `waiver.file` | `<书名>.epub.typeset-ignore.json` | 按书豁免文件的位置（§7.2） |

### 0.3 共用检测片段（规则明细中以 `@名称` 引用）

- `@HAN`：`[\u3400-\u4dbf\u4e00-\u9fff\uf900-\ufaff\U00020000-\U0002fa1f]`（Python 用 `regex` 模块可写 `\p{Han}`）。
- `@CNPUNCT`：`[，。、；：？！…—·“”‘’（）《》〈〉【】〔〕「」『』～]`。
- `@HALF`：`[,.;:!?()]`。
- `@BLOCK`：`p, h1-h6, li, blockquote, dd, dt, figcaption, td, th, div[not(*[self::p or self::div or self::ul or self::ol or self::table or self::blockquote])]`（叶子块）。
- `@TEXT(el)`：`el` 的 `string()` 去除首尾 Unicode 空白（含 `\u00a0 \u3000 \u200b \ufeff`）。
- `@HEADING_SEQ(file)`：按文档顺序取 `//h1|//h2|…|//h6`，得 `[(level, text)]`。
- `@LINKGRAPH`：遍历全部内容文档，收集 `a[@href]` 与 `id`，解析相对路径（先做 `%xx` 解码并规范 `..`），得「源位置 → 目标文件#id」图。
- `@SENT_END`：`[。！？…”’）」』.!?…]$`，段末允许后接右引号/右括号。
- `@CLASS_REGISTRY`：04 §4.1.1 类名注册表中全部类名的集合（由 04 的表生成，不手抄）。
- 所有基于文本的规则**只处理文本节点**，不得跨越 `pre`、`code`、`script`、`style` 与 `[translate=no]`，修复时对文本节点改写，不对序列化字符串做正则替换（避免破坏标签）。

### 0.4 序列化选项

引擎重写文件时按下表序列化。这些是**输出格式选项**，不产生问题报告；只对因其他修复而被重写的文件生效，不为「仅统一缩进」重写用户原有文件（避免满篇 diff）。目的是输出稳定、可 diff、修复幂等（§0.2 第 3 条）。参照 SE 手册第 1 章，经取舍后采用。

| 选项 | 默认 | 说明 |
|---|---|---|
| `xml.decl` | `true` | 文件头写 `<?xml version="1.0" encoding="utf-8"?>` 与 `<!DOCTYPE html>`，`utf-8` 小写；根元素同时写 `lang` 与 `xml:lang`（值取 `lang.primary`），用到 `z3998:` 时写 `epub:prefix`（SEM-036） |
| `xml.attr_order` | `alpha` | 属性按字母序，`xmlns*` 置前；属性顺序无语义，只为输出稳定 |
| `xml.indent` | `tab` | 块级容器的子节点缩进用 Tab，可配 2 空格；行内混排文本里的空白不得增删 |
| `xml.leaf_oneline` | `true` | 叶子块（`@BLOCK`）写成单行，标签紧贴文字；`pre`、`[xml:space=preserve]`、`white-space:pre*` 内部不动 |
| `xml.br_format` | `se` | `行1<br/>⏎行2</p>`：`<br/>` 紧跟前一行文字，续行不加缩进 |
| `xml.enum_lower` | `true` | `epub:type`、`role`、`rel` 等枚举值转小写；`lang` 值按 BCP 47 规范大小写；`id`/`class`/`href` 的值不得改大小写 |
| `css.charset` | `true` | 我们写出的 CSS 首行 `@charset "utf-8";`（须从首字节开始、双引号、无 BOM）；`@namespace` 仅在确实用到命名空间选择器时才写（STY-020） |
| `css.format` | `se` | 选择器各占一行；规则间一个空行；每个声明独占一行、`prop: value;`；末条声明也带分号；注释、`@font-face`、`@media` 保留；`url()` 与字符串不改大小写 |
| `css.sort` | `template_only` | 声明按字母序只用于我们自己的模板（04）；不重排用户 CSS（回退声明在前、新声明在后的写法有语义） |

## 1. epubcheck 与本清单的分工

### 1.1 原则

epubcheck 5.x 是 EPUB 3.3 规范一致性的权威判定器，**规范层面的对错一律复用**；本清单自研的是 epubcheck 不管的三件事：**质量**（合规但难看）、**修复**（epubcheck 只报不修）、**语义推断**（需要理解文本）。

调用方式：`java -jar epubcheck.jar book.epub --json out.json`（JSON 报告含 `messages[].{ID,severity,message,locations[]}`）；按 `ID` 路由到本清单规则。FATAL/ERROR/WARNING/USAGE 四级映射：FATAL、ERROR → error；WARNING → warning；USAGE/INFO → info。【需实测】5.x 具体 JSON 字段名。

### 1.2 分工表

| 范围 | 做法 |
|---|---|
| 规范硬错误（ZIP/mimetype、container、OPF schema、manifest/spine 引用、XHTML schema、nav 结构、CSS 语法、媒体类型回退、脚本/远程资源声明） | **直接复用** epubcheck；本清单对应规则只定义「如何把 epubcheck 报告转成可修复补丁」，并在 epubcheck 不可用时给自研兜底（STR-001…STR-007 的检测方法可做轻量自检，用于修复前的快速判断） |
| 修复 | **自研**：epubcheck 无修复能力。典型：媒体类型/扩展名不符（OPF-029/PKG-022）→ 魔数嗅探后改 manifest/重命名；重复 ID；缺失 `properties`（OPF-014/015）；目录失效（RSC-012）→ 重建 nav |
| 导航与内容一致性 | **自研**：epubcheck 只验 nav 结构与链接可达，不比较「目录文字 vs 正文标题」「漏标章节」 |
| 排版质量（缩进、空段、断行、图注、注释配对、标题层级、版式一致） | **完全自研**（TYP、部分 SEM/STY） |
| 04 规范层规则（类名注册表、标题角色类与层级、章号章名空格、注号 id、诗歌结构、图表 id、`z3998:` 前缀等） | **完全自研**（SEM、STY、TYP；唯一例外：`z3998:` 未声明前缀 epubcheck 报 OPF-028，可复用判定、自研补全） |
| 文本规范化 | **完全自研**（TXT） |
| CSS | epubcheck 只查语法和少量问题（CSS-008 语法错误、CSS-007 非标准字体类型等；5.x 已不检查 `position`）；样式质量、一致性、可调节性**自研** |
| 资源 | epubcheck 查媒体类型/回退/文件存在（MED-*、RSC-*）；图像模式、体积、分辨率、变形、封面比例、字体覆盖**自研** |
| 无障碍 | epubcheck 5.x 仅做少量可访问性检查（如 `ACC-*` 使用类消息、nav 存在性）；**完整无障碍审计**（alt 质量、元数据完整性、对比度）自研，或另接 Ace（DAISY 的无障碍检查器）【需实测 epubcheck 5.x 对 a11y 元数据的覆盖】 |

### 1.4 实测：22 本测试书的 epubcheck 结果（EPUBCheck 5.4.0，2026-10-22）

样本：21 本早年亚马逊中国电子书（AZW3 原件解包后原样打包，EPUB 2.0.1）+《EPub指南》原书（EPUB 3）。**22 本全部有 error**（每本 4–19 个），1 本 fatal。

| epubcheck 码 | 出现本数 | 实际消息（归类） | 本清单规则 | 备注 |
|---|---|---|---|---|
| RSC-005 | 22 | **schema 错误总入口**，须按消息文本细分：`<meta charset>` 不允许（402 处）、`id` 不是合法 XML 名称（284）、`li@value`/`img@width` 等属性不允许（94）、`data-AmznRemoved` 等属性（27）、`img` 缺 `alt`（25）、空命名空间元素（25）、NCX 缺 `version`（21）、`<title>` 为空、列表/表格嵌套非法、厂商私有属性 | SEM-002/003/004/015、A11Y-001、STR-015 | 前四类多数是 **EPUB 2 的 XHTML 1.1 schema** 造成的，升级为 EPUB 3（HTML5 序列化）后自然消失：`meta charset`、`li@value`、`data-*` 在 HTML5 均合法 |
| OPF-032 | 21 | `guide` 引用了非内容文档（图片作封面） | STR-015 | 升级 EPUB 3 时改由 nav landmarks 表达封面；保留的 `guide` 只指向 XHTML |
| CSS-008 | 4 | CSS 语法错误（如属性名后缺冒号） | STY-001 | — |
| RSC-007 | 4 | `@font-face` 引用的字体文件不在包内 | RES-009 | 指南原书也有（引用了未打包的字体） |
| HTM-004 | 2 | DOCTYPE 不规范 | SEM-002 | — |
| RSC-012 | 1 | 链接片段标识符不存在 | SEM-005、STR-010 | — |
| OPF-027 | 1 | 厂商私有属性（`duokan-page-fullscreen`） | — | 见 §1.3 |
| OPF-029 | 1 | PNG 文件登记为 `image/jpeg` | STR-006 | — |
| RSC-016 | 1（fatal） | XML 解析致命错误：`&` 后不是实体名（裸 `&`） | SEM-001 | 不修复则整个文档无法解析 |

结论：

1. **「升级到 EPUB 3」本身就是一条高收益修复**：本样本中数量最多的 RSC-005 子类，大半随 EPUB 2→3 的序列化升级消失。实现时先升级再校验，避免对 XHTML 1.1 的报错逐条修。
2. RSC-005 不能只按码号路由，**必须按消息文本二次分类**（正则匹配 `attribute "(\w+)" not allowed`、`must not be empty` 等）。
3. epubcheck 自带繁体中文消息表（`MessageBundle_zh_TW.properties`），网页界面可直接用作中文报错文案的底稿。

**STR-001**
- 检测：读 ZIP 中央目录第一条名称、压缩方法（=0）、`extra_len`（=0）、内容字节全等比较
- 修改提示：重打包：把 mimetype 放在 ZIP 第一条，Stored 不压缩，无 extra field，内容恰为 application/epub+zip。
- 修复方法：重打包：mimetype 首位、Stored、无 extra；其余条目 Deflate
- epubcheck：PKG-006 PKG-007 PKG-005

**STR-002**
- 检测：遍历条目：`name.casefold()` 去重；`PurePosixPath(name).parts` 含 `..` 或以 `/` 开头即越界；匹配 `(^|/)(__MACOSX|\.DS_Store|Thumbs\.db)`
- 修改提示：删除 __MACOSX、.DS_Store、Thumbs.db；重复名与越界路径先人工确认再处理。
- 修复方法：丢弃垃圾文件；重复名与越界路径 manual（先报告）
- epubcheck：PKG-004 PKG-012

**STR-003**
- 检测：XPath `//c:rootfile/@full-path` → 查 ZIP；多个 rootfile 时标 info，默认只处理第一个
- 修改提示：让 container.xml 的 rootfile full-path 指向真实存在的 OPF；缺失时扫描包内 *.opf 重建。
- 修复方法：缺失/悬空时扫描包内 `*.opf` 重建
- epubcheck：RSC-003 OPF-*~

**STR-004**
- 检测：XPath：`/opf:package[@version]`；`//dc:identifier[@id=/opf:package/@unique-identifier]`；`count(//dc:title)>=1`；`//opf:meta[@property='dcterms:modified']` 正则 `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\dZ$`
- 修改提示：补全 OPF 必需元数据：identifier、title、language 与 dcterms:modified；缺 title 或 language 请用户填写。
- 修复分级：auto（modified 取当前 UTC；unique-identifier 悬空则指向首个 identifier）；缺 title/language/identifier 为 suggest
- 修复方法：补全；缺 identifier 生成 `urn:uuid:`
- epubcheck：OPF-048 OPF-030 RSC-005

**STR-005**
- 检测：构建 `{href→item}`；`set(zip_entries) - set(manifest_hrefs)` 即孤儿；孤儿再用 `@LINKGRAPH` 判断是否被引用
- 修改提示：把被引用却未登记的文件补进 manifest；孤儿文件默认只提示；缺失的文件请补回或删掉引用。
- 修复分级：auto（被引用的孤儿补登记并按魔数填 media-type；未被引用的孤儿默认只 warning，开关 `--prune` 时删除）；缺文件 suggest
- 修复方法：补登记 / 删除 / 去重 id（同步 spine）
- epubcheck：OPF-003 RSC-001 RSC-007 RSC-008

**STR-006**
- 检测：魔数表：`FFD8FF` jpeg、`89504E47` png、`47494638` gif、`RIFF....WEBP` webp、`774F4632/774F4646` woff2/woff、`00010000/true/OTTO` ttf/otf、文本类用 XML 根元素判断 xhtml/svg/ncx；与 manifest 及 `suffix` 比较
- 修改提示：按文件真实内容（魔数）改 manifest 的 media-type；扩展名不符时重命名并更新所有引用。
- 修复方法：以魔数为准：改 manifest media-type；扩展名不符则重命名并更新全部引用

**STR-007**
- 检测：`//itemref/@idref ⊆ //item/@id`；`manifest 内容文档 − spine`；`Counter(idref)>1`
- 修改提示：补入漏项，去掉重复和悬空的 itemref；正文不要设 linear=no。
- 修复分级：auto（重复项去重；漏项 suggest：按文件名/标题推断位置追加）；`linear="no"` 对正文是 warning 并 suggest 改 yes
- 修复方法：去重/补入/删除悬空 itemref
- epubcheck：OPF-049 OPF-034 OPF-033

**STR-008**
- 检测：`count(//item[contains(concat(' ',@properties,' '),' nav ')])=1`；在 nav 文档里 `//h:nav[@epub:type='toc']//h:a[normalize-space()='']`

**STR-009**

**STR-010**

## 3. 适合交给大模型的规则

### 3.1 判定原则

规则引擎能用确定性算法判定的一律不用大模型。大模型只处理三类：**语义分类**（这段是标题吗、是诗吗）、**上下文裁决**（这个半角标点是不是英文句子的一部分、这两段是否该合并）、**生成**（alt、元数据摘要）。大模型的输出必须是**结构化补丁**（`{rule_id, node_ref, action, new_text|new_tag, confidence}`），由引擎校验后应用，**不允许大模型重写整段 XHTML**；任何补丁须先通过：XML 良构、仅改文本/标签/class、文本字符集合差异（编辑距离占比）不超过 5%（TXT-010 等除外，其本身就是改字）。

### 3.2 规则与输入

| 规则 | 大模型任务 | 给模型的输入（仅片段） | 输出 | 默认阈值 |
|---|---|---|---|---|
| TYP-003 / TXT-015 断段合并 | 判断两段是否同一句被截断 | 前一段末尾 ≤60 字 + 后一段开头 ≤60 字 + 前一段字数与全书行宽中位数 | `{merge: bool, confidence}` | ≥0.9 才 suggest 批量，其余逐条确认 |
| TYP-006 / SEM-008 标题判定 | 是否标题及层级 | 候选块文本 + 其前后各 1 块摘要（≤40 字）+ 样式线索（对齐、字号相对值、有无 `h*`）+ 该文件已识别的标题序列 | `{is_heading, level}` | 以上下文一致性（相同样式者同判） |
| TYP-011 / SEM-020 / SEM-034 特殊块 | 诗歌/引文/书信/日记/对话分类 | 连续候选块（≤30 行）原文；每行只保留文本与对齐/缩进 | `{type, boundaries}` | 要求 llm 仅标注范围，改写由模板引擎做 |
| TYP-015 样式误用 | 块内容与所用样式类的语义是否匹配 | 类名 + 该类 3 个代表块文本 + 疑似误用块文本 | `{match: bool, suggested_class}` | — |

| STR-016 / STR-019 / TYP-014 角色与一致性 | 文件角色（序/后记/版权…）、三处书名作者是否一致 | 文件首 300 字 + 标题 + 文件名；封面 OCR 文本、OPF 元数据、版权页行 | `{role}` / `{conflicts}` | — |

| SEM-019 ruby 读音 | 多音字读音校验 | `ruby` 汉字 + 所在句 + 现有拼音 | `{correct: bool, suggest}` | pypinyin 初筛后才送审 |
| A11Y-003 summary | 生成 `accessibilitySummary` | 检测得到的特性清单（结构化 JSON）而非全文 | 一段话 | 用户确认 |

### 3.3 输入约束

1. **只送片段，不送全书**：单次请求 ≤2k 汉字（约 3k token）；图像另计。上下文只含判定所需的邻近块与全书统计量（如行宽中位数、样式类频次表），后者以 JSON 摘要提供。
2. 每个片段带稳定引用（`file`、块序号 `n`、内容哈希），响应按引用回填；哈希变化则补丁作废。
3. 全书级判断（章节角色、术语一致性）使用**离线抽取的特征表**（标题序列、各文件首尾 300 字、实体表），不送正文。
4. 预过滤：先由规则筛出候选，再送模型；候选占比应 <5% 的块，若全书 >30% 命中说明规则阈值失效，应先调规则。
5. 隐私与成本：支持本地模型/可配置端点；对同一片段缓存（按 `哈希+规则ID`）。
6. 输出验证：JSON schema 校验；`confidence` 缺省视为 0；模型返回与输入不符的引用一律丢弃。
7. 禁止交给大模型的：ZIP/OPF/nav 的结构修复、ID/链接重写、CSS 重写、文件重命名（确定性重写，见 STR/STY 规则）。

## 6. 问题报告格式

报告格式参照 `se lint`（编号 + 问题 + 位置，同规则同文件合并），并做三处改进：**修改提示是独立字段**；多一级 `info`、并给出**修复等级**；每处命中记录**选择器**而不止行号（我们会重新序列化文件，行号会漂移）。引擎内部、命令行、网页界面共用同一份数据。

### 6.1 数据结构

报告是一个对象，主体是问题（issue）列表。**一条问题 = 同一规则 × 同一文件**；该文件里这条规则的多处命中放进 `hits` 数组，不拆成多条。全书级问题（元数据、缺文件等）`file` 为 `null`，只有一个隐含命中。

**问题（issue）**

| 字段 | 类型 | 含义 |
|---|---|---|
| `key` | string | 稳定键 `{rule_id}@{file 或 "-"}`，UI 与豁免都用它指代这条问题 |
| `rule_id` | string | 规则编号，如 `TYP-002`；epubcheck 消息按 §1.3 映射，无映射的用 `EPUBCHECK-{code}` |
| `severity` | `error`/`warning`/`info` | 严重度（取自规则；epubcheck 来源按 §1.1 映射） |
| `message` | string | 问题：一句话，来自规则「说明」，可带命中数 |
| `hint` | string | 修改提示：来自规则「修改提示」，一句话；程序和界面都单独显示 |
| `spec` | string[] | 规范条目，如 `["04 4.5.1.1", "04 4.5.1.7"]`；无则空数组 |
| `fix_level` | `auto`/`suggest`/`llm`/`manual` | 修复等级 |
| `source` | string | `native`，或 `epubcheck:RSC-012` |
| `confidence` | number | 0–1，规则或大模型给出的置信度；确定性规则为 1.0 |
| `file` | string/null | EPUB 内的相对路径（当前包内路径）；`null` 表示全书级 |
| `status` | `open`/`waived`/`partial`/`fixed`/`skipped` | `waived`：全部命中已豁免；`partial`：部分命中已豁免；`fixed`：本次已修复；`skipped`：因豁免或失败而未修 |
| `hit_count` | int | 命中总数（含已豁免） |
| `waived_count` | int | 其中已豁免的数量 |
| `hits` | Hit[] | 命中位置列表，按 `line` 升序 |
| `waivers` | Waiver[] | 命中本问题的豁免条目摘要（`id`、`reason`），无则空数组 |

**命中位置（Hit）**

| 字段 | 类型 | 含义 |
|---|---|---|
| `line`、`col` | int/null | 当前文件的行、列（从 1 起）；全书级问题为 `null` |
| `orig_line` | int/null | 原输入文件中的行号（行号回溯：序列化时记录「行起点 → 原行号」映射，二分查找；新生成的节点为 `null`） |
| `xpath` | string | 命中节点的 XPath；文本类命中指向所在元素 |
| `selector` | string | 命中节点的 CSS 选择器（尽量用 `#id`、类，避免位置序号），供豁免与界面定位 |
| `snippet` | string | 文字片段：命中的文本或元素起始标签；超过 120 字截断，保留命中处前后各 20 字 |
| `range` | [int,int]/null | 文本类命中：命中字符区间（相对所在元素的 `string()`），供文字锚点豁免 |
| `waived` | bool | 此处是否已豁免 |
| `waiver_id` | string/null | 命中的豁免条目 id |
| `fix` | object/null | 补丁（原子操作，见下），已豁免的命中为 `null` |

- `fix.op` 取值集合：`remove_node`、`replace_text`、`set_attr`、`rename_file`（附 `old→new`，引擎自动展开为全局引用更新）、`rewrite_css`、`regen_nav`、`regen_manifest`、`merge_nodes`、`split_file`。补丁只能由这些原子操作组成，便于回滚和 diff 展示。
- `source` 为 `epubcheck:*` 时，`rule_id` 取 §1.3 的映射；无映射的 epubcheck 消息以 `EPUBCHECK-{code}` 原样上报，`fix_level=manual`。
- 报告内的排序：先按 `file` 自然排序（数字按大小，`null` 排最前），同文件内按规则编号。
- 同一位置同时被多条规则命中时，按 §0.2 修复顺序依次处理，并在每一步后重新计算 xpath 与行号（修复可能改变节点位置）；`orig_line` 不变。
- 汇总：报告顶层有 `summary`，分别统计 `error`/`warning`/`info` 的**未豁免**问题数、已豁免问题数、可自动修复数。已豁免的问题不计入失败。

默认输出人读的文本，`--format json` 输出 §6.2 的 JSON。布局：全书级问题排最前，之后按文件分组；每条问题 = 一行标题 + 提示 + 规范 + 命中列表。

- 标题行格式：`{severity}  {rule_id}  {message}  [{fix_level}]`；全部命中都被豁免的问题，标题行以 `已豁免` 代替严重度，并在下一行写「理由：…」，不列命中。

- 退出码：0 = 没有未豁免的 `error`；1 = 有；2 = 用法或豁免文件格式错误。

### 6.4 网页显示格式

- **顶部汇总条**：`error / warning / info` 的未豁免计数徽标，已豁免计数（灰），可自动修复数；筛选器（严重度、规则类别、修复等级、文件）；开关「显示已豁免」。
- **问题列表**：全书级问题置顶，其后按文件分组（可折叠，文件名自然排序）。每条问题是一张卡片：
  - 第一行：严重度徽标 · 规则编号（可点，展开规则明细）· 问题说明 · 命中数 · 修复等级标签（`auto` 绿、`suggest` 橙、`llm` 紫、`manual` 灰）；
  - 第二行：修改提示（`hint`，单独一行，与问题说明视觉区分）；
  - 第三行：规范链接（`04 4.5.1.1` 等，点击跳到 04 对应条目）；
  - 折叠区：命中列表，每行 `行:列`、文字片段（命中处高亮），点击在右侧预览里定位并高亮该节点；
  - 操作按钮：「应用修复」（`auto`/`suggest` 先展示补丁 diff，`llm` 展示草稿，均须确认）、「忽略此问题…」。
- **已豁免**：卡片整体变灰，右上角「已豁免」标签，卡片内显示理由与豁免 id，按钮换成「取消豁免」；部分命中已豁免时，卡片照常显示，已豁免的命中行置灰并带「已豁免」小标签。已豁免的问题不计入失败，也不出现在「应用修复」的批量范围内。
- **忽略此问题**：点击后弹出对话框，自动带上规则、文件、定位（优先 `#id` 选择器，其次类选择器，文本类命中用文字锚点），**必填理由**，留空不可保存；保存即写入豁免文件（§7）。对话框可选「仅此处 / 此文件内同类 / 全书同类」三档范围，决定 `file`、`where` 是否省略。
- **豁免自检提示**（STR-024）：未命中、文件已不存在等 `info` 显示在页面底部「豁免文件」折叠区，提供「一键清理」。

## 7. 按书豁免

SE 的做法（书根目录一个 XML，按文件名 + 规则编号 + 行号，没有理由字段）可借鉴三点：按书声明、文件可通配、未命中自检。我们改造四处：**理由必填**；**不用行号**（我们会重新序列化，行号随时变化），改用选择器或文字锚点；**路径抗重命名**（我们自己会改文件名）；存放为**旁路文件**，不往别人的书里加东西。

### 7.1 原则

1. 豁免只用于「这一处是有意的例外」；风格参数（`indent.em`、`punct.profile` 等）是配置（§0.2），不放进豁免。
2. 被豁免的问题**不隐藏**：报告里显示为「已豁免」并带理由；对应的自动修复**跳过**，保证幂等。
3. 豁免不改变检测结果，只给命中打标记；`--no-waivers` 可随时看到全部原始问题。
4. 每条豁免必须写理由，供日后审阅；没有理由的条目无效。

### 7.2 文件位置与命名

- 默认放在 EPUB 同目录：`<书名>.epub.typeset-ignore.json`（`waiver.file` 可改）。
- 输出新 EPUB 时，在新文件旁写出对应的 `<新书名>.epub.typeset-ignore.json`：条目原样保留，只更新顶层的 `renames`（§7.4）。
- 文件不存在即无豁免。不写进 OPF，也不写进 EPUB 内任何文件。

### 7.3 格式

顶层字段：

| 字段 | 必填 | 含义 |
|---|---|---|
| `version` | 是 | 格式版本，目前为 `1` |
| `book` | 否 | `{"identifier": "...", "title": "..."}`，用于核对豁免文件是否对应这本书；不符报 warning（STR-024） |
| `renames` | 否 | 引擎写出的「原路径 → 当前路径」映射，用户一般不手写（§7.4） |
| `ignore` | 是 | 豁免条目数组 |

每条豁免：

| 字段 | 必填 | 含义 |
|---|---|---|
| `id` | 否 | 条目标识；缺省时引擎按序补 `w-001`… 并写回 |
| `rule` | 是 | 规则编号，如 `TXT-003`；可用 `TXT-*` 通配一个类别；epubcheck 来源的问题用 `EPUBCHECK-{code}` |
| `file` | 否 | EPUB 内相对路径，**匹配完整路径**，支持 shell 风格通配（`*` 不跨目录，`**` 跨目录）；省略表示全书 |
| `where` | 否 | 定位，省略表示该文件内（或全书）该规则的全部命中。见下表；**没有行号字段** |
| `reason` | 是 | 人话理由，非空；缺失则该条无效并报 error |

`where` 的取值（可同时写多项，同时写则须全部满足）：

| 键 | 含义 |
|---|---|
| `selector` | CSS 选择器；命中节点是选中元素或其后代即算命中。尽量用 `#id`、类名；避免 `:nth-child`、位置序号（重排后易漂移，STR-024 会提示） |
| `xpath` | XPath，语义同上；OPF、nav 等非 HTML 文件用它 |
| `anchor` | 文字锚点 `{"quote": "命中处原文", "prefix": "前文（可选）", "suffix": "后文（可选）"}`；在文件文本中找 `quote`（空白不折叠，保证空格类规则能定位），用 `prefix`/`suffix` 消歧；命中区间与 `quote` 重叠即算命中 |

示例：

### 7.4 匹配规则与抗重命名

1. **规则**：`rule` 与问题的 `rule_id` 相等，或为 `X-*` 通配该类别。
2. **文件**：`file` 的通配模式与问题所在文件的路径匹配。每个文件有三个候选路径：当前路径、原输入路径、`renames` 里记录的所有历史路径；任一匹配即算。因此我们因 STR-006（改扩展名）、STR-013、STR-017（规范命名）或 SEM 拆分而改名后，豁免仍能对上：
   - 引擎在每次改名时记录「原路径 → 新路径」，输出新 EPUB 的同时把链条写进新豁免文件的 `renames`；条目本身不改写（通配模式无法可靠改写）；
   - 拆分出的新文件继承原文件的历史路径；合并的文件继承各源文件的历史路径之并集；
   - 以上都对不上（文件已被删除或被其他工具改名）时，条目判为「文件不存在」，STR-024 报 info。
3. **定位**：`where` 在**检测时**对当前文档求值；每轮修复后重新检测并重新求值，所以序列化造成的行号变化、`xpath` 序号变化不影响 `selector`/`anchor`。`where` 省略则文件内（或全书）该规则的所有命中都算。
4. **命中粒度**：命中位置落在 `selector`/`xpath` 选中的节点内，或与 `anchor` 的 `quote` 区间重叠，该命中即标记已豁免；同一问题的其余命中保持原状（问题状态为 `partial`）。全书级、无节点的命中（如 STR-004）只看 `rule` 与 `file`。
5. **优先级**：多条豁免命中同一处时，只记第一条（按文件中的先后）为 `waiver_id`，其余算「冗余」，STR-024 报 warning。

### 7.5 对修复与报告的影响

- 被豁免的命中，`fix` 置空；引擎生成补丁时过滤掉落在已豁免范围内的节点。同一补丁横跨已豁免与未豁免部分时拆开，只应用未豁免部分。
- 报告里问题状态为 `waived`（全部命中已豁免）或 `partial`；已豁免的问题不计入失败与退出码，但显示在报告里（§6.3、§6.4）。
- 修复阶段重跑检测后，豁免重新匹配；幂等不受影响。
- 豁免 `source` 为 epubcheck 的 `error` 时，书仍会被 epubcheck 判为不通过；STR-024 对此报 info，提醒「豁免后 epubcheck 仍会报，不能算零 error」。

### 7.6 豁免文件自检（STR-024）

豁免文件自己也被检查，违规按下表报告：

| 检查 | 级别 | 处理 |
|---|---|---|
| JSON 无法解析、`version` 不支持、出现未知字段 | error | 整个文件不生效，退出码 2 |
| 缺 `reason`、`reason` 为空白 | error | 该条无效 |
| 含 `line`、`col` 等行号字段 | error | 该条无效；提示改用 `selector` 或 `anchor`（UI/命令行的「按行号忽略」只是输入便利，保存时转成选择器或锚点，不落行号） |
| `rule` 不存在或已废弃 | warning | 该条无效 |
| 完全相同的条目重复 | warning | 保留第一条 |
| 全书（或整文件）豁免与同规则的带定位豁免并存 | warning | 带定位的一条冗余 |
| `book.identifier` 与当前书不符 | warning | 照常生效，提示核对 |
| 条目没有命中任何问题（规则已修好、文字已改） | info | 提示清理，防止豁免变成僵尸 |
| `file` 模式解析不到任何现存文件（含历史路径） | info | 同上 |
| `file` 省略或为 `*`/`**` 且无 `where` | info | 范围过宽，提示确认 |
| `where` 含位置序号（`:nth-child`、`[42]`） | info | 重排后易漂移，建议改选择器或文字锚点 |
| 豁免的是 epubcheck 来源的 `error` | info | 书仍无法零 error |

### 7.7 与 se lint 的差异小结

| 项 | se lint | 本软件 |
|---|---|---|
| 位置 | 书根目录 XML，进仓库 | EPUB 同目录旁路 JSON，不进 EPUB |
| 文件匹配 | 只匹配文件名 | 匹配 EPUB 内完整路径，可通配，可省略表示全书 |
| 定位 | 行号 | 选择器、XPath 或文字锚点，不用行号 |
| 理由 | 无 | 必填 |
| 重命名 | 不涉及 | 原路径 + `renames` 链条 |
| 未使用的豁免 | 报错 | info |
| 运行时开关 | 跳过豁免、指定规则的豁免失效 | `--no-waivers`、`--unwaive` |

### 8.1 P0 规则测试夹具（每条至少一个最小 EPUB）

### 8.2 通过标准

- 回归集建议：epubcheck 官方测试 EPUB、含中文竖排/横排、含诗歌/引文/脚注/表格/大图、TXT 转换书各至少一本；
- 每条规则的假阳性率目标：`auto` 规则在回归集上 0 误修（人工抽检），`suggest` 规则命中后用户接受率 ≥70% 才升级为默认勾选；
- 新增规则必须附最小夹具与期望补丁，并声明是否与 epubcheck 重叠（规则明细里的「epubcheck」一行）、对应的规范条目（「规范」一栏）。
- 规范引用校验：本文里每个 `04 4.N.M.K` 引用，必须在 04 中存在对应条目；规则编号永不复用，新增只能接在各类现有最大号之后。
- 报告与豁免的回归：同一规则同一文件多处命中合并为一条；被豁免的命中不被自动修复触碰；文件被改名后豁免仍命中；未命中的豁免报 info。
