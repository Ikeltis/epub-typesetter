# 第 3 章　电子书结构

### SE 3.0　三大分区（前置/正文/后置）与 landmarks 标记
- SE 原规则：书由 Front / Body / Back matter 三部分组成，列表顺序是典型顺序，可有例外；这些分区在 ToC 的 Landmarks 中必须用相应分区标识标注。
- 我们现状：`02` §3 采用同样三分法，表中按序列出，并写明"分区标记：每个 `<body>` 加 `epub:type="frontmatter|bodymatter|backmatter"`，正文起点对应 landmarks 的 `bodymatter`"；"不要重排用户书的次序，除非明确错位"。`01` §6.3 landmarks 要求 `bodymatter` 有且指向正文起点；`07` STR-012、STR-016。
- 结论：已一致
- 理由：思路相同；"有例外、不强重排"与我们对已有书的立场吻合。
- 落地：无。

### SE 3.1　封面（Cover）
- SE 原规则：封面是呈现书外观的图像（图 + 书名 + 作者）；SE 的封面是模板生成的 SVG，由 `se build-images` 产出。
- 我们现状：`02` §3 第 1 行：`cover`/`doc-cover`，spine 首项，整图，不进目录、landmarks 有；`01` §4.5 封面声明；`07` RES-001。
- 结论：不采用
- 理由：SE 出版物专属（SVG 模板生成封面）；原则 4 明确不给别人的书生成 SVG 封面。语义标注部分我们已经有。
- 落地：无。

### SE 3.2　书名页（Title page）
- SE 原规则：列书名与作者的一页；SE 里是 `se create-draft` 生成的 SVG 图，再由工具编译。
- 我们现状：`02` §3 第 2 行 `titlepage`，内容为书名、作者、译者、出版者，文字页。
- 结论：不采用
- 理由：SE 出版物专属（SVG 书名页）；原则 4。我们保留原书书名页，只补语义。
- 落地：无。

### SE 3.3　版本/出版者信息页（Imprint）
- SE 原规则：Imprint 页含出版者信息；SE 给模板由制作者填写。
- 我们现状：`02` §6.2 有 `imprint`（"出版者信息"）但 §3 顺序表没有对应行；中文书的版权页通常把出版者、ISBN、CIP 等合在 `copyright-page`。
- 结论：修改后采用
- 理由：词表层面一致，可以采用 `imprint` 这一语义词；但不生成页面（原则 4）。中文书里版权页与出版信息多半同页，不应强拆。
- 落地：`02` §3 第 3 行备注补一句"出版者信息单独成页时标 `imprint`；与版权页同页则只标 `copyright-page`；不生成、不拆分"；`02` §6.3 第 1 条必标项不加 `imprint`；`07` SEM-010 值域表确认含 `imprint`。

### SE 3.4　献词（Dedication）
- SE 原规则：作品开头的题献，向某人致敬。
- 我们现状：`02` §3 第 4 行 `dedication`/`doc-dedication`，front，不进目录。
- 结论：已一致
- 理由：完全一致。
- 落地：无。

### SE 3.5　题词（Epigraph），含诗体题词
- SE 原规则：书首的引语或诗，用以烘托气氛；若是诗或诗引文，必须遵循诗歌结构标准。
- 我们现状：`02` §3 第 5 行 `epigraph`/`doc-epigraph`，"也可放在章首"；§5.7 诗歌结构；§4.1.8 无标题的题词页不得用 `section epub:type="chapter"`。
- 结论：已一致
- 理由：题词与诗歌结构分别有规定，足以覆盖。诗歌标记问题见 SE 4.1.2。
- 落地：无。

### SE 3.6　致谢（Acknowledgements）
- SE 原规则：感谢的人或机构名单；位置取决于作者，可在前置也可在后置。
- 我们现状：`02` §3 第 13 行 `acknowledgments`/`doc-acknowledgments`，"back/front"，可进目录。
- 结论：已一致
- 理由：位置随原书，一致。
- 落地：无。

### SE 3.7　序/前言/导言（Foreword / Preface / Introduction）
- SE 原规则：Foreword 通常由他人所写；Preface 说明主题与目标，通常作者所写；Introduction 多见于非虚构，作者所写，提出主要论点。
- 我们现状：`02` §3 第 7 行三者各有 epub:type/role，进目录，"推荐序、译者序、再版序各一文件"；§6.2 含订正（preface 原书误译）。
- 结论：已一致
- 理由：定义一致；中文"序/前言/导言"的归类已覆盖，推荐序归 `foreword`、自序/前言归 `preface`。
- 落地：无。

### SE 3.8　半书名页（Half title）
- SE 原规则：有前置部分的书，半书名页标志正文开始；只列书名不列作者；有前置部分时必须有。
- 我们现状：`02` §6.2 有 `halftitlepage`（半书名页），§6.2"标题相关"有 `halftitle`；§3 顺序表无对应行；`bodymatter` landmarks 指向"正文起点"。
- 结论：修改后采用
- 理由："必须有半书名页"是 SE 的出版体例，不采用（原则 4，不给他人书添加页面）；但"若书中已有，则识别并标 `halftitlepage`，且不把它当正文起点"值得采用，避免 landmarks 的 `bodymatter` 误指半书名页。中文纸书常见"书名页前的简页"。
- 落地：`02` §3 表在第 1、2 行之间增加"半书名页（可选，仅识别）`halftitlepage`，front，不进目录"；`02` §3 补一句"半书名页属 front，不得作为 `bodymatter` 起点"；`07` STR-012 判据补"`bodymatter` 目标不得是仅含书名的页"。

### SE 3.9　目录页（Table of Contents）与 spine
- SE 原规则：ToC 列主要标题；传统纸书的目录属前置；SE 的做法是目录不进 spine，只通过阅读器的目录功能呈现。
- 我们现状：`02` §3 第 6 行"可见目录页可选，nav 必有"；`01` §6 与 spine 节："nav 可以不在 spine；若有链接指向它则必须在 spine"，常见做法放版权页后或末尾 `linear="no"`；`01` §6.2 "封面/版权/nav 自身可不进目录"。
- 结论：已一致
- 理由：EPUB 3 允许 nav 不在 spine，我们已写明两种合法做法。对已有书不改动其可见目录页（删除需用户确认，`02` §9 #23 只处理手写点线目录）；对没有可见目录页的书，不新增。
- 落地：无。

### SE 3.10　正文（Body matter）的构成
- SE 原规则：正文是主要内容，分章；文集则分篇/诗/文；顶层可有卷、部等更大的划分。
- 我们现状：`02` §3 第 8 行"正文：部→章→节"，`part`/`chapter`；§6.2 `volume`/`division`；§4.1.3 层级约定。
- 结论：已一致
- 理由：一致。文集的单篇可用 `article`/`chapter`，见 SE 4.2.3。
- 落地：无。

### SE 3.11　序章（Prologue）及框架叙事特例
- SE 原规则：序章多见于小说，一般属正文；若序章是框架叙事中的虚构元素，为保持框架可放在半书名页之前，带 `frontmatter` 语义并保留 `prologue`。
- 我们现状：`02` §3 表无序章行；§6.2 有 `prologue`/`doc-prologue`（"序章/楔子"）；§3 "不要重排用户书的次序"。
- 结论：修改后采用
- 理由：序章应补进顺序表，默认归正文。框架叙事特例的核心是"尊重原书位置、不强行搬进正文"，与我们不重排的立场一致；位置判断交给用户/大模型，软件不自动搬动。
- 落地：`02` §3 表第 8 行之前加"序章/楔子 `prologue` `doc-prologue`，body，进目录"；备注"若原书将其置于正文标题页之前（框架叙事），保持原位，body 上可写 `frontmatter` 且保留 `prologue`"；`07` STR-016 的分类词表加"序章、楔子"。

### SE 3.12　尾声（Epilogue）与后记（Afterword）的归属
- SE 原规则：Epilogue 多见于小说，收束情节，应具有与章相近的结构，属正文；Afterword 是书之后的独立收束，通常作者所写，属后置部分。
- 我们现状：`02` §3 第 9 行把 `epilogue`/`afterword`/`conclusion` 合并，分区写"body 末或 back"，中文名"后记/跋/结语"。
- 结论：修改后采用
- 理由：SE 的区分有用：`epilogue`（尾声）、`conclusion`（结语）是正文的一部分，`afterword`（后记/跋）在书的叙述之外，属 back。中文"后记""跋"几乎都是后者，现在合并容易让 `bodymatter`/`backmatter` 标错。
- 落地：`02` §3 第 9 行拆成两行：尾声/终章/结语 `epilogue`/`conclusion`→body；后记/跋 `afterword`→back，进目录；备注"中文"后记"默认标 `afterword`，不确定则交大模型/用户确认"；`07` SEM-010 分区校验增加"`afterword` 不得在 `bodymatter` 之内"，可检测，仅警告。

### SE 3.13　后置部分的定义
- SE 原规则：后置材料跟在正文后面，可以与正文分离，如尾注、附录、后记、版本记录。
- 我们现状：`02` §3 第 9–14 行；分区标记同 SE 3.0。
- 结论：已一致
- 理由：一致。
- 落地：无。

### SE 3.14　插图目录（List of Illustrations）
- SE 原规则：插图的索引，以列表形式给出，每项链接到插图在正文中的位置；SE 置于后置部分。
- 我们现状：`02` §6.2 `loi`/`lot`/`lov` 仅作为 nav 的类型说明（`01` §6.1 "自定义 nav"）；§3 顺序表没有可见的插图目录页。
- 结论：修改后采用
- 理由：识别并标注已有的"插图目录/表格目录"页是有用的，且可检测（页面主体是指向 `figure`/`table` 的链接列表）。位置不采用 SE 的"后置"，中文书的图表目录通常紧跟目录页，按原书位置保留。
- 落地：`02` §3 第 6 行备注补"插图目录/表格目录页（`loi`/`lot`），front，位置随原书，不生成"；`07` SEM-010 值域加入 `loi`/`lot`；是否生成 nav 的 `loi` 不做（无原书依据，沿用 `01` §6.1）。

### SE 3.15　尾注（Endnotes）与脚注转尾注
- SE 原规则：笔记集中成尾注，每条有唯一顺序编号并链接回正文；原书脚注转为尾注。
- 我们现状：`02` §3 第 11 行 `endnotes`/`doc-endnotes`；§7 开头"默认输出是全书一个书末尾注文件……做法同 SE"；§7.4 旧写法转换；`07` SEM-007。
- 结论：已一致
- 理由：我们已经对齐。
- 落地：无。

### SE 3.16　版本记录（Colophon）
- SE 原规则：Colophon 含出版者、作者、初版日期、版本、封面作者等信息；SE 的 colophon 是标准化模板。
- 我们现状：`02` §3 第 14 行"作者/译者简介、版本记录 → `colophon`/`doc-colophon`，可进目录，出版社广告页建议用户确认后删除"。
- 结论：不采用
- 理由：SE 出版物专属（标准化模板、生成 SE 版本记录页，原则 4）。已有的版本记录页只保留并标 `colophon`，这点我们已有。
- 落地：无。

### SE 3.17　版权页（Copyright page）及其位置
- SE 原规则：版权页说明作品版权状态；SE 书全部公有领域，使用标准页，并放在书的最后，与通常置于前置的惯例相反。
- 我们现状：`02` §3 第 3 行 `copyright-page`，front，"中文书常放书名页之后"；"版权页出现在最后一章之后"被视为错位，重排需用户确认。
- 结论：不采用
- 理由：SE 出版物专属（置于末尾是 SE 体例，也不适用于有版权信息的中文书籍）；公有领域声明页不添加（原则 4）。
- 落地：无。

# 第 4 章　语义

### SE 4.1.1　语义与外观分离
- SE 原规则：HTML 应表达元素"是什么"，而不是"看起来怎样"；示例对比 `div` + 行内 margin 与 `p` + `blockquote`。
- 我们现状：`02` 开篇"核心立场：内容文档只表达'这是什么'……长什么样交给 CSS"；§9 伪排版反模式 24 项。
- 结论：已一致
- 理由：同一原则，我们的反模式清单更细。
- 落地：无。

### SE 4.1.2　诗歌的结构与 `epub:type`
- SE 原规则：诗用 `<blockquote epub:type="z3998:poem">`，诗节为 `<p>`，诗行为 `<span>`，行间 `<br/>`；诗节与诗行的含义是 SE 约定。
- 我们现状：`02` §5.7：`<div class="poem" epub:type="z3998:verse">` > `<p class="stanza">` > `<span class="line">` + `<br/>`；"简便做法"；要求声明 `epub:prefix`；不想声明则不加 `epub:type`。
- 结论：修改后采用
- 理由：节/行结构已一致。有两点需要调整：（1）整首诗的容器值应是 `z3998:poem`（歌词用 `z3998:song`、赞美诗 `z3998:hymn` 等），`z3998:verse` 的词表含义是诗行/节一级，用在整首诗的容器上不准确【需核对 Z39.98 词表原文】；（2）诗是被引用的他人作品、嵌在叙述中时（题词、引诗）容器用 `blockquote`，是本书自身内容的诗则用 `div`/`section`，现在 `div` 一刀切。
- 落地：`02` §5.7 示例与说明改为：容器 `epub:type="z3998:poem"`，补"被引用时用 `<blockquote>`"；`07` SEM-020 的修复动作按此输出；`02` §5.7 的 `epub:prefix` 说明见 SE 4.3.3。

### SE 4.2.0　可用元素范围
- SE 原规则：EPUB 允许 HTML5 的全部元素，每个元素在使用前都要仔细考虑语义；以下是常用元素的不完整列表。
- 我们现状：`02` §5 整体映射表；§1.2 #8 废弃元素；§5.8 其他元素。
- 结论：已一致
- 理由：一致。
- 落地：无。

### SE 4.2.1　`body` 的直接子元素必须是 `section` 或 `article`
- SE 原规则：`body` 是 XHTML 顶层元素，必须有一个直接子元素是 `section` 或 `article`。
- 我们现状：`02` §4.1.1"每个文件一个根 `<section>`"；§4.1.8 无标题页不用 `chapter`，改用 `div` 或带 `aria-label` 的 `section`；§4.2 示例；`07` SEM-011。
- 结论：已一致
- 理由：做法已相同。例外是封面页（单图）与导航文档，这两类我们另行处理，不强求外包 `section`。
- 落地：`07` SEM-011 判据补"封面页、nav 文档豁免"（若目前未写）。

### SE 4.2.2　`section` 的含义
- SE 原规则：`section` 是作品中的主要结构划分（部、卷、章、小节），语义上不能独立存在，属于更大的作品。
- 我们现状：`02` §4.1.4：`section` 必须有标题（或 `aria-label[ledby]`），纯样式分组用 `div`。
- 结论：已一致
- 理由：一致。
- 落地：无。

### SE 4.2.3　`article` 的含义
- SE 原规则：`article` 是可以单独抽出来发布的条目，例如诗集里的一首诗、短篇集里的一篇；小说里的一首诗不是。
- 我们现状：`02` §4.1.4："`article` 仅用于可独立流通的内容块（如杂志中独立文章）"。
- 结论：修改后采用
- 理由：定义相同，但 SE 的例子更贴近文集类图书，我们只举了杂志。中文书里的诗集、散文集、短篇集单篇适用；小说内的诗不适用。
- 落地：`02` §4.1.4 `article` 举例补"诗集中的单首诗、文集/短篇集中的单篇"，并注明"小说内的插入诗不用 `article`"；自动检测不做（体裁判断交大模型，仅建议，`07` SEM-011 info）。

### SE 4.2.4　`p`、`blockquote`（含非言语引文）
- SE 原规则：`p` 是段落；`blockquote` 表示块级引用，也包括名片、墓碑、电报、信件等"非言语的引用"。
- 我们现状：`02` §5.1 引文用 `blockquote` 内含 `p`；反模式含"用 `<blockquote>` 仅为缩进排版（如诗、信、署名）"；§5.5 "`blockquote`：引用他人的话"。
- 结论：修改后采用
- 理由：我们的限制针对"为了缩进而滥用"，但写法容易被理解成"信件一律不能用 `blockquote`"，与 SE 冲突。嵌在叙述里的书信、电报、碑文、告示本质是被引用的文献，应用 `blockquote`，并可加 `z3998:letter` 等。
- 落地：`02` §5.1 引文行与 §5.5 `blockquote` 条改写为"引用他人的话或叙述中嵌入的书信/电报/碑铭等文献；仅为缩进的不是 `blockquote`"；`02` §5.1 反模式列去掉"信"；`07` SEM-020 书信识别后的修复输出用 `blockquote`（+`z3998:letter`，需声明前缀）。

### SE 4.2.5　`figure` / `figcaption`，图注与 `alt` 的区别
- SE 原规则：`figure` 包住照片/图表/插图（`img`），可含 `figcaption`；`figcaption` 只做 `figure` 的子元素，与 `alt` 不同：`alt` 是给读屏的文字描述，`figcaption` 内容更自由。
- 我们现状：`02` §5.1 图与图注行、§5.5；§1.2 #9 `alt` 必有；`07` SEM-017、A11Y 的 `alt` 检查。
- 结论：修改后采用
- 理由：结构一致；缺少"图注不能替代 `alt`"的明确规则。自动抄图注当 `alt` 是常见偷懒做法。
- 落地：`02` §5.1 图与图注行备注补"`alt` 是图像内容描述，图注是对图的说明，二者不互相替代"；`07` A11Y 增加检查：`alt` 与同 `figure` 的 `figcaption` 文本完全相同 → info，建议改写 `alt`（修复交大模型/用户，不自动改）。

### SE 4.2.6　`header`
- SE 原规则：`header` 表示直接父元素的头部区，常见于除标题外还有别的头部内容的 `section`，也可用于 `blockquote` 等。
- 我们现状：`02` 无 `header` 条目；§4.1.5 副标题用 `<p class="subtitle">`/`<span>` + `epub:type="subtitle"`；§4.1.7 序号与章名同在一个 `h1`。
- 结论：修改后采用
- 理由：`header` 是 HTML 标准元素，与阅读系统无关；章标题、副标题、作者署名这类"标题组"放入 `header` 结构更清楚。只是 `h1` 内的序号 + 题名我们不拆开，不受影响。作为可选写法，不强制已有书改动。
- 落地：`02` §4.1 新增第 9 条"标题组：当 `section` 开头除标题外还有副标题、署名、题词时，可放入 `<header>`；仅有标题时不加"；§5.1 加 `header` 行；`07` 不新增必检项，识别输入时容忍。

### SE 4.2.7　`footer`（署名）
- SE 原规则：`footer` 表示直接父元素的脚部区，典型用于序、前言、信件、电报中的署名。
- 我们现状：`02` §5.1 引文出处"`<footer>` 不推荐，改为 `<p class="source">`"；署名/落款用 `<p class="inscription">` 或 `<address>`（仅限联系信息）。
- 结论：修改后采用
- 理由：`footer` 在 HTML 标准里完全合法，我们当初的"不推荐"没有标准依据，应是对某些阅读器渲染的顾虑（原则 1 不以厂商为理由）。与 `p.class` 方案比较，`footer` 更有语义，但 `p.class` 对多数老书更容易迁移。建议：输出可用 `footer`，输入两种都接受。属需要你决策的点。
- 落地：`02` §5.1 引文出处/署名两行改为"优先 `<footer>`（直接子元素放在 `section`/`blockquote` 末尾），`p.inscription`/`p.source` 作为可接受的旧写法，不强制转换"；`04` 对应模板同步（待决策后改）。

### SE 4.2.8　`hr`（主题分隔）
- SE 原规则：`hr` 只表示主题转换，不得用来制造黑线边框。
- 我们现状：`02` §5.8 `hr`：主题转换，"高层级转换用标题，轻度转换用 hr"；§9 #14 符号线转 `hr`。
- 结论：已一致
- 理由：一致；SE 禁止拿 `hr` 当边框，我们同样要求样式交 CSS，但没有显式写出禁止项。
- 落地：`02` §5.8 `hr` 行补半句"不用 `hr` 做装饰性边线，边线用 CSS `border`"。（微调，不影响结论）

### SE 4.2.9　`ol` / `ul` / `li`
- SE 原规则：`ol` 有序、渲染器自动编号；`ul` 无序、渲染器给项目符号；`li` 为其项。
- 我们现状：`02` §5.3 重点说明；§9 #13 手写序号转 `ol`；§1.2 #6 内容模型。
- 结论：已一致
- 理由：一致。
- 落地：无。

### SE 4.2.10　`table`
- SE 原规则：`table` 用于表格数据或需要表格外观的报表、图表。
- 我们现状：`02` §5.6、§9 #24（不用表格排版）。
- 结论：已一致
- 理由：我们的限定更严格（不做版面表），不冲突。SE 的"需要表格外观的报表"我们也接受。
- 落地：无。

### SE 4.2.11　`div` 几乎不使用
- SE 原规则：`div` 没有语义，几乎不合适，仅在没有其他语义元素时用来分组相关元素。
- 我们现状：`02` §9 #11 `div` 当段落转 `p`、#12 展平空壳嵌套；`07` SEM-009；`02` §4.1.4 纯样式分组才用 `div`。
- 结论：已一致
- 理由：一致。
- 落地：无。

### SE 4.2.12　`em`（强调）
- SE 原规则：`em` 渲染为斜体，语义是强调或不同语气的话语。
- 我们现状：`02` §5.2 `em` 语气强调，视觉用着重号/楷体/加粗，"不要用 `<i>` 表示强调"；§9 #20。
- 结论：已一致
- 理由：语义相同；"渲染为斜体"属英文视觉规则，不采用，我们的视觉处理见 `03`。
- 落地：无。

### SE 4.2.13　`i`（无语义斜体）加 `epub:type` 说明内容
- SE 原规则：`i` 渲染为斜体、本身无语义，须加 `epub:type` 说明内容；示例中船名 `<i epub:type="se:name.vessel.ship">`，缩写 `<abbr epub:type="z3998:initialism">`。
- 我们现状：`02` §5.2"文字风格"行：`b`/`i`/`span class` 表示文体变化，类名表达语义（`class="foreign"`）；书名用 `cite`；`abbr title`。
- 结论：不采用
- 理由：（1）`se:name.*` 属于自定义词表，原则 2 禁止；（2）中文无斜体，作品名、船名等靠书名号/专名号，`i` 本身在中文书里用得很少；（3）SE 要求每个 `i` 必须有 `epub:type` 是英文排版体例。我们继续用 `cite`、`lang` 和语义 class。`z3998:initialism` 对中文价值很低，不强推。
- 落地：无。

### SE 4.2.14　`b`（小型大写）
- SE 原规则：SE 约定 `b` 表示小型大写，无语义，纯视觉。
- 我们现状：`02` §5.2/§9 #20：`b` 不用于强调，全段 `b` 疑为伪标题（`07` SEM-016）。
- 结论：不采用
- 理由：中文不适用（无小型大写）。
- 落地：无。

### SE 4.2.15　`span`
- SE 原规则：`span` 是无其他合适语义元素时的行内文本，通常搭配 `class` 或 `epub:type`。
- 我们现状：`02` §5.2"无语义容器"行：类名表达含义不表达外观；§9 抑制 `span` 滥用（SEM-009）。

### SE 4.3.1　语义标注（`epub:type`）的机制
- SE 原规则：EPUB 允许用 `epub:type` 给元素添加语义，如 `<section epub:type="chapter">`。
- 我们现状：`02` §6.1 机制说明，加 role 并存（DPUB-ARIA）；§6.3 选用与回退原则；`07` SEM-010、A11Y-010。
- 结论：已一致
- 理由：一致，且我们额外要求与 `doc-*` role 并存。
- 落地：无。

### SE 4.3.2　词表优先序：SSV 优先，其次 z3998，最后才是自定义词表
- SE 原规则：先用 EPUB 结构语义词表（同名关键字以它为准），没有再用 z3998，再没有才用 SE 自家词表（`se:`，层级用 `.`）。
- 我们现状：`02` §6.1："自定义值需带前缀并声明"；§6.2 以 SSV 为准；原则 2 限定只用 SSV/DPUB-ARIA/z3998。
- 结论：修改后采用
- 理由：优先序"SSV > z3998"采用；第三层 SE 词表不采用（SE 专属、与厂商无关原则冲突）。目前 §6.1 对"自定义值"的措辞留了口子，应收紧为：软件只生成 SSV 与 `z3998:` 值；输入中已有的其他带前缀值原样保留，不报错、不改写。
- 落地：`02` §6.1 第 5 条改写为上述；`07` SEM-010 增加"同一语义 SSV 与 z3998 都有时用 SSV 值"，并注明"只生成 SSV/`z3998:`；输入中已声明前缀的未知词表值保留"。
- 附：`se:` 词表本身（SE 4.3 第 3 条的层级写法、`se:name.vessel.ship` 等）不采用，理由：与厂商无关原则冲突 / SE 出版物专属。

### SE 4.3.3　z3998 关键字的前缀写法与声明
- SE 原规则：z3998 词表的关键字加 `z3998:` 前缀，如 `<blockquote epub:type="z3998:letter">`。
- 我们现状：`02` 仅在 §5.7 说明"声明 `epub:prefix="z3998: http://www.daisy.org/z3998/2012/vocab/structure/"`，在 `<html>` 或 `<body>` 上"；§6.1 提到自定义值要声明前缀。
- 结论：修改后采用
- 理由：（1）要通用说明 z3998 的前缀规则，不能只在诗歌小节里提；（2）我们写"`<html>` 或 `<body>`"，而 EPUB 规范要求 `epub:prefix` 只能出现在根元素 `<html>` 上，`<body>` 上无效【需用 EpubCheck 实测确认】；应更正。
- 落地：`02` §6.1 新增"z3998 前缀"条：`epub:prefix="z3998: http://www.daisy.org/z3998/2012/vocab/structure/"` 只写在 `<html>` 根上，且 `xmlns:epub` 已声明；`02` §5.7 删除"或 `<body>`"；`07` SEM-010 新增检查：用了 `z3998:` 值而 `<html>` 无对应前缀声明 → error，auto 修复补声明。

### SE 4.3.4　一个元素可带多个 `epub:type` 值，词表可混用
- SE 原规则：`epub:type` 多值以空格分隔，即使来自不同词表，如 `chapter z3998:letter`。
- 我们现状：`02` §6.1："值可多个，空格分隔"；">3 个通常是误用"；§3 分区值可与 `cover` 等并列。
- 结论：已一致
- 理由：一致。
- 落地：无。

### SE 4.3.5　语义继承（如 `body` 上的 `z3998:non-fiction`）
- SE 原规则：子元素继承父元素语义；示例把 `z3998:non-fiction` 写在 `body` 上，两章都视为非虚构。
- 我们现状：`02` §3 在 `body` 标分区（`frontmatter`/`bodymatter`/`backmatter`），与此继承机制相同；不标体裁。
- 结论：不采用
- 理由：继承机制已一致，无需另写；`fiction`/`non-fiction` 体裁标记属其他：价值低、需要判断，错标比不标更糟（`02` §6.3 第 3 条），不纳入自动生成。
- 落地：无。

### SE 4.3.6　标题上的序号标注（`z3998:ordinal` / `z3998:roman`）
- SE 原规则：章标题 `<h2 epub:type="z3998:ordinal z3998:roman">I</h2>`，标记序号并说明是罗马数字。
- 我们现状：`02` §4.1.5/§4.1.7：序号与题名在同一标题内，必要时 `<span class="num">`；章序号用中文数字（`第一章`）。

### 与现有规范冲突、需要决策的点
1. 署名/出处：`footer`（SE）与 `p.inscription`/`p.source`（我们现有）二选一，还是并存。建议输出用 `footer`、输入两种皆收，不强制转换。（SE 4.2.7）
2. `blockquote` 的适用范围：现有文字把"信"列入滥用，SE 把书信、电报等列入合法用法。建议按 SE 修订，但"信件是否算引用"需要大模型/用户判断，只建议不自动改。（SE 4.2.4）
3. 后记/跋的分区：现有表把尾声与后记并为"body 末或 back"，建议拆开，后记默认 back；与部分中文书把"后记"当作书的收尾章的做法可能不同，需要接受"不确定时交用户确认"。（SE 3.12）
4. 诗歌容器词汇：现有 `z3998:verse` 应改 `z3998:poem`，但我对 Z39.98 词表中二者的确切定义没有对照原文，采纳前需要查 `z39-98-2012` 词表核对。（SE 4.1.2）
5. `epub:prefix` 位置：现有"html 或 body"与 EPUB 规范（只能在根 `html`）不符，应更正；建议用 EpubCheck 实测一次。（SE 4.3.3）
6. 半书名页：不强制要求，但要不要在顺序表里正式列出（建议列为"仅识别"，不生成）。（SE 3.8）
