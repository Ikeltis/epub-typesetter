# 缮本（epub-typesetter）：EPUB 排版优化软件

> **缮本**：「缮」是修补、誊写，「缮本」本是誊写清楚的本子，又与「善本」同音；日语里「本」就是书，所以也可读作「修书」。修补一本已有的书，得到一个好本子，正是这个软件做的事。

把已有的 EPUB（主要是中文书）修成结构规范、排版讲究的 EPUB 3。带网页界面，规则引擎负责确定的事，大模型只给建议、由你确认。目标是任意符合 EPUB 3 规范的阅读系统，不绑定具体阅读器，不做格式转换。

## 它能做什么

- **体检**：用 EPUBCheck 和本工具的规则逐项检查原书，每条问题都带规则编号、修改提示、规范条目和命中位置。
- **两种生成方式**
  - **仅规范修复**：只修规范错误和伪排版（空格缩进、空段、废弃标记、缺失的元数据与导航等），版面不动。
  - **排版重建**（推荐）：识别书的结构后按规范重排，套用统一主题。能识别的结构有：
    - 标题层级、部与章；前言、后记等辅文；
    - 注释：配对后集中到书末，带回链；
    - 插图与图注、插图目录和表格目录；
    - 诗歌、书信、列表、条文、表格、术语表；
    - 广告页（整页删除，可在确认板上逐页保留）。
- **确认板**：程序的判断都摆出来，由你改：
  - 原样式相同的段落归成一组，可以整组改角色；
  - 每个标题可以改级别和辅文类型；
  - 识别出的结构可以逐条取消，把握不够的建议勾选了才执行。
- **大模型辅助（可选）**：用 Claude 原生接口，对确认板上的各项给出判断和理由，还能看图起草图片描述（alt）；你点「采纳」后才生效。
- **版本与下载**：每次生成都留一个版本（最近 5 个），写明是哪种方式、用了几处确认、其中几处来自大模型，各自可下载；原件始终不改。
- **按书豁免**：有意保留的写法可以「忽略」，理由必填，之后生成会跳过它。

每次生成后都会校验：跑一遍 EPUBCheck，再逐块比对正文、保证文字不丢；排版重建还会核对图片数量。结果都显示在页面上。

## 快速开始

需要 Docker。

```sh
git clone https://github.com/Ikeltis/epub-typesetter.git
cd epub-typesetter
docker compose up -d --build        # 然后打开 http://127.0.0.1:8780
```

上传的书和所有处理结果保存在 `./data/`，每本书一个目录。

书的页面按四步排：

1. **体检**：看原书有哪些问题。
2. **生成**：选「排版重建」或「仅规范修复」。
3. **确认**：打开确认板检查程序的判断，可以先让大模型分析，再点「按确认结果重新生成」。
4. **下载**：从版本列表里下载需要的那一份。

## 大模型设置（可选）

不配置也能用全部的规则功能，只是没有大模型建议。用的是 Claude 原生接口（Anthropic 官方 Python SDK）。地址和令牌不写进代码，按优先级从三处读：

1. 网页右上角「大模型设置」：保存在 `data/settings.json`，权限 600，不进仓库；保存后可点「测试连接」。
2. 环境变量 `EPUBTS_LLM_*`：复制 `.env.example` 为 `.env` 填写，`docker compose up -d` 会读取（`.env` 不进仓库）。
3. Anthropic SDK 的标准环境变量 `ANTHROPIC_BASE_URL`、`ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`。

令牌怎么填：

- 官方接口：地址留空，填 **API key**（走 `x-api-key` 头）。
- 兼容 Claude 原生协议的中转：填中转地址，再按中转的要求填 API key 或 **Bearer 令牌**。
- 两个只填一个。

模型分两档，都可以在设置里改：

| 档位 | 默认模型 | 用途 |
|---|---|---|
| 轻量 | `claude-haiku-5-5` | 段落样式、结构核对、广告判断、图片描述 |
| 重型 | `claude-opus-5-5` | 全书标题层级与辅文类型 |

为了控制隐私和花费：

- 只发判断需要的片段（每组几段样例、标题列表、缩小后的插图），不发整本书。
- 同样的内容只问一次，结果按内容哈希缓存。
- 确认板上显示调用次数和按官方价估算的费用。一本书的段落、结构、标题分析通常只要几美分。

SDK 暂时固定在 1.x：2.x 默认发送的 API 版本 2026-10-21 有些中转还不接受。

## 处理流程

```
上传 → 解析 → 体检（EPUBCheck + 规则）
          ├─ 仅规范修复：规则引擎的确定性修复 ─────────────────────────────┐
          └─ 排版重建：规范修复 → 语义分析 → 成组结构识别 → 按确认板的决定取舍  │
                       → 按章重建（标题、注释、插图、诗歌、书信、表格…）       │
                       → 主题样式（只附带用到的模板）→ 导航与 NCX → 再规范修复 │
                                                                            ↓
                         校验：EPUBCheck、文字逐块比对、图片数核对
                                                                            ↓
                                                              新版本 → 下载
确认板 ←→ 大模型分析（只给判断，采纳后写进决定，重新生成时生效）
```

## 规范：《EPUB 制作规范》（`guide/`）

软件的一切行为都以这套规范为准，从 `00_总纲.md` 读起。写法参照 Standard Ebooks《Manual of Style》（带编号的命令式规则，配正例和反例），检查报告格式参照 `se lint`。

| 文档 | 内容 |
|---|---|
| `00_总纲.md` | 一本好 EPUB 的标准、版本选择、文档地图 |
| `01_容器包文档与导航.md` | zip、OPF、nav、NCX、无障碍元数据 |
| `02_内容文档与语义结构.md` | XHTML 结构、语义元素、`epub:type`、注释 |
| `03_CSS与中文排版规范.md` | 样式原则、中文排版的量化规则、默认样式表 |
| `04_排版样式模板库.md` | 标题、引文、诗歌、书信、剧本、列表、插图、注释、表格、封面、竖排、术语表等模板（2.0.2） |
| `05_图片与字体资源.md` | 图片、封面、字体、生僻字 |
| `06_中文文本规范化.md` | 标点、空白、断行的清洗规则 |
| `07_质检清单.md` | 全部检查规则（170 条，带编号、严重度、修复等级、修改提示、规范条目）、报告格式、按书豁免（2.0.0） |
| `08_参照StandardEbooks.md` | 与 Standard Ebooks 手册和 `se lint` 的对照结论与决策；逐条笔记在 `_se_notes/` |

规范是唯一来源，代码里的样式和规则说明都由它生成：

- 主题样式表来自 03 §11 和 04 各节的 CSS 块，改完运行 `python3 scripts/build_theme.py`。
- 规则的说明、修改提示、规范条目来自 07，改完运行 `python3 scripts/build_rules_meta.py`。

## 开发

所有命令都在 Docker 开发容器里跑，宿主机无需安装 Python 依赖：

```sh
docker compose -f compose.dev.yml build                      # 首次构建
docker compose -f compose.dev.yml run --rm dev pytest        # 测试
docker compose -f compose.dev.yml run --rm dev epubcheck book.epub
```

命令行（供测试与批量处理；正式界面是网页）：

```sh
docker compose -f compose.dev.yml run --rm dev python -m epub_typesetter check book.epub [--format json] [--hits all]
docker compose -f compose.dev.yml run --rm dev python -m epub_typesetter fix book.epub -o out.epub --epubcheck
```

- `check`：输出 07 §6 格式的报告。退出码 0 表示没有未豁免的 error，1 表示有，2 表示用法或豁免文件有误。
- `fix`：只做确定性修复。
- 按书豁免：在书旁放 `<书名>.epub.typeset-ignore.json`，格式见 07 §7。

## 方向与原则

1. 目标阅读器：任意支持 EPUB 3 的阅读系统，不做厂商私有适配。
2. 网页界面，独立软件，不和本地书库耦合。
3. 只做「已有 EPUB → 更好的 EPUB」，不做格式转换。
4. 大模型只做判断、不改写正文，结论经你确认后才落地。
5. 正文一字不丢：删除的内容（书内目录页、广告页、注释区小标题、重复封面等）全部列在「重建详情」里。
