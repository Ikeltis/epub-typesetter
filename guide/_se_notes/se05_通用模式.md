## 5.1 id 属性

### SE 5.1.1.1　每个 `<section>`、`<article>` 都有 `id`
- SE 原规则：所有 section/article 元素都带 id，包括嵌套小节。
- 我们现状：guide/02 §4.1.6「给 `section` 或标题其一加 id」；§10.2「不被引用的 id 默认保留」；rebuild.py:510 给标题生成 `h{n}`（全书流水号）供 nav 定位。无「每个 section 必有 id」的要求。
- 结论：修改后采用
- 理由：嵌套小节若要进目录（nav 指向小节）必须有稳定锚点；`h{n}` 流水号对人不可读，且插入新标题后会漂移，影响幂等。但不必对每个 section 强制，只在「需要被引用」（进 nav、被链接）时补。
- 落地：guide/02 §10.2 增「新生成 section id 规则」（见 5.1.1.2、5.1.2.3 条）；07 SEM-004 不改；rebuild.py 的标题 id 生成改为优先取所属 section 的 id（改代码 rebuild，后续排期）。

### SE 5.1.1.2　body 直接子 section/article 的 id = 文件名去扩展名
- SE 原规则：`chapter-1.xhtml` 里的根 section 是 `id="chapter-1"`。
- 我们现状：guide/02 §4.1/§4.2 示例是 `chapter-001.xhtml` 配 `id="ch1"`/`"ch3"`，二者并不相同；§2.3 文件名有规范但 id 无对应。
- 结论：修改后采用
- 理由：id 与文件名一致后，由文件名可推 id，nav/landmarks 链接、合并拆分时重命名都可机械推导（可检测、可修复）。但已有 id 是外部链接目标，不能为了一致而改名（02 §10.1「不得自动改名」）。
- 落地：guide/02 §4.2 示例改为 `chapter-003.xhtml` ↔ `id="chapter-003"`，并加规则：「根 section 缺 id 时取文件名主干；已有 id 一律保留」；07 加一条 P2 info 检查「根 section id ≠ 文件名主干」，只提示不自动改。

### SE 5.1.1.3　一个文件含多个 section/article 时，各自 id = 「假如独立成文件时的文件名」
- SE 原规则：合集文件中每个并列单元的 id 取其独立成文件时的文件名主干（示例是短篇集 `the-fox-and-the-grapes`）。
- 我们现状：02 §4.1.3 允许「一文件多个并列单元（附录一/二）」；§2.2 拆分后文件命名 `chapter-003-a`；没有并列单元的 id 命名规则。
- 结论：修改后采用
- 理由：这样日后拆分文件时 id 无需改变，链接不断。中文书名/标题不能直接做 id，需要转写。
- 落地：guide/02 §4.1 补一句：并列单元 id 按 §2.3 的文件命名规则生成（如 `appendix-a`、`appendix-b`，中文标题转序号或拼音，不用汉字）；§2.2 拆分流程注明「拆出的 section id 不变」。

### SE 5.1.2.1　非 section/article 元素默认不带 id，除非是被链接的点（如尾注）
- SE 原规则：id 用于「读者可能想跳到的结构划分」；其他元素不加 id，除非有链接指向。
- 我们现状：02 §10.2「不被任何链接/CSS/脚本/aria 引用的 id 默认保留」；§9 #18 空锚点迁移。我们对**存量** id 的态度与 SE 相反（保留）。
- 结论：修改后采用
- 理由：SE 管的是「自己产出」，我们处理别人的书，删除存量 id 可能破坏外部引用，保留是对的。但**新生成**的 id 应克制：只有链接目标才生成。
- 落地：guide/02 §10.2 加一句「新生成 id 仅用于链接目标（nav、noteref/backlink、pagebreak、loi/lot 引用、术语引用）；存量 id 不清理，除非用户选『精简』」。代码：现有 rebuild 的 id 生成已基本符合（注号/注文/标题），无需改。

### SE 5.1.2.2　id 不作 CSS 钩子
- SE 原规则：不用 id 做样式钩子。
- 我们现状：03 §10「`id` 选择器…做关键样式」列为应避免；03 §12 A8「`id` 选择器 → class」。
- 结论：已一致
- 理由：同向，理由略不同（我们是旧 RS 兼容与可维护）。注意 SE 自己的 5.2.1 示例用 `#chapter-3 blockquote`，与本条自相矛盾，见 5.2.1。
- 落地：无。

### SE 5.1.2.3　figure 的 id = `illustration-N`（全书流水号）
- SE 原规则：`<figure id="illustration-N">`，N 跨整本书从 1 起。
- 我们现状：04 T12 的 figure 无 id；02 §10.2 示例命名 `fig-3-1`（章号-序号）。我们有 loi（图目录）的 epub:type 但没规定图 id。
- 结论：修改后采用
- 理由：「全书流水号」优点是合并拆分不冲突，值得采用；但名字 `illustration` 是 SE 的插图语境，我们的 figure 还含表格/代码，改用中性名；`fig-章-序` 因章号变动（合并/拆章）会失效。
- 落地：guide/02 §10.2 示例由 `fig-3-1` 改为 `figure-N`（全书流水号，从 1 起；表格为 `table-N`）；规定仅在被 loi/lot 或正文交叉引用时生成。04 T12 加一行说明。

### SE 5.1.2.4　noteref 的 id = `noteref-N`（全书流水号）
- SE 原规则：`<a id="noteref-228" epub:type="noteref" href="endnotes.xhtml#note-228">`。
- 我们现状：04 T16 已规定 `id="noteref-N"`、`href="endnotes.xhtml#note-N"`；rebuild.py:322-323 已实现。
- 结论：已一致
- 理由：T16 本就按 SE 做法写成。
- 落地：无。（附带发现：02 §7.3 仍写 `nr-<章>-<序>`/`fn-…`，与 T16 不同，见汇总「内部不一致」。）

### SE 5.1.2.5　尾注 `<li>` 的 id = `note-N`
- SE 原规则：`<li id="note-1">`，N 为注释序号，回链 `epub:type="backlink"`。
- 我们现状：T16 已一致（`li id="note-N"`，回链放注文末尾）；rebuild.py:540 已实现。
- 结论：已一致
- 理由：同上。
- 落地：无。（`backlink` 作为 `epub:type` 值是否在词表内，02 §6.2 称「role 专用」而 T16 写了 `epub:type="backlink"`，需核对，见汇总。）

### SE 5.1.2.6　术语表 `<dt>` 的 id = `<dfn>` 文本的 URL 安全形式；其余子元素按语境命名
- SE 原规则：`<dt id="blizzard" epub:type="glossterm"><dfn>Blizzard</dfn></dt>`；glossary 里其他非 dt 子元素的 id 不统一规定。
- 我们现状：02 §6.2 列了 `glossterm`/`glossdef`/`glossref`；04 没有术语表模板；07 无术语表检查；02 §10.2「中文 id 虽 XML 合法但不建议」。
- 结论：修改后采用
- 理由：术语表是中文书常见辅文，需要稳定 id 才能被 `glossref` 引用。但汉字不适合直接做 id（已有 §10.2 的立场），应转写。
- 落地：04 新增小模板「术语表」（`<dl>`；`<dt epub:type="glossterm" id="term-N"><dfn>…</dfn></dt>`；`<dd epub:type="glossdef"><p>…</p></dd>`），id 用 `term-N` 流水号（拼音转写易重名且需额外依赖）；`glossary` 的 `section` 仍带 `role="doc-glossary"`。02 §6.2 无需改。

### SE 5.1.2.7　需要 id 但无标准的元素：`<最近 section id>-<元素名>-<N>`
- SE 原规则：N 是该元素在最近父 section（或 article、endnote）内「展平文档树序」的序号，如 `chapter-1-p-2`；子 section 内另计。
- 我们现状：02 §10.2 示例 `ch1`、`s1-2`、`fn-03-2`、`p234`、`fig-3-1`，要求「语义命名、字母开头」，但无统一生成式。
- 结论：修改后采用
- 理由：统一生成式使 id 可推导、可幂等（相同输入产生相同 id），且前缀带 section id 保证不冲突，满足 P5。
- 落地：guide/02 §10.2 加通用生成式 `<所属 section id>-<元素名>-<N>`（N 在该 section 内按文档序，从 1 起）；特例沿用：`noteref-N`、`note-N`、`figure-N`、`table-N`、`term-N`、pagebreak `p<页码>`（02 §8.1）。07 SEM-004 的重命名修复方法改引此生成式（现为 `id-2`、`n-`+原值）。

### SE 5.1.2.8　诗行 id = `<含 z3998:poem 的 section/article id>-line-N`
- SE 原规则：只有被引用的行才加 id，N 为该诗内「展平序」行号，不含 `<header>`。
- 我们现状：04 T9 诗词曲没有行 id；02 §5.7 诗的结构为 `<span class="line">`。
- 结论：修改后采用
- 理由：中文书很少链接到诗行（偶见古籍/注释本），所以不主动生成；但需要时采用统一格式，行号不含标题行。
- 落地：guide/04 T9「注意」加一行：被链接的诗行按 `<诗所在 section id>-line-N` 生成 id（不含标题/作者行），不主动生成。

### SE 5.1.2.9　id 全书唯一；冲突时加最近 section id 前缀
- SE 原规则：id 必须跨整本书唯一（不止文件内）；不同文件里的 `p-1` 冲突时，各加所在 section id 前缀。
- 我们现状：02 §1.2.7、§10.2 要求「文件内唯一」；07 SEM-004「同一目标文档内不得因拆分合并出现重复」。XML/HTML 规范只要求文档内唯一。
- 结论：修改后采用
- 理由：规范层面不需要全书唯一，也不应据此改动存量 id（会断外部链接）；但对**新生成** id，带 section id 前缀可自然达到全书唯一，合并拆分不冲突。5.1.2.7 的生成式已满足。
- 落地：guide/02 §10.2 注明「新生成 id 全书唯一（靠 section 前缀）；存量 id 只要求文件内唯一」。07 增一条 P2 info：全书范围内重复 id 提示（不自动改）。

## 5.2 class 属性

### SE 5.2.1　不用一次性 class 给单个元素挂样式，改用 CSS 选择器（示例：`#chapter-3 blockquote`）
- SE 原规则：class 不作单次使用的样式钩子，几乎总能用选择器选中单个元素；SE 的做法是借 section id 选择器。
- 我们现状：03 §10 禁用 `id` 选择器做关键样式、「复杂链式后代选择器」；07 STY-006（内联样式频次 ≥3 才抽取）、STY-007（多 class 凑效果）、STY-011/015；02 §9 #7「提取成 class；保留在内容语义必需的一次性场景」。没有对「只出现一次」的样式给出明确去向。
- 结论：修改后采用
- 理由：「class 只用于重复出现的一类元素」这个原则可采用；但「用 `#section-id` 选择器替代」与 03 §10 冲突（旧 RS 支持差、id 不稳定、我们不保证 id 不被改写）。因此一次性样式的去向需要裁决。
- 落地：**需决策（见汇总 D1）**。建议：①出现 ≥3 次 → class（STY-006 已有）；②出现 1–2 次 → 优先结构选择器（`section.endnotes li`、`blockquote + p` 这类类+元素组合，不用 id）；③仍无法表达 → 允许带语义名的 class，并在 STY-006 报告里标 info。待定后改 03 §10 与 07 STY-006。

### SE 5.2.2　class 用于一类重复出现的元素
- SE 原规则：同一类元素出现多次时用 class（`.business-card`）。
- 我们现状：04 §0.2 类名注册表；STY-015 清理未用类；STY-006 频次≥3 抽取。
- 结论：已一致
- 理由：就是同一思路。
- 落地：无。

### SE 5.2.3　class 名描述「是什么」，不描述「怎么显示」
- SE 原规则：`.business-card` 好，`.black-border` 差。
- 我们现状：02 §5.2「类名表达含义，不表达外观（`class="name"` 好，`class="red"` 差）」；07 STY-011「命名按语义」；但 04 §0.2/default.css 里的通用类 `noindent`、`align-left/center/right`、`small`、`break-all`、`no-break`、`heiti/kaiti/fangsong`、`w-100/80/60` 是外观命名；`accent` 为语义名。
- 结论：修改后采用
- 理由：原则已采用，但 03/04 的工具类是有意设计的稳定词汇，改名成本高（default.css、rebuild、测试夹具均已使用），且中文书稿里「不缩进/居中/小字」本身就是排版语义。新增的模板类应坚持语义命名。
- 落地：04 §0.2 增一句「通用工具类（noindent、align-*、small、break-all、no-break、字体角色类、w-*）是注册的例外；新增模板类必须语义命名」；07 STY-011 的外观词典加入「工具类白名单」（读取 04 §0.2 注册表）。

## 5.3 xml:lang 属性

### SE 5.3.1.1　读音不是英语的词用 `xml:lang`，哪怕不需要斜体；无样式需求时用 `<span xml:lang>`
- SE 原规则：让读屏知道该读哪种语言；不需要视觉样式时用 `<span xml:lang="TAG">` 包起来。
- 我们现状：02 §8.2「片段外文 `<span lang="en" xml:lang="en">`…与主语言不同时才写」；07 A11Y-002「段内他语种片段用 `lang` 标注」。
- 结论：已一致
- 理由：同一做法，且我们同时写 `lang` 与 `xml:lang`（XHTML 在 EPUB 3 中两者都应写，SE 只写 `xml:lang`；我们更稳）。
- 落地：无。

### SE 5.3.1.2　任何读音特殊的词都标，包括地名、书名
- SE 原规则：不仅是整句外文，任何需要特殊读音的词都带 xml:lang。
- 我们现状：02 §8.2「英文夹杂的中文书不需要给每个英文单词包 `<span lang>`，除非 TTS/断词有明确需求；整段、整个书名、整句才标」；03 §7.3 同。
- 结论：修改后采用
- 理由：中文书里 GDP、iPhone、人名拉丁转写极多，逐词标注噪声大、自动化误差大；SE 的英文环境下外来词稀少所以可以逐词。折中：对**拉丁字母连续串**（≥2 个词或含非 ASCII 拉丁字符，或被《》包住的外文书名）自动标 `lang`（按脚本判别语言码，码不确定时交 LLM/用户），短缩写与常见品牌不标。
- 落地：guide/02 §8.2 把「整段、整个书名、整句才标」改为带阈值的可检测规则（如上）；07 A11Y-002 增加该检测（info，auto 修复仅限能唯一判别为 `en` 的片段，其余 llm）。

### SE 5.3.1.3　`xml:lang` 放在尽可能高的元素上；斜体靠 `body [xml|lang]{font-style:italic}`
- SE 原规则：整个 blockquote 都是外文时，把 xml:lang 放在 blockquote 上，而不是每段套 `<i>`；斜体由属性选择器统一加。
- 我们现状：02 §8.2 示例有 `<p lang="fr" xml:lang="fr">`，但没有「尽量提到最高层」的规则。
- 结论：采用
- 理由：语言标注上提到最高层元素，既减少噪音又更符合 HTML 语义；可检测（相邻同语言兄弟合并到父层）。
- 落地：guide/02 §8.2 加规则「同一块内所有子元素都是同一外语时，把 `lang/xml:lang` 提到该块容器上」；07 加检查（P2 info，auto 修复）。

### SE 5.3.1.4　外文用 `[xml|lang]` 统一斜体（含 `@namespace xml`）
- SE 原规则：见上，用 CSS 属性选择器给带 xml:lang 的元素加斜体。
- 我们现状：03 §7.7、default.css 第 85 行：西文才斜体，汉字不斜；已有 `:lang(en)` 选择器。
- 结论：不采用
- 理由：中文不适用（斜体只对西文，且是否斜体取决于内容类型——书名/学名斜、普通外语句子不一定）；`:lang()` 已满足需求，无需 `@namespace xml`。
- 落地：无。

## 5.4 `<title>` 元素

### SE 5.4.1　`<title>` 只描述本文件，不含书名
- SE 原规则：不要把书名放进 title。
- 我们现状：02 §1.1「必需且非空，建议用本文件的章节标题；不得全书同名或为文件名」；07 SEM-003。
- 结论：已一致
- 理由：同一规则。
- 落地：无。

### SE 5.4.2　title 取值 = 该文件目录条目的文字，且不含 XHTML 标签
- SE 原规则：与目录条目同一算法，只是不能含标签。
- 我们现状：02 §1.1「建议用本文件的章节标题」；07 SEM-003 修复方法「以首个 h1（无则 nav 中对应条目）填充」；rebuild.py:432 取 `ch.title`（章节检测结果，实际与 nav 同源）。优先级是 h1 在前、nav 在后，SE 则以目录条目为准。
- 结论：修改后采用
- 理由：以 nav 条目为准能保证书签/历史记录与目录一致（h1 可能是「第一章<br/>开端」这类多行结构，nav 条目是人工/算法确定的单行文字）；两者不同才需要裁决。无目录条目的文件（封面、版权页）再回落到 h1 或角色名。
- 落地：guide/02 §1.1 `<title>` 行改：「取该文件在 nav 中的条目文字（纯文本，去标签、折叠换行为空格）；无条目者取首个标题纯文本；仍无则用角色名（封面/版权页…）」。07 SEM-003 修复方法同改；rebuild.py 已基本符合，只需确认标题含 `<br/>`/子标签时被折叠（改代码 rebuild，小改）。

## 5.5 Headers

### SE 5.5.1　`<header>` 至少有一个直接子块级元素
- SE 原规则：header 里不能只有裸文本。
- 我们现状：02/04 不使用 `<header>`（章标题直接 `h1` + `p.subtitle`）；输入书可能含 header；02 §1.2.6 有通用内容模型要求，无 header 专项检查。
- 结论：修改后采用
- 理由：我们不生成 header，所以不需要作为产出规则；但对输入书中已有的 header，空 header 或含裸文本的 header 在 XML 解析下合法，却使 `header p` 之类样式不一致，可低成本检测并修复（裸文本包 `<p>`）。
- 落地：guide/07 SEM 增一条 P2 info：「`header` 无块级子元素」，auto 修复（裸文本包 `<p>`）；02 §4 加一句「不新增 `header`/`hgroup`；输入中已有的保留」。

## 5.6 有序/无序列表

### SE 5.6.1　`<ol>/<ul>` 的每个 `<li>` 至少有一个直接子块级元素（通常是 `<p>`）
- SE 原规则：列表项内容包 `<p>`，不裸写文本。
- 我们现状：02 §5.3 示例 `<li>准备材料</li>` 是裸文本；default.css `li p{margin:.2em 0;text-indent:0}` 已为 `li > p` 备好样式；T16 尾注 `<li>` 用 `<p>`。
- 结论：修改后采用
- 理由：SE 之所以要求，是为了给 li 内文字一致的段落样式。我们的中文短列表项（「准备材料」）强行套 `<p>` 是冗余，且默认表里 `p{text-indent:2em}` 对 `li p` 要额外抵消，规则越多越脆。折中：只在 li 内**同时有裸文本和块级子元素**（如 `<li>开始制作<ul>…</ul></li>`）时，才把裸文本包 `<p>`，避免混合内容在不同 RS 下被匿名盒处理出不同间距。
- 落地：guide/02 §5.3 加规则「li/dd 内文字与块级子元素混排 → 文字包 `<p>`；纯文字的短项可不包」；示例里的嵌套列表按此改；07 SEM 增一条 P2：混合内容检测，auto 修复。尾注 li 沿用 T16（已含 `<p>`）。

## 5.7 表格

### SE 5.7.1　`<table>` 有直接子 `<tbody>`（不直接放 `<tr>`）
- SE 原规则：`<tr>` 必须在 tbody/thead/tfoot 内。
- 我们现状：02 §1.2.6 允许 table 直属子为 `tr`；§5.6 示例有 `<tbody>`；04 T18 示例有 `<tbody>`；07 SEM-013 未查 tbody。HTML 内容模型下 `table > tr` 在 XHTML 里合法，但 HTML 解析器会自动补 tbody，造成「序列化前后 DOM 不同、CSS 子选择器 `table > tr` 失效」。
- 结论：采用
- 理由：标准内、无副作用、可全自动修复，也使 `thead`/`tbody`/`tfoot` 的样式选择器一致。
- 落地：guide/02 §1.2.6 把 `tr` 从 table 直属允许子元素中拿掉（改写：「`tr` 必须在 `thead/tbody/tfoot` 内」）；§11 自动修复清单加「裸 `tr` 包 `tbody`」；07 SEM-013 增检测与 auto 修复。

### SE 5.7.1.1　可以有多个 `<tbody>`，用于表中间的分组表头（`th scope="rowgroup"`）
- SE 原规则：中间分组标题行放在各自 tbody 的首行：`<th colspan="2" scope="rowgroup">`。
- 我们现状：02 §5.6 只展示单 tbody；07 SEM-013 要求 `th` 带 scope 但未提 rowgroup。
- 结论：采用
- 理由：HTML 标准做法，对读屏友好；中文统计表常有「一、二、三」分组行，正好适用。
- 落地：guide/02 §5.6 补多 tbody + `scope="rowgroup"` 示例；04 T18 注意事项加一行；07 SEM-013 写明 `rowgroup` 合法。

### SE 5.7.2　`<thead>` 可选；其中用 `<th>`，不用 `<td>`
- SE 原规则：表头单元格用 th。
- 我们现状：02 §5.6、04 T18 示例已是 `thead > tr > th scope="col"`；07 SEM-013「有 `th`（表头）与 `scope`」。
- 结论：已一致
- 理由：同。
- 落地：无。

### SE 5.7.2.1　`<th>` 只出现在 thead，除非带 `scope`（行表头、rowgroup）
- SE 原规则：tbody 里用 th 须有 scope。
- 我们现状：02 §5.6「`<th scope="row">2023</th>`」示例、07 SEM-013 要求 `th` 带 `scope`。
- 结论：已一致
- 理由：同。
- 落地：无。

### SE 5.7.3　合计/汇总行放在 `<tfoot>`
- SE 原规则：表尾合计行用 tfoot。
- 我们现状：02 §5.6 示例有 `tfoot` 且「为稳妥放在最后」；07 SEM-013 提到 tfoot 顺序；未规定合计行必须识别为 tfoot。
- 结论：修改后采用
- 理由：「合计」「总计」「小计」行用 tfoot 有语义价值，但判断是否为合计行需要内容判断（中间的小计行不应移出 tbody），不宜全自动。
- 落地：07 SEM-013 增检测：末行首格匹配 `^(合计|总计|共计|小计|Total)$` → suggest（用户确认后移入 tfoot，首格设 `th scope="row"`）。02 §5.6 补一句。

### SE 5.7.4　表格外边距：`margin:1em`（满宽）或 `margin:1em auto`（非满宽）；戏剧用表格或已有外边距者除外
- SE 原规则：表格需要可见外边距。
- 我们现状：default.css `table{width:100%; margin:.8em 0}`（满宽），04 T18 `table.table-narrow{width:auto; margin-left:auto; margin-right:auto}`（窄表居中）；blockquote 内表格靠 blockquote 的 margin。
- 结论：已一致
- 理由：数值略不同（.8em vs 1em）但同一思路；数值以 03 为准。
- 落地：无。

## 5.8 引文

### SE 5.8.1　`<blockquote>` 必须含至少一个块级子元素（如 `<p>`）
- SE 原规则：blockquote 里不能裸文本。
- 我们现状：02 §5.1「`<blockquote>` 内含 `<p>`」；§5.5「引用中含多段，每段一个 `<p>`」；04 T6 示例同。
- 结论：已一致
- 理由：同。
- 落地：无。

### SE 5.8.2　有出处的引文，出处作为 blockquote 的直接子 `<cite>`（示例 `—<i>Henry V</i>`）
- SE 原规则：`<blockquote><p>…</p><cite>—作品名</cite></blockquote>`，样式靠 `blockquote cite{display:block; text-align:right}`。
- 我们现状：02 §5.1 说出处写 `<p class="source">——出处</p>` 放入 blockquote 内，或用 `<figure><blockquote/><figcaption/></figure>`；§5.5 又写「署名/出处不放在引用文字内」；04 T6 则是 `p.attribution` 在 blockquote 内、右对齐；02 §5.2 的 `<cite>` 仅表书名/作品名。三处写法不一。
- 结论：修改后采用
- 理由：出处作为 blockquote 内的独立块（不是引文正文的一部分）可采用；但载体用我们已注册的 `p.attribution`（T6），不用 `<cite>` 包整句——HTML 规范要求 `cite` 只标作品标题，人名不应放进 `cite`，而中文出处常是「——梁启超《少年中国说》」这类「人名+书名」。书名可在其内再用 `<cite>`（可选）。另外 HTML 规范原文建议引文署名应放在 blockquote **之外**（`figure/figcaption` 形式），SE 与 T6 的做法都在内，见汇总 D2。
- 落地：统一 02 §5.1 的 `p.source` 与 §5.5 的矛盾表述为 T6 的 `p.attribution`（改 02 §5.1、§5.5）；T6 不改；07 增（或并入 SEM-020）检测「blockquote 末段为 `——…` 开头的短行 → 标 `attribution`」（suggest）。

## 5.10 CSS 规则

### SE 5.10.1　要对整个元素的全部内容施加样式时，样式加在该元素本身，不要在里面再套一层元素
- SE 原规则：`<blockquote><p><b>…</b></p></blockquote>` 应改为 CSS 作用于 blockquote。
- 我们现状：02 §9 #20（`b/i` 表达强调）、07 SEM-016「整段/整标题被 b 包裹 → suggest 样式类」；§9 #9 伪标题。
- 结论：已一致
- 理由：同一做法（整段加粗→样式类）。
- 落地：无。

### SE 5.10.2　只对子串施加格式时，若有语义合适的元素（b/i 等）就用它，不用 `<span>` + 以 `epub:type` 为钩子的 CSS
- SE 原规则：`<b epub:type="z3998:salutation">` 而非 `<span epub:type=…>` 配 `[epub|type~=…]{…}`，因为 SE 的 b/i 在 core.css 里被重置，是样式中性的。
- 我们现状：02 §5.2「文字风格…`<b>/<i>/<span class>`，类名表达语义」；03 §10 不依赖属性选择器钩子；04 T8 书信用 `span.salutation` 之类的 class。
- 结论：不采用
- 理由：其他：SE 的前提是自家 core.css 把 `b`/`i` 变成样式中性（`b` 变小型大写），我们的 `b/strong` 就是粗体，`i` 是斜体，不能当中性容器。样式钩子统一用 class，`epub:type` 只承载语义，这也符合 03 §1.2 的分层。
- 落地：无。

### SE 5.10.3　需要显式左对齐时用 `text-align: initial`，不用 `left`，以便 RS 在用户偏好两端对齐时能覆盖
- SE 原规则：见上。
- 我们现状：default.css 多处 `text-align:left`（标题、`.align-left`、`td/th`、`pre`、`p.subtitle`、`p.source`、`p.meta`、04 的 `p.table-note`/版权页）；03 §7.6 竖排处要求 `start/end`；03 §1.2 L1 基线倾向 CSS 2.1 属性。
- 结论：修改后采用
- 理由：物理 `left` 在竖排与 RTL 下是错的；`initial`/`start` 逻辑上更好。但 `start` 在老 RS 的支持未验证，且 03 §5 本身把 `text-align:justify` 设为 body 默认（与 SE 不设 justify 的哲学不同，见汇总 D3）。折中：横排默认表保持 `left`（L1），竖排 `vertical.css` 一律 `start/end`；`.align-left` 类的输出值待实测。
- 落地：guide/03 §5「两端对齐」小节与 §7.6 加一句「显式左对齐用 `text-align:start`（竖排必须）；横排默认表是否换成 `start` 须在目标 RS 实测」；07 STY 增 P2 info 检测竖排样式中的物理 `text-align:left/right`。default.css 暂不改。

### SE 5.10.4　`height`、`max-height`、`top`、`bottom` 用 `vh`，不用百分比
- SE 原规则：百分比高度在分页 RS 里参照系不稳。
- 我们现状：03 §2「视口单位与 100% 高度…参照系因 RS 而异【需实测】；文字尺寸不用 vh；仅封面整页图允许 `max-height:100vh`」；04 T14 封面用 `height:100%`（并注「`100%/100vh` 行为因 RS 而异，两种写法都给出」）；04 T19 竖排 `img{max-height:100%}`。
- 结论：修改后采用
- 理由：两边都承认百分比高度不可靠；SE 的结论是实践得来的，我们的 T14 却默认 `100%`。对「整页」类容器（封面、篇章整页图）优先 `vh`，同时保留 SVG 的 `viewBox` 方案兜底；文字区域本来不设高度，不受影响。
- 落地：guide/04 T14 CSS 改为 `100vh` 优先（`body.cover-page`、`.cover`、`.cover svg`），保留「需实测」；T19 的 `max-height:100%` 同改；guide/03 §2 视口单位行补「height/max-height/top/bottom 不用 %，用 vh」；07 STY 增 P2 info 检测这四个属性的百分比值。

### core.css-4　`q::before,q::after{content:""}`（去掉 `<q>` 的 RS 自动引号）
- SE 原规则：SE 正文引号都是字面字符，不让 RS 在 `<q>` 外再生成一层。

- 我们现状：03 §6 标题左对齐黑体、不用小型大写、margin 按级别；03 §2 输出不用 `:has()`；02/04 不使用 `hgroup`。

### core.css-7　`header{break-after:avoid; break-inside:avoid; hyphens:none; text-align:center}`、`header > * + p{text-indent:0}`、`section > header + *{margin-top:3em}`
- SE 原规则：header 防分页拆开，其内附加的 `p` 不缩进。
- 我们现状：default.css 对 `h1–h6` 有 `break-after/inside:avoid`，但没有对 `header`；`p{text-indent:2em}` 会作用到 header 内的副标题段。
- 结论：修改后采用
- 理由：输入书中已有的 `header` 同样不应被分页拆开，且其内 `p`（副标题、作者行）不应缩进。居中与 3em margin 不采用（中文标题左对齐）。
- 落地：default.css 与 guide/03 §11 追加 `header{break-after:avoid; break-inside:avoid; page-break-after:avoid; page-break-inside:avoid} header p{text-indent:0}`（两处同步改；先改 guide 再改 default.css）。

### core.css-8　`cite{font-style:normal}`、`blockquote cite{display:block; font-style:italic; text-align:right}`、`blockquote cite i{font-style:normal}`
- SE 原规则：`cite` 默认正体；引文出处块右对齐斜体。
- 我们现状：default.css 第 85 行 `:lang(en) em, em:lang(en), i, cite{ font-style:italic; … }` ——其中 `i, cite` 无语言限制，**对中文的 `<cite>《书名》</cite>` 和 `<i>` 也会强制斜体**，与 03 §7.7「汉字不用斜体」、02 §5.2「cite 书名号保留」矛盾（中文被合成伪斜体）。出处块我们用 `p.attribution`（正体右对齐）。
- 结论：修改后采用
- 理由：「cite 默认正体」可采用，且是现存缺陷的修复；出处块的斜体与 `display:block` 不采用（中文不斜体，载体是 `p.attribution`）。
- 落地：改 guide/03 §11 与 default.css 第 85 行为：`i, cite{ font-style:normal; } :lang(en) i, i:lang(en), :lang(en) cite, cite:lang(en){ font-style:italic; font-family:inherit; }`（`em` 的那一半保留）。配套：外文 `i/cite` 必须带 `lang`（见 5.3.1.2），否则会失去斜体，07 增检测。属改代码/样式，影响面小，建议尽快做。

### core.css-9　`abbr{white-space:nowrap; border:none}`
- SE 原规则：缩写不断行。
- 我们现状：default.css `abbr{text-decoration:none}`。
- 结论：不采用
- 理由：其他：`nowrap` 对短缩写合理，但中文书的 `abbr` 也可能包一个较长的中文词组，nowrap 会造成溢出；`white-space:nowrap` 已有类 `.no-break` 按需用。
- 落地：无。

### core.css-10　`b,strong{font-variant:small-caps; font-weight:normal}`、`i>i, em>i, i>em{font-style:normal}`
- SE 原规则：粗体变小型大写；嵌套斜体反转。
- 我们现状：default.css `strong,b{font-weight:bold}`；`em` 为楷体。
- 结论：不采用
- 理由：中文不适用（小型大写；中文强调用楷体/着重号）。嵌套反转针对斜体，`em` 在中文里不是斜体，无需照搬。
- 落地：无。

### core.css-11　`a[epub|type~="noteref"]{font-size:smaller; font-style:normal !important; vertical-align:super}`；`section[epub|type~="endnotes"] > ol > li{margin:1em 0}`
- SE 原规则：注号上标，尾注项间距。
- 我们现状：default.css 的 `a.noteref{font-size:.75em; line-height:0; vertical-align:super; …}`、`section.endnotes > ol > li{margin:1em 0; …}`，用 class 而非属性选择器；无 `!important`；03 §4 指出 `smaller` 在个别 RS 过小。
- 结论：已一致
- 理由：效果一致；属性选择器与 `!important` 的写法不采用（03 §10）。
- 落地：无。

### core.css-12　暗色模式下对黑底透明图 `filter:invert(100%)`，用 `@media all and (prefers-color-scheme: dark)`（注：RMSDK 需要同时写目标媒体类型）
- SE 原规则：靠 `se:image.*` 的 epub:type 区分图片类型。
- 我们现状：04 T12 夜间透明图方案：白底板 `.line-art`，可选 `@media (prefers-color-scheme:dark){ img.line-art{filter:invert…} }`；default.css 第 130 行 `@media (prefers-color-scheme: dark){ .accent{…} }`，未写 `all and`。
- 结论：修改后采用
- 理由：用 class 代替 `se:` 词汇已经是我们的做法；只采用「`@media all and (…)` 写法」这一点——它是合法的标准 CSS，对老引擎无害，且与厂商无关。
- 落地：guide/03 §9 第 8 条与 04 T12 的 `@media` 写法改为 `@media all and (prefers-color-scheme: dark)`；default.css 第 130 行同改。

### 与现有规范冲突、需要决策的点
- **D1（5.2.1）一次性样式怎么挂**：SE 用 `#section-id 选择器`，与 03 §10 禁用 id 选择器冲突。建议：≥3 次→class；1–2 次→「类+元素」结构选择器；仍不行→语义名 class，不用 id。需确认。
- **D2（5.8.2）引文出处放 blockquote 内还是外**：HTML 规范建议署名放 blockquote 之外（`figure/figcaption`），SE 与我们 T6（`p.attribution`）都放里面。要不要改 T6 为 `figure > blockquote + figcaption`？这会影响 T6、02 §5.1、rebuild。建议暂保持现状，仅统一 02 内部表述。
- **D3（5.10.3）`text-align`**：SE 不设全局 justify，让用户偏好生效；我们 03 §5 把 body 默认设为 `justify`。属于哲学差异，建议保持（中文两端对齐是惯例，且用户设置本就可覆盖），但请确认。
- **D4（core.css-8）修 cite/i 斜体缺陷**：现在 default.css 会给中文 `<cite>《…》</cite>`、`<i>` 强制斜体，与 03 §7.7 矛盾。建议立刻按 core.css-8 修；若同意，需同步让外文 `i/cite` 带 `lang`。
- **D5（5.1.1.2）id 与文件名一致**：只对新生成 id 约束，存量 id 不改。若希望连存量也统一，会断外部链接，不建议。
