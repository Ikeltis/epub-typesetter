# 07 质检清单（规则引擎规格书）

> 基准：EPUB 3.3 及配套规范（OCF、Packages、Content Documents、Accessibility 1.1），epubcheck 5.x。
> 本文是优化软件「检测 + 修复」规则引擎的输入规格。与厂商/阅读器无关；书中来自多看、掌阅、Kindle 的私有规则已删除，仅保留其中通用的出版质量要求（改写为中立形式）。
> 标记：【补】书外补充；【需实测】未经验证，实现前须用样本核对。文中 epubcheck 码已于 2026-10-22 对照 EPUBCheck 5.4.0 自带的消息表（`MessageBundle.properties`）逐个核实存在且含义相符。
> 相关文档：容器/OPF/导航见 `01_容器包文档与导航.md`；内容文档语义见 `02_内容文档与语义结构.md`；CSS 与排版值见 `03_CSS与中文排版规范.md`、`04_排版样式模板库.md`；图片字体见 `05_图片与字体资源.md`；文本规范化细则见 `06_中文文本规范化.md`。本清单只给「判定 + 修复入口」，具体数值以那些文档为准。

## 0. 规则字段与约定

### 0.1 字段

| 字段 | 取值与含义 |
|---|---|
| ID | `{类别}-{三位序号}`。类别：PKG 打包与结构、SEM 内容文档良构与语义、CSS、TYP 排版质量、RES 资源、TXT 文本规范化、A11Y 无障碍 |
| 优先级 | P0 = MVP 必做；P1 = 第二阶段（多需启发式或确认）；P2 = 可选/低频/依赖大模型 |
| 严重度 | `error` 违反规范或几乎必然导致阅读异常；`warning` 合规但质量缺陷或兼容风险；`info` 提示/统计，不计入失败 |
| 修复等级 | `auto` 确定性、可回滚、无需确认，默认直接执行；`suggest` 规则可算出修改但有误伤风险，生成补丁并要求用户确认；`llm` 需大模型判断（见 §3），产出补丁后同样要确认；`manual` 只报告 |
| epubcheck | 对应 5.x 消息码；`—` 表示 epubcheck 不检查（自研） |

### 0.2 运行约定

1. 引擎分两阶段：**检测**（只读，输出问题列表 `{rule_id, severity, file, line, col, selector/xpath, message, fix_level, fix_payload?}`）与**修复**（按 rule 顺序应用补丁，再整体重跑检测）。
2. 修复顺序固定：PKG（容器/OPF）→ RES（重命名/转码，需同步更新引用）→ SEM → CSS → TXT → TYP → PKG 导航重建 → A11Y。重命名类修复必须全局更新 OPF、nav、内容文档、CSS 中的引用。
3. 修复必须幂等：对已修复文件再次运行应产生零补丁。
4. 任何 `auto` 修复前保留原包；修复结果须通过 epubcheck（§1）才算成功，否则回滚该条规则的补丁。
5. 豁免：规则可被 `<meta>`/配置按 `{rule_id, file, selector}` 豁免（如现代诗、科技书千分位半角逗号、有意的全屏封面）。
6. **配置项**（不同出版风格的分歧一律做成配置，不做硬规则），默认值如下：

| 配置 | 默认 | 说明 |
|---|---|---|
| `doc.max_bytes` | 256 KB（warning） | 单个内容文档体积，超出建议按标题拆分。EPUB 规范无硬限制；原书的 120 KB 来自特定平台规范，与 `02_内容文档与语义结构.md` §2 统一为 256 KB【需实测】 |
| `nav.max_depth` | 3 | 目录层级建议上限 |
| `indent.em` | 2 | 中文正文首行缩进 em 数；`0` 表示无缩进风格（块间距分段） |
| `css.class_style` | `kebab` | 类名一律小写连字符，以 `04_排版样式模板库.md` §0.2 类名注册表为准（原书中的驼峰命名来自厂商规范，已舍弃） |
| `img.max_bytes` | 1 MB warning / 3 MB error | 书中两个来源的数值，取严作 warning、宽作 error |
| `img.max_px_long_side` | 4096 | 【补】 |
| `lang.primary` | 自动探测 | 中文书 `zh-CN` 或 `zh-Hans` 均合法，须全书一致 |
| `punct.profile` | `cn-mainland` | 标点规范见 `06_中文文本规范化.md` |
| `contrast.min` | 4.5 | WCAG AA 正文 |

### 0.3 共用检测片段（规则表中以 `@名称` 引用）

- `@HAN`：`[\u3400-\u4dbf\u4e00-\u9fff\uf900-\ufaff\U00020000-\U0002fa1f]`（Python 用 `regex` 模块可写 `\p{Han}`）。
- `@CNPUNCT`：`[，。、；：？！…—·“”‘’（）《》〈〉【】〔〕「」『』～]`。
- `@HALF`：`[,.;:!?()]`。
- `@BLOCK`：`p, h1-h6, li, blockquote, dd, dt, figcaption, td, th, div[not(*[self::p or self::div or self::ul or self::ol or self::table or self::blockquote])]`（叶子块）。
- `@TEXT(el)`：`el` 的 `string()` 去除首尾 Unicode 空白（含 `\u00a0 \u3000 \u200b \ufeff`）。
- `@HEADING_SEQ(file)`：按文档顺序取 `//h1|//h2|…|//h6`，得 `[(level, text)]`。
- `@LINKGRAPH`：遍历全部内容文档，收集 `a[@href]` 与 `id`，解析相对路径（先做 `%xx` 解码并规范 `..`），得「源位置 → 目标文件#id」图。
- `@SENT_END`：`[。！？…”’）」』.!?…]$`，段末允许后接右引号/右括号。
- 所有基于文本的规则**只处理文本节点**，不得跨越 `pre`、`code`、`script`、`style` 与 `[translate=no]`，修复时对文本节点改写，不对序列化字符串做正则替换（避免破坏标签）。

## 1. epubcheck 与本清单的分工

### 1.1 原则

epubcheck 5.x 是 EPUB 3.3 规范一致性的权威判定器，**规范层面的对错一律复用**；本清单自研的是 epubcheck 不管的三件事：**质量**（合规但难看）、**修复**（epubcheck 只报不修）、**语义推断**（需要理解文本）。

调用方式：`java -jar epubcheck.jar book.epub --json out.json`（JSON 报告含 `messages[].{ID,severity,message,locations[]}`）；按 `ID` 路由到本清单规则。FATAL/ERROR/WARNING/USAGE 四级映射：FATAL、ERROR → error；WARNING → warning；USAGE/INFO → info。【需实测】5.x 具体 JSON 字段名。

### 1.2 分工表

| 范围 | 做法 |
|---|---|
| 规范硬错误（ZIP/mimetype、container、OPF schema、manifest/spine 引用、XHTML schema、nav 结构、CSS 语法、媒体类型回退、脚本/远程资源声明） | **直接复用** epubcheck；本清单对应规则只定义「如何把 epubcheck 报告转成可修复补丁」，并在 epubcheck 不可用时给自研兜底（STR-001…STR-007 的检测方法可做轻量自检，用于修复前的快速判断） |
| 修复 | **自研**：epubcheck 无修复能力。典型：媒体类型/扩展名不符（OPF-029/PKG-022）→ 魔数嗅探后改 manifest/重命名；重复 ID；缺失 `properties`（OPF-014/015）；目录失效（RSC-012）→ 重建 nav |
| 导航与内容一致性 | **自研**：epubcheck 只验 nav 结构与链接可达，不比较「目录文字 vs 正文标题」「漏标章节」 |
| 排版质量（缩进、空段、断行、图注、注释配对、标题层级、版式一致） | **完全自研**（TYP、部分 SEM/CSS） |
| 文本规范化 | **完全自研**（TXT） |
| CSS | epubcheck 只查语法和少量问题（CSS-008 语法错误、CSS-007 非标准字体类型等；5.x 已不检查 `position`）；样式质量、一致性、可调节性**自研** |
| 资源 | epubcheck 查媒体类型/回退/文件存在（MED-*、RSC-*）；图像模式、体积、分辨率、变形、封面比例、字体覆盖**自研** |
| 无障碍 | epubcheck 5.x 仅做少量可访问性检查（如 `ACC-*` 使用类消息、nav 存在性）；**完整无障碍审计**（alt 质量、元数据完整性、对比度）自研，或另接 Ace（DAISY 的无障碍检查器）【需实测 epubcheck 5.x 对 a11y 元数据的覆盖】 |

### 1.4 实测：22 本测试书的 epubcheck 结果（EPUBCheck 5.4.0，2026-10-22）

样本：21 本早年亚马逊中国电子书（AZW3 原件解包后原样打包，EPUB 2.0.1）+《EPub指南》原书（EPUB 3）。**22 本全部有 error**（每本 4–19 个），1 本 fatal。

| epubcheck 码 | 出现本数 | 实际消息（归类） | 本清单规则 | 备注 |
|---|---|---|---|---|
| RSC-005 | 22 | **schema 错误总入口**，须按消息文本细分：`<meta charset>` 不允许（402 处）、`id` 不是合法 XML 名称（284）、`li@value`/`img@width` 等属性不允许（94）、`data-AmznRemoved` 等属性（27）、`img` 缺 `alt`（25）、空命名空间元素（25）、NCX 缺 `version`（21）、`<title>` 为空、列表/表格嵌套非法、厂商私有属性 | SEM-002/003/004/015、A11Y-001、STR-015 | 前四类多数是 **EPUB 2 的 XHTML 1.1 schema** 造成的，升级为 EPUB 3（HTML5 序列化）后自然消失：`meta charset`、`li@value`、`data-*` 在 HTML5 均合法 |
| OPF-032 | 21 | `guide` 引用了非内容文档（图片作封面） | STR-015 | 升级 EPUB 3 时改由 nav landmarks 表达封面；保留的 `guide` 只指向 XHTML |
| CSS-008 | 4 | CSS 语法错误（如属性名后缺冒号） | STY-001 | — |
| RSC-007 | 4 | `@font-face` 引用的字体文件不在包内 | RES-009 | 指南原书也有（引用了未打包的字体） |
| HTM-004 | 2 | DOCTYPE 不规范 | SEM-002 | — |
| RSC-012 | 1 | 链接片段标识符不存在 | SEM-005、STR-010 | — |
| OPF-027 | 1 | 厂商私有属性（`duokan-page-fullscreen`） | — | 见 §1.3 |
| OPF-029 | 1 | PNG 文件登记为 `image/jpeg` | STR-006 | — |
| RSC-016 | 1（fatal） | XML 解析致命错误：`&` 后不是实体名（裸 `&`） | SEM-001 | 不修复则整个文档无法解析 |

结论：

1. **「升级到 EPUB 3」本身就是一条高收益修复**：本样本中数量最多的 RSC-005 子类，大半随 EPUB 2→3 的序列化升级消失。实现时先升级再校验，避免对 XHTML 1.1 的报错逐条修。
2. RSC-005 不能只按码号路由，**必须按消息文本二次分类**（正则匹配 `attribute "(\w+)" not allowed`、`must not be empty` 等）。
3. epubcheck 自带繁体中文消息表（`MessageBundle_zh_TW.properties`），网页界面可直接用作中文报错文案的底稿。

## 3. 适合交给大模型的规则

### 3.1 判定原则

规则引擎能用确定性算法判定的一律不用大模型。大模型只处理三类：**语义分类**（这段是标题吗、是诗吗）、**上下文裁决**（这个半角标点是不是英文句子的一部分、这两段是否该合并）、**生成**（alt、元数据摘要）。大模型的输出必须是**结构化补丁**（`{rule_id, node_ref, action, new_text|new_tag, confidence}`），由引擎校验后应用，**不允许大模型重写整段 XHTML**；任何补丁须先通过：XML 良构、仅改文本/标签/class、文本字符集合差异（编辑距离占比）不超过 5%（TXT-010 等除外，其本身就是改字）。

### 3.2 规则与输入

### 3.3 输入约束

1. **只送片段，不送全书**：单次请求 ≤2k 汉字（约 3k token）；图像另计。上下文只含判定所需的邻近块与全书统计量（如行宽中位数、样式类频次表），后者以 JSON 摘要提供。
2. 每个片段带稳定引用（`file`、块序号 `n`、内容哈希），响应按引用回填；哈希变化则补丁作废。
3. 全书级判断（章节角色、术语一致性）使用**离线抽取的特征表**（标题序列、各文件首尾 300 字、实体表），不送正文。
4. 预过滤：先由规则筛出候选，再送模型；候选占比应 <5% 的块，若全书 >30% 命中说明规则阈值失效，应先调规则。
5. 隐私与成本：支持本地模型/可配置端点；对同一片段缓存（按 `哈希+规则ID`）。
6. 输出验证：JSON schema 校验；`confidence` 缺省视为 0；模型返回与输入不符的引用一律丢弃。
7. 禁止交给大模型的：ZIP/OPF/nav 的结构修复、ID/链接重写、CSS 重写、文件重命名（确定性重写，见 PKG/CSS 规则）。

## 6. 问题报告格式与测试夹具

### 6.1 问题记录（JSON，引擎内部与 UI 共用）

```json
{
  "rule_id": "TYP-002",
  "severity": "warning",
  "file": "OEBPS/text/chapter-03.xhtml",
  "line": 118, "col": 5,
  "xpath": "/html/body/section/p[42]",
  "message": "空段落（仅含 &nbsp;）",
  "fix_level": "auto",
  "fix": {"op": "remove_node", "xpath": "/html/body/section/p[42]"},
  "source": "native | epubcheck:RSC-012",
  "confidence": 1.0
}
```

- `fix.op` 取值集合：`remove_node`、`replace_text`、`set_attr`、`rename_file`（附 `old→new`，引擎自动展开为全局引用更新）、`rewrite_css`、`regen_nav`、`regen_manifest`、`merge_nodes`、`split_file`。补丁只能由这些原子操作组成，便于回滚和 diff 展示。
- `source` 为 `epubcheck:*` 时，`rule_id` 取 §1.3 的映射；无映射的 epubcheck 消息以 `EPUBCHECK-{code}` 原样上报，`fix_level=manual`。
- 同一位置同时被多条规则命中时，按 §0.2 修复顺序依次处理，并在每一步后重新计算 xpath（修复可能改变节点位置）。

### 6.3 通过标准

- 回归集建议：epubcheck 官方测试 EPUB、含中文竖排/横排、含诗歌/引文/脚注/表格/大图、TXT 转换书各至少一本；
- 每条规则的假阳性率目标：`auto` 规则在回归集上 0 误修（人工抽检），`suggest` 规则命中后用户接受率 ≥70% 才升级为默认勾选；
- 新增规则必须附最小夹具与期望补丁，并声明是否与 epubcheck 重叠（表中「epubcheck」列）。
