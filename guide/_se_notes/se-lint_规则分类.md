## 5. 报错结构与豁免机制（供我们设计报告格式参考）

以下为对源码结构的复述，非摘抄。

### 5.1 报错的数据结构

- **一条报错（LintMessage）** 包含：规则编号 `code`；问题描述 `text`（一句话，内部用方括号做轻量标记，如元素名、属性名、CSS 值、路径各有各的着色标签，提示 hint 也嵌在同一段文字里用标签包住，而不是单独字段）；严重度 `message_type`（只有 error 与 warning 两级，没有 info）；所属文件 `filename`（可为空，表示全书级问题，如元数据或缺文件）；明细列表 `submessages`。
- **明细（LintSubmessage）** 是同一规则在该文件里的每一处命中：命中的文本片段或元素的序列化文本 `text`，加行号 `line_num` 和列号 `column_num`（列号预留，基本未用）。同一规则同一文件只产出一条 message，多处命中放进 submessages，而不是每处一条。
- 明细有多种构造方式：由正则命中位置（带行号）、由 XPath 命中元素（完整元素文本）、由元素的起始标签（只显示标签，不展开内容）、由元素的内部文字；可选给片段加着色标签。报告里按行号升序排列。
- 若明细是带缩进的多行 XHTML，构造时会统一去掉共同的前导缩进，让输出整齐。
- **行号回溯**：为了在删去注释或某些片段后仍能给出原文件行号，源文件包装类 SourceFile 保存「行起点偏移 → 原行号」的映射，每次做删除替换时同步重算偏移，查找时用二分定位。这让「先清洗文本再正则匹配」和「报告原始行号」可以同时成立。
- **报告顺序**：全部 message 按「文件名 + 空格 + 规则编号」做自然排序（数字按大小比较），无文件的排在最前。
- **编号稳定**：已废弃的编号保留占位而不复用（源码中有 4 个空占位），编号分类用单字母前缀，按主题分组，便于长期引用与文档链接。
- **粒度**：规则按「文件级」（元数据、文件系统）与「内容级」（行号级）两种位置信息混用；文件级问题没有行号，只有文件。

### 5.2 豁免机制

- **配置文件**：书根目录下一个 XML 文件（`se-lint-ignore.xml`），根下若干 `file` 元素，每个带 `path` 属性；`file` 下若干 `ignore` 元素，带 `code` 属性（要忽略的规则编号），可选地含若干 `line` 子元素（要忽略的行号）。源码里没有「理由」字段。
- **匹配方式**：`path` 是通配模式（fnmatch 风格），**只拿报错文件的文件名（不含目录）去匹配**；同时要求规则编号完全相等。没有 line 子元素 = 整文件豁免该规则；有 line = 只从该报错的明细里删去行号相同的那几条，若明细因此被删光，整条报错一并消失。
- **自检规则**：豁免文件自身也被 lint，违规时报 error 或 warning：同一 path 重复出现；同一规则既整文件豁免又按行豁免（冲突）；通配路径却带行号（行号在通配下无意义）；同一行重复豁免；`path` 写成单个 `*`（太宽泛，警告）；**豁免从未命中**（未使用的豁免本身报错，防止规则修好后豁免变成僵尸）；豁免文件里没有任何规则（应删除文件，源码里已登记但未启用）。
- **运行时开关**：可整体跳过豁免文件；也可传入一组规则编号，使这些编号的豁免在本次运行中失效（用于临时复查被豁免的问题）。
- **缺点与可改进处**：只按文件名匹配，不同目录同名文件会被一并豁免；行号一旦因编辑偏移，豁免就失效（会靠「未使用的豁免」报错暴露）；没有理由字段、没有有效期。

### 5.3 对我们报告格式的建议

1. 每条报告保留：规则 ID、严重度（我们有 error/warning/info 三级，比 SE 多一级）、一句话问题、**独立的 hint 字段**（SE 把它塞进文字里，不利于机器处理）、文件、行/列、命中片段，并增加我们特有的**修复等级**（auto/suggest/manual）与**可回滚补丁**引用。
2. 同规则同文件合并为一条，明细列出每处命中；JSON 输出里明细是数组，网页界面可折叠。
3. 行号回溯：我们的重建流程会改写 XHTML，建议报告里同时记「原文件行号」与「当前文件行号」，沿用偏移映射的思路。
4. 豁免采用「书根目录一个配置文件」，条目为（文件通配 + 规则 ID + 可选行或选择器），**增加 reason 字段和用 EPUB 内相对路径而不是仅文件名匹配**；保留「未命中的豁免即报错」和「通配路径不可配行号」「整文件豁免与行豁免冲突」三条自检。行号易漂移，建议豁免以「元素 id 或内容片段哈希」作辅助锚点。
5. 编号永不复用，废弃的 ID 保留占位；规则按前缀分类（我们已有 STR/SEM/STY/TYP/TXT/RES/A11Y）。
