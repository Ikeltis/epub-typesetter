# 01 容器、包文档与导航

> 基准：EPUB 3.3（W3C Recommendation, 2023）= Packages + OCF + Content Documents + Accessibility 1.1 等。
> 标记：【补】= 原书未涉及、由本规范补充；【需实测】= 阅读器行为无把握，不得当作结论；EpubCheck 错误码取自 5.x，以实际输出为准。
> 本篇覆盖"包"这一层：zip 容器、container.xml、OPF、导航文档、NCX 兼容、无障碍元数据。内容文档见 `02_内容文档与语义结构.md`；图片/字体资源见 `05_图片与字体资源.md`；质检汇总见 `07_质检清单.md`。

---

## 1. 整体结构与解析顺序

```
book.epub (ZIP)
├─ mimetype                      # 必须，首个条目，Store，内容固定
├─ META-INF/
│   ├─ container.xml             # 必须，指向包文档
│   ├─ encryption.xml            # 可选，字体混淆/加密声明
│   └─ (signatures.xml / metadata.xml / rights.xml)  # 可选，原样保留
└─ EPUB/                         # 目录名不限（OEBPS、OPS、content、根目录皆合法）
    ├─ package.opf               # 包文档（文件名不限）
    ├─ nav.xhtml                 # EPUB 3 导航文档
    ├─ toc.ncx                   # 可选：EPUB 2 兼容
    ├─ text/    *.xhtml
    ├─ styles/  *.css
    ├─ images/  fonts/  audio/
```

阅读系统解析链：校验 mimetype → 读 `META-INF/container.xml` 取 `rootfile@full-path` → 读 OPF → 按 manifest/spine/nav 呈现。

**硬规则**：程序不得写死 `OEBPS/content.opf`，一律从 container.xml 读取；目录名、文件名（`text/`、`Text/`）只是习惯，规范不要求。

## 2. OCF：容器规范

### 2.1 mimetype（硬性，可逐条判定）

| 要求 | 判据 |
|---|---|
| 文件名恰为 `mimetype`（小写，位于 zip 根） | 条目名全等 |
| **是 zip 的第一个条目** | 中央目录/本地头顺序第 0 项 |
| **Store（不压缩）** | compress_type = 0 |
| 本地文件头 **无 extra field** | extra_len = 0 |
| 内容为 US-ASCII 的 `application/epub+zip`，无 BOM、无前后空白、**无结尾换行** | 字节全等，长度 20 |
| 不加密 | — |

违反即 EpubCheck `PKG-006`（缺失/非首个）、`PKG-005`（extra field）、`PKG-007`（内容错误）。许多阅读器能容忍，但识别工具（`file`、系统缩略图、上传校验）依赖前 60 字节魔数，故必须遵守。

### 2.2 ZIP 要求

- 压缩只允许 **Deflate** 或 **Store**；禁止加密条目、禁止分卷（multi-disk）。建议避免 ZIP64。
- 条目名 UTF-8（置 general purpose flag bit 11），路径分隔符 `/`；不得以 `/` 开头、不得含 `\`。
- 不得含重复条目；**条目名在 Unicode 大小写折叠后也不得重复**（`Cover.xhtml` 与 `cover.xhtml` 在 macOS/Windows 上会互相覆盖）。
- 不建议含目录条目（`text/`），不得含 `__MACOSX/`、`.DS_Store`、`Thumbs.db`、`desktop.ini`、`.git/` 等垃圾（EpubCheck 会警告）。
- 压缩建议：文本类（xhtml/css/opf/ncx/svg）Deflate；**已压缩的图片/音视频/woff/woff2 用 Store** 即可，重压无收益。
- 容器根目录（除 mimetype、META-INF）下可放任意内容；`META-INF/` 内只放 OCF 保留文件，**不得放出版物资源**。

### 2.3 路径与文件命名

EPUB 3.3 OCF 对路径的限制（任一违反 = 错误，`PKG-009`/`PKG-011`）：

- 不得含：`NUL` 与控制字符（U+0000–001F、U+007F–009F）、`"` `*` `:` `<` `>` `?` `\` `|`、Unicode 非字符与私用区字符。
- 路径各段不得为空，不得是 `.` 或 `..`；**段末不得是 `.`**。
- 不得有两个路径仅在大小写（或 NFC/NFD 规范化后）不同。

EpubCheck 另有软提示：含空格 `PKG-010`（警告）、含非 ASCII `PKG-012`（USAGE）。

**【补】优化软件的命名策略**（规范不强制，但跨阅读器/跨平台最稳）：

```
正则  ^[a-z0-9][a-z0-9_-]*(\.[a-z0-9]+)?$       # 小写 ASCII、数字、_ -，单个扩展名
```

- 禁空格、中文、`#`、`%`、`&`、`+`、`'`、全角字符；扩展名小写，且与真实内容一致（`.jpg` 里是 PNG 要纠正，见 §10）。
- 序号补零：`chapter-001.xhtml`，保证字典序 = 阅读序；总长度（含目录）建议 ≤ 100 字节，硬上限 255 字节/段。
- 内容文档/图片/CSS/字体分目录存放（`text/ images/ styles/ fonts/`），便于质检；但**改名/移动必须同步改全书引用**：OPF `href`、nav/NCX、XHTML 的 `href/src/xlink:href/poster`、CSS 的 `url()` 与 `@import`、SVG 内引用、`encryption.xml` 的 `CipherReference@URI`、`container.xml`。
- href 是 **URL 而非文件系统路径**：空格须写 `%20`，`#`/`?`/`%` 在文件名里须百分号编码；比较时先解码再比对 zip 条目。
- 重命名风险大于收益时（书无问题、仅命名不雅）默认不改，作为"建议"项。

### 2.4 container.xml

```xml
<?xml version="1.0" encoding="UTF-8"?>
<container version="1.0" xmlns="urn:oasis:names:tc:opendocument:xmlns:container">
  <rootfiles>
    <rootfile full-path="EPUB/package.opf" media-type="application/oebps-package+xml"/>
  </rootfiles>
</container>
```

- `full-path` 相对 zip 根；指向的文件必须存在；`media-type` 固定。
- 允许多个 `rootfile`（多 rendition，例如漫画 SVG 版 + 文字版）；**第一个是默认 rendition**。绝大多数书只有一个。优化软件遇到多 rootfile：默认逐个处理，或报告后原样保留非默认 rendition。
- 不得写 `<?xml ... encoding="GBK"?>`；所有 XML 文件（container/opf/ncx/xhtml/svg）编码为 UTF-8（或 UTF-16，不推荐）。

### 2.5 字体混淆（encryption.xml）

用于嵌入字体的"防随手提取"（**不是 DRM**），算法 URI `http://www.idpf.org/2008/embedding`。

```xml
<encryption xmlns="urn:oasis:names:tc:opendocument:xmlns:container"
            xmlns:enc="http://www.w3.org/2001/04/xmlenc#">
  <enc:EncryptedData>
    <enc:EncryptionMethod Algorithm="http://www.idpf.org/2008/embedding"/>
    <enc:CipherData><enc:CipherReference URI="EPUB/fonts/body.otf"/></enc:CipherData>
  </enc:EncryptedData>
</encryption>
```

算法（可逆，约 15 行代码）：

1. 取 OPF 中 `unique-identifier` 所指 `dc:identifier` 的文本，**删除全部空白字符**（U+0020、U+0009、U+000D、U+000A）。
2. 取其 UTF-8 字节的 **SHA-1**（20 字节）作为密钥。
3. 对字体文件**前 1040 字节**，第 i 字节与 `key[i % 20]` 异或；其余字节不变。
4. 解混淆 = 同一操作。

对优化软件的硬约束：

- **改 `dc:identifier`、或移动/改名被混淆字体，都会使混淆失效**。处理流程：读入时先对所有 `encryption.xml` 登记的字体解混淆，输出时选择（a）不再混淆并删除对应条目（最简单，推荐；需提示"字体许可是否允许明文嵌入"），或（b）用新 identifier 重新混淆。
- `encryption.xml` 中出现**其他算法**（如 `xmlenc#aes128-cbc`、Adobe `adobe.com/adept`）= 真 DRM：**拒绝处理或原样透传**，不得尝试改写。
- 混淆字体在 zip 中仍按普通文件压缩/存储；`encryption.xml` 条目的 URI 必须与 manifest href 完全一致（解码后）。

## 3. 包文档（OPF）总览

```xml
<?xml version="1.0" encoding="UTF-8"?>
<package xmlns="http://www.idpf.org/2007/opf" version="3.0"
         unique-identifier="pub-id" xml:lang="zh-Hans" prefix="">
  <metadata xmlns:dc="http://purl.org/dc/elements/1.1/">
    <dc:identifier id="pub-id">urn:uuid:3f8b8c1e-5d0a-4c53-9a3e-0b6f6e1d2a77</dc:identifier>
    <dc:title id="t1">书名</dc:title>
    <dc:language>zh-Hans</dc:language>
    <meta property="dcterms:modified">2025-01-31T08:00:00Z</meta>
    ...
  </metadata>
  <manifest> ... </manifest>
  <spine page-progression-direction="ltr"> ... </spine>
</package>
```

- `version` 写 `3.0`（EPUB 3.3 的包文档版本号仍是 `3.0`；**写成 `3.3` 会报错**）。
- 三个子元素 `metadata`、`manifest`、`spine` 必备；`collection`、`bindings`（已弃用）、`guide`/`tours`（EPUB 2 遗留）可选。
- `unique-identifier` 必须匹配某个 `dc:identifier@id`（`OPF-030`）；缺失 `OPF-048`。
- `prefix` 仅在使用非保留词表前缀时才需声明；**保留前缀无需声明**：`dcterms`、`marc`、`media`、`onix`、`prism`、`rendition`、`schema`、`xsd`、`a11y`。
- `xml:lang`/`dir`/`id` 可选，不影响内容文档。

## 4. 元数据

### 4.1 必需项（缺任一 = 错误）

| 元素 | 规则 |
|---|---|
| `dc:identifier` | ≥1；被 `unique-identifier` 引用的那个是出版物唯一标识。推荐 `urn:uuid:` 或 `urn:isbn:`（ISBN 须通过校验位）。**优化时不得随意更换**（同一本书的新版本应保持标识不变；且字体混淆依赖它，见 §2.5） |
| `dc:title` | ≥1；非空；应与封面/书名页一致，不得是文件名（`book`、`新建文档`、`Untitled`） |
| `dc:language` | ≥1；BCP 47；首个为主语言，须与正文主语言一致 |
| `<meta property="dcterms:modified">` | 恰 1 个，格式 `CCYY-MM-DDThh:mm:ssZ`（**UTC、必须带 `Z`、无毫秒/时区偏移**），例 `2025-01-31T08:00:00Z`。优化软件每次输出都应更新为当前 UTC |

**语言码（中文）**【补】：推荐带文字的标签——简体 `zh-Hans`（或 `zh-Hans-CN`），繁体 `zh-Hant`（`zh-Hant-TW`/`zh-Hant-HK`）。`zh-CN`/`zh-TW` 同样合法且兼容性最广；只写 `zh` 合法但丢失字形倾向（阅读系统/字体回退会据此选择 CN/TW/HK/JP 字形，见 `03_CSS与中文排版规范.md`）。判定依据：正文字符的简繁统计，而非猜测。文言文可用 `lzh`；日文 `ja`。

### 4.2 常用可选项

| 元素 | 说明 |
|---|---|
| `dc:creator` | 作者；**每人一个元素**（不要 `A、B` 并写）；顺序即署名顺序 |
| `dc:contributor` | 译者、编者、绘者、校订者等次要责任人 |
| `dc:publisher` / `dc:date` | 出版者；日期（出版日期，ISO 8601：`2020`、`2020-05`、`2020-05-01`）；**`dc:date` 至多 1 个** |
| `dc:subject` / `dc:description` / `dc:rights` / `dc:source` | 主题词（每词一个元素）、简介（纯文本）、版权声明、来源（纸书 `urn:isbn:`） |
| `dc:type`、`dc:format`、`dc:relation`、`dc:coverage` | 极少用 |

简介（`dc:description`）可吸收原书"内容提要/作者简介"页的文字（见 `02_内容文档与语义结构.md` §3）。

### 4.3 refines：给元数据加修饰

`<meta refines="#id" property="..." [scheme="..."]>值</meta>`，`refines` 是指向被修饰元素 `id` 的**片段 URL**（必须带 `#`，且 id 存在）。

```xml
<dc:creator id="a1">余华</dc:creator>
<meta refines="#a1" property="role" scheme="marc:relators">aut</meta>
<meta refines="#a1" property="file-as">Yu, Hua</meta>
<meta refines="#a1" property="alternate-script" xml:lang="en">Yu Hua</meta>
<meta refines="#a1" property="display-seq">1</meta>

<dc:contributor id="c1">某某</dc:contributor>
<meta refines="#c1" property="role" scheme="marc:relators">trl</meta>

<dc:title id="t1">活着</dc:title>
<meta refines="#t1" property="title-type">main</meta>
<dc:title id="t2">（修订版）</dc:title>
<meta refines="#t2" property="title-type">subtitle</meta>
<meta refines="#t2" property="display-seq">2</meta>
```

| 属性 | 用途 | 值 |
|---|---|---|
| `role`（`scheme="marc:relators"`） | 责任人角色 | `aut` 作者、`trl` 译者、`edt` 编者、`ill` 绘者、`pbl` 出版者、`cov` 封面设计、`ann` 注释者、`aui` 序言作者、`cmm` 评注者、`ctb` 贡献者 |
| `file-as` | 排序用名 | 西文 `姓, 名`；中文可留空或写拼音【补】 |
| `alternate-script` | 另一文字的同一名字（拼音/英文名） | 需 `xml:lang` |
| `title-type` | 标题类型 | `main`、`subtitle`、`short`、`collection`、`edition`、`expanded` |
| `display-seq` | 多项并列时显示次序 | 正整数 |
| `identifier-type` + `scheme` | 标识符类型 | 如 ISBN：`<meta refines="#i2" property="identifier-type" scheme="onix:codelist5">15</meta>` |
| `authority` / `term` | 主题词来源与编码 | 如中图法 |

规则：`dc:creator` 可无 role（默认视为作者）；译者按【补】惯例放 `dc:contributor` 并标 `trl`（亦可放 creator，规范允许，但会被某些系统当作作者署名）；**EPUB 2 的 `opf:role`/`opf:file-as`/`opf:event` 属性在 EPUB 3 中不允许**，须迁移成 refines（`OPF-` 系列 schema 错误，归 `RSC-005`）。

### 4.4 系列与分册（belongs-to-collection）

```xml
<meta property="belongs-to-collection" id="c-series">三体</meta>
<meta refines="#c-series" property="collection-type">series</meta>
<meta refines="#c-series" property="group-position">2</meta>
```

- `collection-type`：`series`（系列）或 `set`（套装）；`group-position` 为序号（可为 `2` 或 `2.5`）。
- 嵌套系列：给 `belongs-to-collection` 再 refines 一个 `belongs-to-collection`。
- 【补】Calibre 生态的 `<meta name="calibre:series" content="..."/>`、`calibre:series_index` 是事实标准，Calibre 与不少国内书库只认它们。**既有则保留**，生成系列信息时可两套并存。
- 书名页上的系列格式（`系列名：书名（分册）`）是出版规范，不是 OPF 规则；若 `dc:title` 带了分册后缀，建议拆到 `title-type=subtitle` 或系列元数据里。

### 4.5 封面声明

- EPUB 3：manifest 中**恰有一个**图片项带 `properties="cover-image"`（`OPF-012`：用在非图片上）。
- 【补】兼容旧系统（Calibre、部分书库、旧阅读器）可并存 `<meta name="cover" content="manifest-item-id"/>`；纯 EPUB 3 目标下可省，保留已有的不要删。
- 封面**页面**（`cover.xhtml`）是另一回事：它是 spine 首项，内含该图片，并在 landmarks 登记（§6.3）。

### 4.6 其他元数据

- `dcterms:` 前缀的 `<meta>`（如 `dcterms:modified`）与 `dc:` 元素是两套；自定义/私有 `<meta name="x" content="y"/>`（OPF 2 写法）EPUB 3 容忍，**一律原样保留**，不得当错误删除。
- `<link rel="..." href="...">` 可挂外部记录（ONIX、XMP），`href` 指向容器内文件时该文件须在 manifest 中。
- 元数据里的 XML 实体、换行、首尾空白：写入前 trim；`dc:title` 内不得含 HTML 标签。

## 5. manifest 与 spine

### 5.1 manifest

```xml
<manifest>
  <item id="nav"     href="nav.xhtml"         media-type="application/xhtml+xml" properties="nav"/>
  <item id="ncx"     href="toc.ncx"           media-type="application/x-dtbncx+xml"/>
  <item id="cover"   href="text/cover.xhtml"  media-type="application/xhtml+xml"/>
  <item id="cover-img" href="images/cover.jpg" media-type="image/jpeg" properties="cover-image"/>
  <item id="ch001"   href="text/chapter-001.xhtml" media-type="application/xhtml+xml"/>
  <item id="css"     href="styles/book.css"   media-type="text/css"/>
  <item id="f-body"  href="fonts/body.woff2"  media-type="font/woff2"/>
</manifest>
```

硬规则：

- `id` 全包唯一且是合法 NCName（字母/下划线开头，不含空格、冒号；**不能以数字开头**）；`href` 唯一（同一文件不得登记两次）。
- `href` 是相对 OPF 的 URL，不得含绝对路径、盘符（`C:/...`）、`file:`、越出容器根的 `..`、片段 `#`。
- **容器里的每个文件都必须登记**（`container.xml`、`mimetype`、`META-INF/*`、OPF 自身除外），否则 `OPF-003`（警告）/ 阅读器可能不加载；**登记的文件必须存在**（`RSC-001`）。
- item 次序无意义；允许任意排序。
- 同一 id 被声明两次、href 为本机绝对路径、NCX 项被写成 `application/xhtml+xml`+`properties="nav"`——这类"合并出的坏 manifest"见 §10。

### 5.2 properties 取值

| 值 | 用于 | 含义/判据 | 缺失/误用后果 |
|---|---|---|---|
| `nav` | 导航文档 | **恰 1 个**项带此值，且是 XHTML | 缺则 EPUB 3 无目录 |
| `cover-image` | 封面图 | 至多 1 个，图片类型 | `OPF-012` |
| `scripted` | 内容文档 | 文档含 `<script>`、事件处理属性（`onclick`）、或 `<form>` 等脚本化内容 | 缺 `OPF-014`；多写 `OPF-015` |
| `svg` | XHTML 文档 | 文档含**内联** `<svg>`（经 `<img>` 引用的 SVG 文件不需要） | 缺 `OPF-014` |
| `mathml` | XHTML 文档 | 含 `<math>` | 缺 `OPF-014` |
| `remote-resources` | 内容文档/SVG/CSS | 引用容器**外**的资源（远程字体、音视频） | 缺 `OPF-014` |
| `switch` | 内容文档 | 含 `epub:switch`（EPUB 3.2 起已弃用，勿再生成） | — |

- 自动推断：解析每个 XHTML 得出 `scripted/svg/mathml/remote-resources` 集合，与 manifest 声明做差集，**可全自动修复**。
- 远程资源【补】：规范仅允许**音频、视频、字体**驻留在容器外；图片、CSS、脚本、iframe 目标均应在容器内。优化软件对远程图片/CSS 应报告，而非静默保留。含 `http(s)://` 的 `<a href>` 超链接不算资源引用。
- `properties` 值之间以空格分隔，大小写敏感。
- 其他可见的 manifest 属性：`fallback`（非核心类型的回退，见 §5.4）、`media-overlay`（SMIL，本规范不展开，**遇到则原样保留**）。

### 5.3 media-type 表

| 类别 | media-type | 扩展名 | 备注 |
|---|---|---|---|
| 内容文档 | `application/xhtml+xml` | .xhtml | **不是 `text/html`**（`OPF-035` 警告） |
| 内容文档 | `image/svg+xml` | .svg | SVG 内容文档（如整页封面）也可当图片 |
| 导航/兼容 | `application/x-dtbncx+xml` | .ncx | 仅 NCX |
| 样式 | `text/css` | .css | |
| 图片 | `image/jpeg` | .jpg/.jpeg | 核心 |
| 图片 | `image/png` | .png | 核心 |
| 图片 | `image/gif` | .gif | 核心；动图支持因阅读器而异【需实测】 |
| 图片 | `image/svg+xml` | .svg | 核心 |
| 图片 | `image/webp` | .webp | EPUB 3.3 起列为核心；老阅读器可能不显示【需实测】，保守输出用 jpeg/png |
| 字体 | `font/woff2`、`font/woff` | .woff2/.woff | 核心 |
| 字体 | `font/ttf`、`font/otf` | .ttf/.otf | 核心；旧值 `application/font-sfnt`、`application/vnd.ms-opentype`、`application/font-woff`、`application/x-font-ttf`（后者为**非标准**，原书示例沿用）建议迁移到 `font/*` |
| 脚本 | `text/javascript` | .js | 3.3 推荐；`application/javascript` 仍可 |
| 音频 | `audio/mpeg`、`audio/mp4`、`audio/ogg`（Opus 编码） | .mp3/.m4a/.opus | 核心 |
| 视频 | `video/mp4` 等 | .mp4 | **无核心视频类型**，须 HTML 内给回退 |
| 其他 | `application/smil+xml`（Media Overlay）、`application/pls+xml`（发音词典）、`application/oebps-package+xml`（OPF，仅用于 container.xml） | | |

规则：

- **非核心类型必须有回退**（manifest `fallback` 指向核心类型项，或在 HTML 中用 `<picture>/<source>`、`<audio>/<video>` 子元素、`<object>` 回退）；否则 `OPF-043`。典型：`image/bmp`、`image/tiff`、`image/avif`、`application/pdf`。
- **media-type 必须与文件真实内容一致**：以魔数为准（JPEG `FF D8 FF`、PNG `89 50 4E 47`、GIF `47 49 46 38`、WebP `RIFF....WEBP`、woff `wOFF`、woff2 `wOF2`、OTF `OTTO`、TTF `00 01 00 00`），扩展名也应一致（`OPF-029`/`PKG-022`）。以魔数纠正 media-type，并统一扩展名（改名要同步引用，见 §2.3）。

### 5.4 spine

```xml
<spine page-progression-direction="ltr" toc="ncx">
  <itemref idref="cover"/>
  <itemref idref="ch001"/>
  <itemref idref="notes" linear="no"/>
</spine>
```

- `itemref@idref` 必须存在于 manifest（`OPF-049`），不得重复（`OPF-034`），指向的必须是内容文档（XHTML/SVG）或其 fallback 为内容文档。
- **阅读顺序 = spine 顺序**。至少有一个 `linear="yes"`（默认）项（`OPF-033`）。
- **所有可作为超链接目标的内容文档都必须在 spine 里**（目录项、正文 `<a>`、landmarks 的目标），否则 `RSC-011`。仅被 `<img>`/`<object>` 引用的 SVG、嵌入式文档可不列入。
- `linear="no"`：辅助内容（注释集、彩插、版权补页），不进线性翻页流，仅通过链接到达。【需实测】部分阅读器忽略 `linear`，仍按顺序显示，所以不要依赖它隐藏内容；真正需要隐藏时应从 spine 移出并用 `bindings`/不链接（通常不必要）。
- 导航文档 `nav.xhtml`：**可以不在 spine**；但若目录/landmarks 或正文有链接指向它，则必须在 spine。常见做法：nav 作为可见目录页放在版权页之后（`linear="yes"`），或放在末尾 `linear="no"`。
- `page-progression-direction`：`ltr`（横排左开本，默认）/`rtl`（竖排右开本，日式/竖排中文）/`default`。影响翻页方向，须与 CSS `writing-mode`、封面位置一致（竖排排版细节见 `03_CSS与中文排版规范.md`）。横排简体中文书应为 `ltr` 或省略。
- `itemref@properties`：`page-spread-left`、`page-spread-right`、`rendition:*`（见 §5.5），主要用于固定布局。
- `spine@toc`：EPUB 2 NCX 的 id；EPUB 3 里可选，见 §8。

### 5.5 rendition（版式）

默认即 **reflowable（可重排）**，这是本规范与优化软件的主战场，**无需声明任何 rendition 属性**。

```xml
<!-- 包级 -->
<meta property="rendition:layout">reflowable</meta>      <!-- 或 pre-paginated -->
<meta property="rendition:orientation">auto</meta>       <!-- landscape | portrait | auto -->
<meta property="rendition:spread">auto</meta>            <!-- none | landscape | portrait | both | auto -->
<meta property="rendition:flow">auto</meta>              <!-- paginated | scrolled-continuous | scrolled-doc | auto -->
<!-- 单个 spine 项覆盖 -->
<itemref idref="ch5" properties="rendition:layout-pre-paginated rendition:spread-none"/>
```

固定布局（fixed-layout，漫画/绘本/杂志）要点，**本工具默认只识别并保留，不重排**：

1. 包级 `rendition:layout` = `pre-paginated`；
2. **每个** XHTML 的 `<head>` 内有 `<meta name="viewport" content="width=1200, height=1600"/>`（SVG 则用 `viewBox`），数值为整数像素，且与图片原始宽高对应；
3. 内容常用绝对定位与整页图片，**不适用 `04_排版样式模板库.md` 里的可重排样式**；
4. 判定：存在 `rendition:layout=pre-paginated` 或 spine 项含 `rendition:layout-pre-paginated` → 标记为 FXL，跳过重排类修复，仅做容器/元数据/校验层面的修复。

## 6. 导航文档（nav.xhtml）

### 6.1 要求

- manifest 中 `properties="nav"` 的 XHTML 文档，**EPUB 3 必有且仅一个**。
- 必须包含**一个** `<nav epub:type="toc">`；可选**至多一个** `epub:type="landmarks"`、**至多一个** `epub:type="page-list"`；还可有自定义 nav（`lot`、`loi`、`lov` 等，值取自 epub:type 词表）。
- 结构固定：`nav` > （可选 `h1`–`h6` 标题）> **有序列表 `ol`**；`li` 内是 `a`（可链接）或 `span`（纯标题）后接可选嵌套 `ol`；**`span` 型 li 必须含嵌套 `ol`，且其下至少有一个 `a`**。
- `a` 内容须为**非空文本**（可含 `img` 并有 `alt`），不得空白；`a@href` 必须指向已在 spine 中的内容文档（可带 `#id`，id 必须存在，`RSC-012`）。
- 目录条目**应按阅读顺序**排列，且与 spine 次序同向（EpubCheck `NAV-011` 警告）。
- 文件头同普通 XHTML：`xmlns` + `xmlns:epub`，有 `<title>`。

### 6.2 目录（toc）

```xml
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml" xmlns:epub="http://www.idpf.org/2007/ops"
      xml:lang="zh-Hans" lang="zh-Hans">
<head><meta charset="utf-8"/><title>目录</title></head>
<body>
  <nav epub:type="toc" id="toc" role="doc-toc">
    <h1>目录</h1>
    <ol>
      <li><a href="text/preface.xhtml">序言</a></li>
      <li><a href="text/part-1.xhtml">第一部分 起点</a>
        <ol>
          <li><a href="text/chapter-001.xhtml">第一章 开端</a></li>
          <li><a href="text/chapter-002.xhtml#s2">第二章 之二</a></li>
        </ol>
      </li>
      <li><a href="text/appendix-a.xhtml">附录一</a></li>
    </ol>
  </nav>
</body>
</html>
```

层级与内容规则（可判定）：

| 规则 | 判据 | 处理 |
|---|---|---|
| 条目文字 = 目标位置的标题文字（去序号空白差异后） | 比对 `<a>` 文本与目标 `h1–h6` 文本 | 不一致 → 警告；以正文标题为准重建 |
| 每个 spine 内容文档至少有一个目录入口（可嵌套于父级） | 差集 | 缺 → 补；封面/版权页/nav 本身可例外 |
| 同级、同文档的多条目指向不同锚点 | href 去片段后重复需有 `#id` 且 id 存在 | 缺 id → 自动在目标标题上补 |
| 层级深度 ≤ 3 | 嵌套 ol 深度 | 书籍目录建议 ≤3 层（出版惯例）；规范无限制，超出只警告 |
| 层级对应标题层级：`h1`↔一级…，不跳级 | 目标标题 `hN` 的 N 与条目深度之差一致 | 不一致 → 提示重建标题或目录 |
| 条目文本：无尾部页码、无点线（`....12`）、无前导空白 | 正则 `\.{3,}\s*\d+$`、`^\s` | 清理 |
| 条目文本：不含生僻 SMP 字符却无字体 | `[\u{20000}-\u{2FFFF}]` | 提示字体（见 `05_图片与字体资源.md`） |
| 不含装饰符 `★◆※` 与竖排标点 `︵﹁` | 正则 | 清理 |
| 可见目录页与 nav 同源 | 若另有 HTML 目录页（旧书常有手写目录页） | 删之或以 nav 取代；手写目录页的链接常指向错误锚点 |

**自动生成目录的依据**：以正文 `h1–h6`（及 `section` 嵌套）为唯一源；没有标题元素的伪标题（`<p><b>第一章</b></p>`）不会进目录，应先按 `02_内容文档与语义结构.md` §9 重建标题。

### 6.3 landmarks

```xml
<nav epub:type="landmarks" hidden="">
  <h2>导览</h2>
  <ol>
    <li><a epub:type="cover" href="text/cover.xhtml">封面</a></li>
    <li><a epub:type="titlepage" href="text/titlepage.xhtml">书名页</a></li>
    <li><a epub:type="toc" href="nav.xhtml">目录</a></li>
    <li><a epub:type="bodymatter" href="text/chapter-001.xhtml">正文</a></li>
  </ol>
</nav>
```

- 条目是**文档级地标**，不是目录；每个 `a` 必有 `epub:type`；值取自结构语义词表，常用：`cover`、`titlepage`、`copyright-page`、`toc`、`loi`、`lot`、`foreword`、`preface`、`bodymatter`、`bibliography`、`index`、`glossary`、`acknowledgments`。
- 同一 `epub:type` 不应指向两个不同的位置（`NAV-` 系列警告）；`bodymatter` 应有且指向正文起点（阅读器"跳到正文"）。
- 取代 EPUB 2 的 `<guide>`；两者并存时必须一致（见 §8.3）。
- 自动生成：由文件角色（`epub:type`/文件名/标题关键字）推断；找不到封面/正文起点时**不要乱填**，留空并报告。

### 6.4 page-list

```xml
<nav epub:type="page-list" hidden="">
  <ol>
    <li><a href="text/chapter-001.xhtml#p1">1</a></li>
    <li><a href="text/chapter-001.xhtml#p2">2</a></li>
  </ol>
</nav>
```

- 与正文中的分页标记一一对应：`<span epub:type="pagebreak" role="doc-pagebreak" id="p1" aria-label="1"/>`（详见 `02_内容文档与语义结构.md` §8）。
- 仅用于**保留纸书页码**（教材、引用、学术书）；没有纸书页码的书**不要生成 page-list**，更不能用阅读器的"虚拟页"凑数。

### 6.5 `hidden`

- `hidden` 是 HTML 全局属性，写成 `hidden=""`（XHTML 中合法的布尔属性写法）。
- 作用：**该 nav 在文档正文流中不显示**，但阅读系统仍用它构建自己的目录/地标 UI，辅助技术可见性不受影响。
- 惯例：`landmarks`、`page-list` 一律 `hidden=""`；**`toc` 若同时充当可见目录页则不隐藏**；若书中不另设目录页且 nav 不在 spine，则 `toc` 隐不隐藏都不影响阅读器目录。
- 可对 `ol`/`li` 局部使用 `hidden`，让某些层级不在目录页显示但仍存在于阅读系统目录【需实测】：不同阅读器是否尊重未知。保守做法：不用 hidden 删减层级，直接让目录页显示全部层级。
- 隐藏 nav 的 CSS 手段（`display:none`）不可替代 `hidden` 属性；可见 nav 的样式见 `03_CSS与中文排版规范.md`。

## 7. 无障碍元数据【补】

依据 EPUB Accessibility 1.1（2023）与 Schema.org 词汇；`schema` 前缀保留，无需声明。

```xml
<meta property="schema:accessMode">textual</meta>
<meta property="schema:accessMode">visual</meta>
<meta property="schema:accessModeSufficient">textual</meta>
<meta property="schema:accessibilityFeature">tableOfContents</meta>
<meta property="schema:accessibilityFeature">readingOrder</meta>
<meta property="schema:accessibilityFeature">alternativeText</meta>
<meta property="schema:accessibilityHazard">none</meta>
<meta property="schema:accessibilitySummary">本出版物为纯文本排版，所有图片均提供替代文本；无闪烁、无声音内容。</meta>
<!-- 仅当确有评估依据时： -->
<link rel="dcterms:conformsTo" href="https://www.w3.org/TR/epub-a11y-11#wcag-2.1-aa"/>
<meta property="a11y:certifiedBy">某机构</meta>
```

| 元数据 | 要求 | 值/说明 |
|---|---|---|
| `schema:accessMode` | 必需，≥1 | `textual`、`visual`、`auditory`、`tactile`：**内容**使用的感知方式（含图片就加 `visual`） |
| `schema:accessModeSufficient` | 必需，≥1 | 逗号分隔的"足以理解全书"的方式组合，如 `textual` 或 `textual,visual` |
| `schema:accessibilityFeature` | 强烈建议 | `tableOfContents`（有 toc nav）、`readingOrder`（spine 即合理顺序）、`alternativeText`、`longDescription`、`structuralNavigation`（有规范标题层级）、`pageBreakMarkers`/`printPageNumbers`（有 pagebreak）、`pageNavigation`（有 page-list）、`displayTransformability`（可重排，字体字号可调）、`MathML`、`index`、`ttsMarkup`、`none` 等 |
| `schema:accessibilityHazard` | 必需，≥1 | `none`、`unknown`、`flashing`、`noFlashingHazard`、`motionSimulation`、`noMotionSimulationHazard`、`sound`、`noSoundHazard`。不知道填 `unknown`，**不要乱填 `none`** |
| `schema:accessibilitySummary` | 必需 | 面向读者的自然语言说明，**须人写**，不自动生成 |
| `dcterms:conformsTo` / `a11y:certified*` | 可选 | 声明符合性/认证；**未经评估不得声明** |

可自动推断并写入的特征（有凭证才写）：

- 有 `nav[epub:type=toc]` → `tableOfContents`；
- spine 顺序等于目录顺序且无 `linear=no` 孤岛 → `readingOrder`；
- **每个** `<img>` 都有非空 `alt`（装饰图 `alt=""` 且 `role="presentation"` 除外） → `alternativeText`；
- 存在 `pagebreak` 且有 page-list → `pageBreakMarkers`、`printPageNumbers`、`pageNavigation`；
- 标题层级连续、`lang` 完整 → `structuralNavigation`；
- reflowable 且无固定像素字号 → `displayTransformability`；
- 含 `<math>` → `MathML`；含 `<script>` → 另需检查替代文本与键盘可用，不自动声明。

不能自动判断的：`accessModeSufficient`（须知道图片是否承载信息）、`accessibilitySummary`、`conformsTo`、`longDescription`。工具的做法是**列出待填项交给用户**，不写占位假值。

## 8. NCX 与 guide（EPUB 2 兼容，可选）

### 8.1 取舍

EPUB 3 以 nav.xhtml 为准。**NCX 与 `<guide>` 只是为老阅读器的"可选向后兼容"**：

- 输出策略：默认**保留已有 NCX 并保持与 nav 同源**；原书没有 NCX 时，是否新增作为选项（打开会让 EPUB 2 系阅读器可用，代价是两份目录需同步）。
- 一旦保留，就必须与 nav **条目、层级、顺序、文字一致**；不一致比没有更糟。
- 删除 NCX 时：同时删除 manifest 项与 `spine@toc`。

### 8.2 NCX 最小模板

```xml
<?xml version="1.0" encoding="UTF-8"?>
<ncx xmlns="http://www.daisy.org/z3986/2005/ncx/" version="2005-1" xml:lang="zh-Hans">
  <head>
    <meta name="dtb:uid" content="urn:uuid:3f8b8c1e-5d0a-4c53-9a3e-0b6f6e1d2a77"/>
    <meta name="dtb:depth" content="2"/>
    <meta name="dtb:totalPageCount" content="0"/>
    <meta name="dtb:maxPageNumber" content="0"/>
  </head>
  <docTitle><text>书名</text></docTitle>
  <navMap>
    <navPoint id="np1" playOrder="1">
      <navLabel><text>第一章 开端</text></navLabel>
      <content src="text/chapter-001.xhtml"/>
      <navPoint id="np2" playOrder="2">
        <navLabel><text>1.1 小节</text></navLabel>
        <content src="text/chapter-001.xhtml#s1"/>
      </navPoint>
    </navPoint>
  </navMap>
</ncx>
```

一致性判据（可自动检）：

- `dtb:uid` = OPF 唯一 identifier 的值（逐字符）；
- `dtb:depth` = 实际最大嵌套深度；
- `docTitle` = `dc:title`；
- `playOrder` 从 1 递增，与文档顺序一致（可含重复 src 时每条仍独立递增）；`navPoint@id` 唯一；
- `content@src` 指向存在的文件与锚点（`RSC-012`）；
- manifest 登记 `application/x-dtbncx+xml`，且 `<spine toc="该 id">`（`toc` 为空串、指向不存在 id 是原书实例中的真实故障）；
- NCX **不得**带 `properties="nav"`。

### 8.3 guide

```xml
<guide>
  <reference type="cover" title="封面" href="text/cover.xhtml"/>
  <reference type="toc" title="目录" href="nav.xhtml"/>
  <reference type="text" title="正文" href="text/chapter-001.xhtml"/>
</guide>
```

EPUB 3 里已被 landmarks 取代；EpubCheck 对其给警告（不是错误）。要保留旧阅读器兼容就与 landmarks 对应（`cover`↔`cover`，`toc`↔`toc`，`text`↔`bodymatter`），否则可删。【补】不要为了"兼容"新生成 guide，除非用户明确要求。

## 9. 内容文档登记与资源引用对账

下列对账是容器层质检的核心（全是确定性检查）：

| 对账 | 方法 |
|---|---|
| zip ↔ manifest | zip 条目集（去掉 mimetype、META-INF、OPF）与 manifest href 集合应相等 |
| manifest ↔ 引用 | 构建引用图：OPF → nav/NCX/spine → XHTML(`a/img/link/script/source/audio/video/object/image/use`) → CSS(`url()`、`@import`、`@font-face src`) → SVG(`xlink:href`、`href`) → 字体；manifest 中不被任何文件引用、也不在 spine/nav 的项 = 孤儿 |
| spine ↔ nav | 每个 spine 内容文档应被目录覆盖（封面/版权/nav 自身除外） |
| 链接 ↔ id | 所有 `href="x.xhtml#id"`、nav/NCX 的片段均能在目标文件找到 `id`（`RSC-012`） |
| 资源 ↔ media-type | 魔数/扩展名/登记三者一致 |
| 引用 ↔ 大小写 | 引用路径与 zip 条目**大小写完全一致**（Windows 上能开的书到 Android/Linux 上图片全丢，是最常见的"换设备就坏"原因）【补】 |

孤儿处理：**默认不删**，只报告（可能被脚本、`meta`、`link` 引用）；用户确认后删除，尤其封面备用图、混淆字体来源文件要保留。

## 10. 常见结构错误与修法

| 现象 | EpubCheck | 原因 | 修法（自动级别） |
|---|---|---|---|
| mimetype 非首个/被压缩/有 extra | `PKG-005/006/007` | 用通用 zip 工具打包 | 重新打包，mimetype 先写、Store（全自动） |
| container.xml 的 `full-path` 找不到文件 | `RSC-` / `PKG-` | 改名未同步 | 查找实际 `.opf`（`application/oebps-package+xml`），修正（全自动） |
| `unique-identifier` 指向不存在的 id | `OPF-030` | 编辑元数据时删了 identifier | 新建 `urn:uuid:` identifier 并对齐 NCX `dtb:uid`；若有混淆字体须先解混淆（全自动，需提示） |
| 缺 `dcterms:modified`/格式不合规（含毫秒、无 Z） | `RSC-005` | 老 EPUB 2 转换 | 写当前 UTC `…Z`（全自动） |
| `dc:language` 缺失/非法（`zh_CN`、`chinese`） | `RSC-005` | 手填 | 依正文统计写 `zh-Hans`/`zh-Hant`；下划线改连字符（全自动） |
| manifest 同一 id 两次；NCX 项带 `properties="nav"`且 type 为 xhtml；href 为本机绝对路径（`C%3A/Users/...`） | `OPF-` / `RSC-001` | 工具合并/崩溃遗留 | 保留 href 指向真实文件的一项，纠正 type 为 `application/x-dtbncx+xml`，去 `properties`，`spine@toc` 指向它（全自动） |
| 图片 media-type 与真实格式不符（gif 文件登记 png、png 数据命名 .jpg） | `OPF-029`、`PKG-022` | 改后缀代替转码 | 魔数嗅探→改 media-type→统一扩展名并改引用（全自动） |
| manifest 项文件不存在（常见：字体） | `RSC-007`、`RSC-001` | 资源被删 | 列出缺失；询问删除条目并清理引用，或补文件（半自动） |
| zip 内有文件未登记 | `OPF-003` | 手动加文件 | 若被引用则补登记并按魔数推 media-type；否则列为垃圾待删（全自动/半自动） |
| 链接指向不在 spine 的文档 | `RSC-011` | 拆分/合并后漏 spine | 补入 spine（线性次序按目录次序）或改链接（半自动） |
| 目录/NCX 的片段 id 不存在 | `RSC-012` | 拆分文件后 id 丢失/被改名 | 全书重建 nav/NCX；或在目标标题补 id（全自动） |
| 内容文档用了 svg/mathml/script 但未声明 properties | `OPF-014` | 手工遗漏 | 解析内容推断并补（全自动） |
| 声明了 `scripted` 而无脚本 | `OPF-015` | 遗留 | 去除（全自动） |
| 多个 `cover-image` / `cover-image` 指向非图片 | `OPF-012` | 复制粘贴 | 保留与封面页引用一致的那个（半自动） |
| 超链接目标 `.html` 而 manifest 为 `.xhtml` | `RSC-007` | 改后缀 | 统一改写链接（全自动） |
| spine 为空/全部 `linear=no` | `OPF-033` | 误操作 | 至少一项设为 linear（全自动） |
| 用 `text/html` 登记内容文档 | `OPF-035` | EPUB 2 习惯 | 改为 `application/xhtml+xml`（全自动） |
| 私有属性/扩展（厂商前缀属性、`duokan-*` 等） | `OPF-027`/`RSC-005` | 厂商私有 | 与本规范"厂商无关"目标冲突，处理见下 |
| 空的 `<spine toc="">` | `OPF-` schema | NCX 丢失 | 无 NCX 则去掉该属性；有则指向其 id（全自动） |
| `<rb>`、`<font>`、`<center>`、`<u>` 属性等 HTML5 不允许元素 | `RSC-005` | 老内容 | 见 `02_内容文档与语义结构.md` §9 |

**私有扩展处理原则**【补】：不为特定阅读器生成私有扩展；输入中已有的私有属性/元素（含命名空间扩展）默认**保留**并在报告中标注"非标准"（warning），提供一键清除（suggest）；仅当其违反 XML 良构（未声明命名空间前缀）时直接修。注意：保留时 epubcheck 会报 `OPF-027`/`RSC-005` 错误（实测见 `07_质检清单.md` §1.4），所以要达到「epubcheck 零 error」须由用户确认清除。

## 11. 对优化软件的含义

可自动检测：

- mimetype 位置/压缩/extra/内容；zip 条目重名、大小写冲突、垃圾文件、非法路径字符、`..`、`\`。
- container.xml 存在性与 rootfile 指向；多 rootfile 识别。
- OPF 必需元数据四项齐全且格式合法（`dcterms:modified` 正则 `^\d{4}-\d\d-\d\dT\d\d:\d\d:\d\dZ$`）；`unique-identifier` 对应；`dc:language` BCP 47 合法性。
- manifest 对账：id 唯一、href 存在、孤儿、media-type 魔数、`properties`（svg/mathml/scripted/remote-resources）由 XHTML 内容推断得出。
- spine：idref 有效、无重复、所有链接目标文档在 spine、至少一个线性项。
- nav：唯一、含 toc、层级合法、href/id 可达、顺序与 spine 同向、文字与标题一致；NCX 与 nav 同步性；landmarks 的 cover/bodymatter 是否缺失。
- FXL 识别（`rendition:layout`），识别后切换为"只保守修复"模式。
- 加密：`encryption.xml` 区分字体混淆与真 DRM。

可自动修复（全自动、无损）：

- 重新打包（mimetype 首位 Store、其余分类压缩、去垃圾）；重写 container.xml。
- 补/改 `dcterms:modified`、`dc:language`、缺失 identifier；对齐 NCX `dtb:uid` / 标题。
- 按魔数修正 media-type 与扩展名并同步引用；补登记孤儿；删除重复/绝对路径 manifest 项；补全 `properties`；修 `spine@toc`。
- 从标题树重建 nav（含 landmarks，条件满足时含 page-list）并同步 NCX；重排 `playOrder`。
- media-type 迁移（`application/x-font-ttf` → `font/ttf` 等；`text/javascript`）。

需用户确认：

- 重命名文件为规范命名（涉及大量引用改写）；字体解混淆后明文嵌入；删除孤儿资源；是否新增/删除 NCX、guide；`dc:creator`/`dc:contributor` 角色归类；系列元数据写入（含 calibre 兼容）；目录层级压平；spine 重排。

只提示不改：

- 远程资源、非核心媒体类型缺回退、固定布局、含脚本的书、真 DRM、无障碍摘要与符合性声明（须人工评估）、私有扩展。
