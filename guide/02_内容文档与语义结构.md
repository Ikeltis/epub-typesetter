# 02 内容文档与语义结构

> 基准：EPUB 3.3 Content Documents（XHTML 取 HTML Living Standard 的 XML 序列化）、EPUB Structural Semantics Vocabulary、DPUB-ARIA 1.1。
> 标记：【补】= 原书未涉及；【更正】= 订正原书/笔记的错误或过时说法；【需实测】= 阅读器行为未验证；（SE x.y）= 参照 Standard Ebooks《Manual of Style》的条目，对照结论见 `08_参照StandardEbooks.md`。
> 包与导航见 `01_容器包文档与导航.md`；样式写法见 `03_CSS与中文排版规范.md`、`04_排版样式模板库.md`；图片见 `05_图片与字体资源.md`；文本字符规范化见 `06_中文文本规范化.md`；检查项汇总见 `07_质检清单.md`。

核心立场：**内容文档只表达"这是什么"（结构与语义），"长什么样"全部交给 CSS**。凡是用空格、空段、`<br>`、字号标签、行内样式去"摆"出视觉效果的写法，都是需要被替换的伪排版（§9）。

## 1. XHTML5 良构要求

EPUB 内容文档必须是**合法的 XML**，同时满足 HTML 的元素/属性内容模型。HTML 解析器宽容的写法，在 XML 解析器下会整页失败（阅读器常见表现：该章空白或报"无法打开"）。

### 1.1 文档骨架

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE html>
<html xmlns="http://www.w3.org/1999/xhtml" xmlns:epub="http://www.idpf.org/2007/ops"
      xml:lang="zh-Hans" lang="zh-Hans">
<head>
  <meta charset="utf-8"/>
  <title>第一章　开端</title>
  <link rel="stylesheet" type="text/css" href="../styles/book.css"/>
</head>
<body>
  <section epub:type="chapter" role="doc-chapter" aria-labelledby="h-ch1" id="ch1">
    <h2 class="chapter-title" id="h-ch1">第一章　开端</h2>
    <p>……</p>
  </section>
</body>
</html>
```

| 项 | 规则 |
|---|---|
| XML 声明 | 可省；若写，编码必须 `UTF-8`，文件实际也必须是 UTF-8（无 BOM 更稳；GBK/GB18030 文件直接是错误） |
| DOCTYPE | 只能是 `<!DOCTYPE html>`；**不得**使用 XHTML 1.1/EPUB 2 的长 DOCTYPE（EpubCheck `HTM-004`），不得有内部子集 |
| `xmlns` | `<html>` 必须声明 `xmlns="http://www.w3.org/1999/xhtml"`；用到 `epub:type` 必须声明 `xmlns:epub="http://www.idpf.org/2007/ops"` |
| `epub:prefix` | `epub:type` 里用了非保留前缀（如 `z3998:`）时必须声明，**只能写在 `<html>` 根元素上**；写在 `<body>` 上 EpubCheck 报 `RSC-005` + `OPF-028`。用了 `z3998:` 值却没声明，EpubCheck 报 `OPF-028`（error），由规则引擎自动补声明（见 §6.1） |
| `<title>` | 必需且**非空**。取值顺序：①该文件在 nav 中的条目文字（纯文本，去标签，换行折叠为空格）；②无条目者取首个标题的纯文本；③仍无则用角色名（封面、版权页……）。只描述本文件，不含书名；不得全书同名或为文件名（SE 5.4） |
| `lang` / `xml:lang` | 根元素同时写且值相同（§8.2） |
| `<head>` | 至少 `title`；样式用外链 `<link>`；`<meta charset>` 与 XML 声明并存无害 |
| 脚本 | 默认不含；含则 manifest 须 `scripted`（见 `01` §5.2） |

### 1.2 XML 层规则（可判定）

1. **标签小写、成对闭合**；空元素自闭合：`<br/> <hr/> <img .../> <meta .../> <link .../> <source .../> <col/> <wbr/>`。
2. **属性必须带引号**，不得有无值属性写法 `<td nowrap>`；布尔属性写 `hidden=""` 或 `hidden="hidden"`。
3. **只有 5 个预定义实体**可用名称：`&lt; &gt; &amp; &quot; &apos;`；其余一律用**数字字符引用或直接写 Unicode 字符**。【更正】原书/笔记说"`&nbsp;` 需要 DOCTYPE 定义"——在 `<!DOCTYPE html>`（无 DTD）下，`&nbsp; &copy; &mdash; &hellip;` 全部是**未定义实体，XML 良构错误**（XML 解析致命错误，EpubCheck `RSC-016`），不是"需要补 DOCTYPE"。修法：`&nbsp;`→`&#160;`（或保持 U+00A0 字符），`&mdash;`→`—`，等。
4. 文本中的 `&` 必须是 `&amp;`；URL 里的 `&` 同样（`?a=1&amp;b=2`）；`<` 必须是 `&lt;`；`>` 建议 `&gt;`。
5. 注释 `<!-- -->` 内不得含 `--`；不得出现 `<![CDATA[` 以外的 HTML 式特殊语法。
6. 元素只能出现在其内容模型允许的位置：`<p>` 不得含块级元素（`div/ul/table/p`）；`<ul>/<ol>` 的子元素只能是 `<li>`；`<table>` 直属子只能是 `caption/colgroup/thead/tbody/tfoot/tr`；`<a>` 不得嵌套 `<a>`；`<li>` 外不得有游离文本。（来源常见：HTML 容错解析器把 `<p><div>` 自动改写，XML 序列化后不再合法。）
7. **`id` 全文件唯一**，且为合法 XML NCName（以字母或 `_` 开头，不含空格、冒号；不以数字开头）；重复 id → `RSC-005`。
8. 不得使用 HTML5 已废弃/不允许的元素与属性（EpubCheck 报 `RSC-005`）：`font`、`center`、`big`、`strike`、`tt`、`acronym`、`frame/frameset`、`rb`/`rtc`（见 §5.4）、`<a name>`、`align/valign/bgcolor/border/cellpadding/cellspacing/width（表格上）/hspace/vspace/nowrap/clear` 等表现属性、`<ul type>`。
   【更正】原书称"`ol` 的 `start`、`type` 已废弃"：在 HTML Living Standard 中 `<ol start type reversed>` 均**仍然合法**（`start` 是整数，即使 `type="a"` 也要写数字），真正废弃的是 `<ul type>`、`<ol compact>` 等。是否用 CSS `list-style-type` 取代 `type` 是风格选择，不是合规问题。
9. `<img>` 必有 `alt`（装饰图 `alt=""`）；`<a>` 不得为空且无可访问名称；`<table>` 无 `<th>` 且非布局表须提示。
10. 属性值内的换行/多空格会被规范化；`style`、`class` 值首尾空白无害，但 `class=""` 空值可删。
11. 命名空间前缀只可用已声明者：`epub:`、`xlink:`（SVG 内）、`m:`（MathML，一般直接 `<math xmlns="http://www.w3.org/1998/Math/MathML">`）。

### 1.3 编码与字符

- 文件 UTF-8；控制字符（U+0000–0008、000B、000C、000E–001F）在 XML 1.0 中**非法**，PDF/OCR 来源常含 U+000C（换页）、U+0008，需删除。
- 孤立代理项、U+FFFE/U+FFFF 非法。
- 不要写出 BOM 以外的零宽/不可见字符（U+200B、U+FEFF 在正文中），清理规则见 `06_中文文本规范化.md`。

### 1.4 从"坏 HTML"到合法 XHTML 的修复流程【补】

输入常是 HTML 式写法（未闭合、实体、大小写）。**不能直接 XML 解析**；管线：

1. 以 HTML5 容错解析器（html5lib/lxml.html/parse5 等价物）读入 DOM；
2. 在 DOM 层做修复（实体、非法元素、嵌套）；
3. 用**严格 XML 序列化器**输出（`<br/>`、实体编码、命名空间、属性引号）；
4. 序列化后**再用 XML 解析器回读一遍**作为自检；
5. 序列化时保持原有 `id`、`class`、`epub:*`、`aria-*`、`data-*`、`role`；未识别属性（私有扩展）不丢。

## 2. 文档组织：拆分与命名

### 2.1 一章一文件

- **规则**：每个一级结构单元（部/卷、章、前言、后记、附录各篇）**独立一个 XHTML 文件**。理由：阅读系统一般以 spine 项为分页/章节切换单位，章首另起一页符合出版习惯；目录、书签、进度与它对齐。
- **一个文件 = 一个 `<section>` 容器 + 一个最高级标题**（§4）。
- 章内小节**不拆文件**（用 `section` 嵌套 + 锚点），除非过大。
- 前置/后置辅文各自成文件：封面、书名页、版权页、献词、目录页（如有）、序、后记、附录、注释集、索引、版本记录。
- 卷/部：若有"部"标题页（只含部标题），自成文件，`epub:type="part"`，其后接各章。

### 2.2 过大文件的拆分

- EPUB 规范**不限制**单文件大小。但超大文件会拖慢分页、占内存、使章内进度和书签粗糙。
- 经验阈值【补，需实测】：纯文本章节 **> 约 300 KB（UTF-8 源码）或 > 约 10 万汉字** 时建议拆分；书中引用的"120 KB 必拆"来自特定平台的内部规范，不是 EPUB 规则，可作为**可配置阈值**，默认 256 KB。EpubCheck 对过大文档只给提示，不报错。
- 拆分点优先级：**章（h1/h2）边界 > 节标题（h3）边界 > 段落边界**；**不得劈开** `<p>`、`<table>`、`<figure>`、列表、`<blockquote>`、`<pre>`、诗歌块。
- 拆分后必须：
  1. 新文件各自有完整骨架与 `<title>`，复制所需 CSS `<link>`；
  2. 被切走的小节顶层 `section` 继续存在，嵌套层不丢；
  3. **全书重写链接**：原文件内的 `href="#x"` 若目标被移走，改成 `newfile.xhtml#x`；他处指向 `oldfile.xhtml#x` 的链接、nav/NCX、脚注回链都要改（`RSC-012` 是漏改的典型报错）；
  4. 新文件登记 manifest，插入 spine 正确位置，更新 nav；
  5. 命名：`chapter-003-a.xhtml`、`chapter-003-b.xhtml`（沿用章序号 + 分片后缀）；第二片之后的文件**没有章标题**，只有续文（可无 h1，`<title>` 用章标题）。
  6. **`data-parent`**：被切出成独立文件的小节，其根 `section` 保留原 `id` 不变，并写 `data-parent="<原父 section 的 id>"`，记录它原本嵌在哪里，日后合并时可按它还原嵌套（SE 的"可重组性"）。**只在我们自己拆分时写**；原书已有的文件不补、不改。`data-*` 是标准 HTML 属性，不属于私有词汇。合并回去后删去该属性。
- 反向：**过碎**（一章被切成数十个 2–3 KB 的文件，常见于 PDF/OCR 来源每页一文件）应合并：把连续文件合并到"章"为单位，合并后 id 冲突需重命名并同步链接。

### 2.3 文件命名

沿用 `01` §2.3：ASCII、小写、序号补零。按角色命名，利于自动识别与人工检查：

| 角色 | 建议文件名 | 角色 | 建议文件名 |
|---|---|---|---|
| 封面 | `cover.xhtml` | 前言/序 | `foreword.xhtml` / `preface.xhtml` |
| 书名页 | `titlepage.xhtml` | 引言 | `introduction.xhtml` |
| 版权页 | `copyright-page.xhtml` | 部/卷 | `part-01.xhtml` |
| 献词 | `dedication.xhtml` | 章 | `chapter-001.xhtml` |
| 目录页 | `toc.xhtml`（或直接 nav） | 后记/跋 | `afterword.xhtml` |
| 半书名页 | `halftitlepage.xhtml` | 序章/楔子 | `prologue.xhtml` |
| 出版者信息页 | `imprint.xhtml` | 尾声/结语 | `epilogue.xhtml` / `conclusion.xhtml` |
| 附录 | `appendix-a.xhtml` | 注释集 | `endnotes.xhtml` |
| 参考文献 | `bibliography.xhtml` | 索引 | `index.xhtml` |
| 版本记录 | `colophon.xhtml` | 致谢 | `acknowledgments.xhtml` |

命名应与 `epub:type`（§6）一致：**由"文件名/标题关键词 → epub:type"可相互推断**。完整的命名规则（分部时章如何命名、补零位数、同类辅文加 `-N`、插图命名）以 `01` §2.3 的命名表为准；辅文按**类型**命名，不按标题（SE 2.2）。

## 3. 图书内容顺序

spine 顺序即阅读顺序。**标准顺序**（出版惯例 + EPUB 结构语义的三分法 frontmatter / bodymatter / backmatter）：

| 序 | 部分 | 分区 | epub:type | DPUB role | 进目录 | 备注 |
|---|---|---|---|---|---|---|
| 1 | 封面 | front | `cover` | `doc-cover` | 否（landmarks 有） | 全书首个 spine 项；整图 |
| 2 | 半书名页（可选，仅识别） | front | `halftitlepage` | — | 否 | 只有书名的简页；原书有则识别并标注，不生成；**不得作为 `bodymatter` 起点**（SE 3.8） |
| 3 | 书名页（扉页） | front | `titlepage` | — | 否 | 书名、作者、译者、出版者 |
| 4 | 版权页 | front | `copyright-page` | — | 否/可 | 版权、ISBN、CIP、出版信息；中文书常放书名页之后。出版者信息单独成页时标 `imprint`；与版权页同页则只标 `copyright-page`；不生成、不拆分（SE 3.3） |
| 5 | 献词 | front | `dedication` | `doc-dedication` | 否 | |
| 6 | 题词 | front | `epigraph` | `doc-epigraph` | 否 | 也可放在章首 |
| 7 | 目录页 | front | nav 内 `toc` | `doc-toc` | — | 可见目录页可选，nav 必有。插图目录、表格目录页标 `loi`、`lot`，front，位置随原书，不生成（SE 3.14） |
| 8 | 序/前言/导言 | front | `foreword`/`preface`/`introduction` | `doc-foreword`/`doc-preface`/`doc-introduction` | **是** | 推荐序、译者序、再版序各一文件 |
| 9 | 序章/楔子 | body | `prologue` | `doc-prologue` | **是** | 默认归正文。原书把它放在正文标题页之前（框架叙事）时，保持原位，`body` 上可写 `frontmatter` 并保留 `prologue`；位置由用户确认，不自动搬动（SE 3.11） |
| 10 | 正文：部→章→节 | body | `part` `chapter` | `doc-part` `doc-chapter` | **是** | |
| 11 | 尾声/终章/结语 | body | `epilogue`/`conclusion` | `doc-epilogue`/`doc-conclusion` | **是** | 属正文，结构与章相近（SE 3.12） |
| 12 | 后记/跋 | back | `afterword` | `doc-afterword` | **是** | 属后置部分，在书的叙述之外；中文"后记""跋"默认标 `afterword`，判断不了时交用户确认（SE 3.12） |
| 13 | 附录 | back | `appendix` | `doc-appendix` | **是** | 分篇 A、B、C |
| 14 | 注释集（尾注） | back | `endnotes` | `doc-endnotes` | 是/否 | 见 §7 |
| 15 | 术语表/参考文献/索引 | back | `glossary`/`bibliography`/`index` | `doc-glossary`/`doc-bibliography`/`doc-index` | 是 | |
| 16 | 致谢 | back/front | `acknowledgments` | `doc-acknowledgments` | 可 | 位置随原书 |
| 17 | 作者/译者简介、版本记录 | back | `colophon` 等 | `doc-colophon` | 可 | 出版社广告页建议用户确认后删除 |

- 中文出版常见次序：**封面→书名页→版权页→(献词)→目录→序言→正文→后记→附录→参考文献→(索引)→版本记录**。相对于西式，版权页常靠前、"出版说明/内容提要/作者简介"放前部或后部均有，保持原书。
- **不要重排**用户书的次序，除非明确错位（版权页出现在最后一章之后、目录页在正文之后等）；重排需用户确认。
- 半书名页属 front，`bodymatter` 起点是第一个正文文件，跳过半书名页与序言类。
- 分区标记：在每个文件的 `<body>` 上加 `epub:type="frontmatter"`/`"bodymatter"`/`"backmatter"`（可与 `cover` 等并列，用空格分隔）。**正文起点**对应 landmarks 的 `bodymatter`。
- 内容简介、"作者简介"等营销页：若有价值，将文本提取进 `dc:description`（`01` §4.2），页面可保留前部；导出为"版权页以外的无语义页"时不要标成 `chapter`。
- 空白页、纯装饰页（只有一个花饰、整页图）：除非为保持页面对称，建议删除，并**不得进目录**。

## 4. section 与标题层级

### 4.1 规则

1. **每个文件一个根 `<section>`**（承载 `epub:type` 和 `id`），其下标题用 `h1–h6`；下级小节嵌套 `<section>`。
2. **标题元素决定结构**：目录、AT 导航、阅读器大纲都由 `h1–h6` 生成。**HTML 的"文档大纲算法"从未被实现，已从规范中移除**，所以**不能指望嵌套 section 自动降级 `h1`**：层级必须用 `h1…h6` 的数字**明确写出**。【补】
3. **层级与目录深度一一对应**：以全书为单位给出统一约定，例如
   - `h1` 只给书名页（04 §4.3，SE 7.2.3）；
   - 有"部"：部 `h2` → 章 `h3` → 节 `h4` → 小节 `h5`；
   - 无"部"：章 `h2` → 节 `h3` → 小节 `h4`。
   - 数字只表示全书层级；样式由角色类 `part-title` / `chapter-title` / `section-title` / `subsection-title` 决定（03 §6.2）。
   同类标题（所有章）必须同级；**不跳级**（`h1` 后直接 `h3` 是错）；**一个文件内最高级标题只出现一次**，除非该文件含多个并列单元（如"附录一/二"合在一页）。
4. `<section>` **必须有标题**（或用 `aria-label`/`aria-labelledby` 命名）；纯样式分组请用 `<div class="...">`，不要用 `section`。`article` 仅用于可独立流通的内容块：杂志中的独立文章、诗集中的单首诗、文集/短篇集中的单篇；小说里插入的诗不用 `article`（体裁判断交大模型，仅建议）（SE 4.2.3）；`aside` 用于附属内容（§5.5）；`nav` 仅用于导航。
5. 标题文本是**纯文字**：不含句末句号、不含自带的"页码"、不含 `<br/>`（副标题用 `<p class="subtitle">` 或 `<span class="subtitle">` 并加 `epub:type="subtitle"`/`role="doc-subtitle"`）；序号与题名间用统一的空格或 `<span class="num">`，不要混用全/半角。
6. 标题 `id` 用于目录与链接，保持稳定。给 `section` 或标题其一加 id，不要用空 `<a id=...>`（§10）。
7. 同一标题元素内的"章序号 + 章名"（如 `第一章　开端`，序号与章名之间一个全角空格）保持在同一个标题元素里，视觉分行用 CSS（`display:block` 的 `span`）；不要拆成两个 `h1`/`h2`，**也不用 `hgroup` 拆成序号 + 章名**：`hgroup` 里的 `p` 不算标题，拆开后目录和读屏只剩"第一章"。`hgroup` 只用于真正的副标题（具体写法见 `04` §4.3）。
8. 无标题的献辞页、题词页、只有图的页，不要放 `section epub:type="chapter"`，也不再用 `div`；用带 `aria-label` 的 `section`，并标对应的 `epub:type`（`dedication`、`epigraph` 等）。具体写法见 `04` §4.2。
9. **标题组**：`section` 开头除标题外还有副标题、署名、题词时，可放入 `<header>`；只有标题时不加。`header` 至少含一个直接子块级元素。这是可选写法，识别输入时容忍，不强制已有书改动（SE 4.2.6）。
10. 根 `section` 缺 `id` 时取文件名主干（`chapter-003.xhtml` → `id="chapter-003"`）；**已有 id 一律保留**。一个文件含多个并列单元（如"附录一/二"合在一页）时，各单元 id 按其独立成文件时的文件名主干生成（`appendix-a`、`appendix-b`；中文标题转序号，不用汉字），日后拆分时 id 不变（SE 5.1.1）。

### 4.2 `section` 与 `epub:type`/role 组合示例

```xml
<body epub:type="bodymatter">
  <section epub:type="chapter" role="doc-chapter" id="chapter-003" aria-labelledby="h-chapter-003">
    <h1 id="h-chapter-003">第三章 转折</h1>
    <p>……</p>
    <section id="chapter-003-s1">
      <h2>一、起因</h2>
      <p>……</p>
    </section>
  </section>
</body>
```

注意：role 需与元素兼容——`doc-chapter`、`doc-part`、`doc-foreword` 等可用于 `section`；`doc-noteref`、`doc-backlink` 只用于 `a`；`doc-footnote` 用于 `aside`/`section`；`doc-pagebreak` 用于 `span/hr/div`。EpubCheck 会因 role 与元素不匹配报 `RSC-005`。

### 4.3 章首视觉留白

"章首下沉 30% 屏"之类（`margin-top:30%`）是**样式**，由 CSS 类控制（见 `04_排版样式模板库.md`），内容文档中不应出现空段/`<br/>` 来制造。

## 5. 语义元素映射表

### 5.1 块级内容

| 内容 | 用 | 禁止/反模式 | 备注 |
|---|---|---|---|
| 正文段落 | `<p>` | `<div>文字</div>`、`<br/><br/>` 分段、每行一个 `<p>`（来自 PDF/TXT 硬换行） | 缩进/段距用 CSS；一个自然段 = 一个 `<p>`；段内不含 `\n` 以外的硬换行 |
| 章/节标题 | `h1–h6` | `<p><b>…</b></p>`、`<div class="title">`、为改字号用 `h` | 见 §4 |
| 引文（长引用） | `<blockquote>` 内含 `<p>`。引用他人的话，或叙述中嵌入的书信、电报、碑铭、告示等文献 | 靠缩进的 `div`；仅为缩进排版而用 `<blockquote>`（自己的诗、署名行） | 出处：保留现有写法 `<p class="attribution">`，放在 blockquote 内、引文之后；破折号写在文字里，不交给 CSS 生成。输入书里的 `footer`、`p.source` 照样识别，不强制转换。见 `04` §4.6（SE 4.2.4） |
| 图与图注 | `<figure>` + `<img alt>` + `<figcaption>` | 图片后跟一个居中的 `<p>` 当图注；**把图注复制进 `alt`** | 图注在 `figcaption`；图只是装饰则不需 figure；图号"图 3-1"写在 figcaption。**`alt` 是图像内容的描述，图注是对图的说明，二者不互相替代**：缺 `alt` 而有图注时，`alt=""` 并标"待补描述"，交大模型/用户补写，不抄图注（读屏会念两遍）（SE 4.2.5） |
| 标题组 | `<header>`（可选） | | 见 §4.1 第 9 条 |
| 表格 | `<table>` + `<caption>` + `<thead>/<tbody>` + `<th scope>` | 用表格做排版、拆成图片、`width/border` 属性 | 见 §5.6 |
| 列表 | `<ol>`（有序）、`<ul>`（无序）、`<dl>`（术语–释义） | 用 `<p>1. …</p>` 手写序号；用 `<br/>` 分条 | 手写序号列表的识别与转换见 §9 |
| 旁栏/提示/补充 | `<aside>`（`epub:type` 可选） | 在正文中用 `<div class="box">` 无语义 | 脚注/尾注见 §7 |
| 诗歌/歌词 | 一节诗一个 `<p>`，每行一个 `<span>`，行间 `<br/>` | 用 `<pre>` + 全角空格排版；用多个 `<p>` 一行一段 | 见 §5.7 |
| 书信 | 叙述中引用的用 `<blockquote>`；书信集里的整封信用 `<section>`；都标 `z3998:letter` | 为缩进把自己的文字做成 `blockquote` | 见 §5.7 |
| 代码 | `<pre><code>` | 用 `<p>` + `&nbsp;` 缩进 | 保留空白靠 `pre` 本身 |
| 分隔线/场景转换 | `<hr/>` | 空段、`<p>* * *</p>`（若有，须带 class 并保持语义）；用 `hr` 做装饰性边线 | 样式用 CSS；`hr` 在 HTML5 语义是"主题切换"；边线用 CSS `border`（SE 4.2.8） |
| 地址/署名/信函落款 | `<p class="inscription">` 或 `<address>`（仅限联系信息）；信函的称呼、落款用 §5.7 的 `z3998:` 词 | 用 `<br/>` 拼多行成一个 p 以外的方案 | 右对齐靠 CSS |

### 5.3 重点：`ol / ul / dl`

```xml
<ol class="steps">
  <li>准备材料</li>
  <li>开始制作
    <ul><li>子项甲</li><li>子项乙</li></ul>
  </li>
</ol>

<dl>
  <dt>EPUB</dt>
  <dd>Electronic Publication，一种基于 Web 技术的电子书格式。</dd>
</dl>
```

- 嵌套列表的标记形状由 CSS 显式指定（`ul ul{list-style-type:circle}`），不要指望阅读器自动轮换【需实测】。
- 长编号（上百条）用 `<ol start>`/`value` 保持连续，不要手打数字。
- 列表中混有标题（"一、二、三"章节式标题列表）不是列表，是标题（§9）。

### 5.4 `ruby`（注音）

```xml
<ruby>孔雀<rp>(</rp><rt>kǒng què</rt><rp>)</rp></ruby>
<ruby>漢<rp>(</rp><rt>han</rt><rp>)</rp>字<rp>(</rp><rt>ji</rt><rp>)</rp></ruby>
```

- 结构：`<ruby>` 基文本 `<rp>` `<rt>` `<rp>`；`rp` 供不支持 ruby 的环境降级为"孔雀(kǒng què)"。
- 【更正】原书/笔记用 `<rb>`：`rb` 在 HTML Living Standard 中已**废弃**，EpubCheck 报 `RSC-005`；直接把基文本写在 `<ruby>` 里，多段基文本就多个"基文本 + rt"对。
- `rtc`（复合注音）同属废弃，不用。
- 按字注音或按词注音是内容决策；按词时空格问题：拼音间音节用空格分隔放在同一个 `rt`。
- 字号比例（约 50–60%）、字体见 `03_CSS与中文排版规范.md`。

### 5.5 `aside`、`figure`、`blockquote` 补充

- `aside`：附属内容。用于：①脚注（§7）；②旁栏/提示框（`epub:type="sidebar"` 已弃用，建议只用 `<aside class="sidebar">`，role 可选 `doc-tip`/`doc-example`/`doc-pullquote`）。**不要**用 `display:none` 隐藏 `aside`：隐藏即对辅助技术不可见；注释弹出由阅读系统据 `noteref` 的语义决定（§7）。
- `figure`：一张或一组图 + 可选 `figcaption`；`figure` 内可含表格、代码、引文，只要是"可整体移走不影响叙述"的单元。
- `blockquote`：引用**他人的话**，或叙述中嵌入的书信、电报、碑铭等文献；仅为缩进排版的内容不是 `blockquote`。出处放在 `blockquote` 内、引文**之后**的 `p.attribution`，不混进引文段落；引用中含多段，每段一个 `<p>`。`blockquote` 至少含一个块级子元素（通常是 `<p>`）（SE 4.2.4、5.8）。

### 5.6 表格

```xml
<table>
  <caption>表 1-1 年度销量</caption>
  <thead><tr><th scope="col">年份</th><th scope="col">销量</th></tr></thead>
  <tbody>
    <tr><th scope="row">2023</th><td>120</td></tr>
  </tbody>
  <tfoot><tr><th scope="row">合计</th><td>240</td></tr></tfoot>
</table>
```

- 表头 `th` 带 `scope`（或 `id/headers`）；标题用 `<caption>`（不要放在表格前的 `<p>`，除非样式需要，则 `caption` 仍应保留语义）。
- 子元素顺序：`caption`、`colgroup`、`thead`、`tbody`、`tfoot`、`tr`；**为稳妥把 `tfoot` 放在最后**（HTML5 允许在 `tbody` 前后，但部分阅读器按源码顺序显示【需实测】）。
- 外观（边框、宽度、对齐）全部 CSS（`border-collapse`、`width:100%`、`text-align`），不用 `border/width/align/cellpadding` 属性；`colspan/rowspan` 之后不要遗留空 `td`。
- **宽表**（列多）在窄屏会溢出：优先让表格自适应（`table-layout:fixed`、缩小字号），其次拆表，最后才考虑图片，并为图片提供 `alt` 与文字版。单元格总高超过一屏时【需实测】可能被截断，宜拆表。
- 不用表格做排版（编委名单对齐、图文并排）：用 CSS；"三字名对齐四字宽"类需求见 `04_排版样式模板库.md`。

### 5.7 诗歌、歌词、书信、对话

**诗歌**（结构与 `04` §4.7 一致）：

```xml
<blockquote epub:type="z3998:poem">
  <p>
    <span>床前明月光，</span><br/>
    <span>疑是地上霜。</span>
  </p>
  <p>
    <span>举头望明月，</span><br/>
    <span>低头思故乡。</span>
  </p>
</blockquote>
```

- **一节诗一个 `<p>`，每行一个 `<span>`，行间 `<br/>`**；缩进的诗行在该 `span` 上加 `indent-N` 类（CSS 控制），**不要**用全角空格缩进（SE 4.1.2）。
- 容器：整首诗标 `epub:type="z3998:poem"`（歌曲 `z3998:song`、赞美诗 `z3998:hymn`、歌词 `z3998:lyrics`）；只是一个片段时标 `z3998:verse`。Z39.98 里 `verse` 是总类，`poem`、`song`、`hymn`、`lyrics` 是子类，所以整首诗不用 `verse`。
- 容器元素：被引用的他人的诗（题词、叙述中的引诗）用 `<blockquote>`；本书自身内容的诗，有标题时用 `<section>`（诗集中的单首诗可用 `<article>`，见 §4.1 第 4 条），无标题时用 `<div>`。
- 输入书里的旧写法 `<div class="poem">` + `<p class="stanza">` + `<span class="line">` 照样识别，重建时转成上面的结构，原有 class 去掉。
- 标题行、作者行放在诗的容器之外（或 `<header>` 内），不算诗行。
- 竖排诗歌的行序/缩进由 `writing-mode` 控制，内容结构不变。

**书信**（见 `04` §4.8）：

- 容器：叙述中引用的信、电报用 `<blockquote>`；书信集里的整封信用 `<section>`（带标题或 `aria-label`）。两者都标 `epub:type="z3998:letter"`（SE 4.2.4）。
- 内部：称呼 `z3998:salutation`，结束语 `z3998:valediction`，署名 `z3998:signature`，附言 `z3998:postscript`；写信人、收信人 `z3998:sender`、`z3998:recipient`。这些词都在 Z39.98 词表里。
- 日期行没有对应的词：Z39.98 **没有** `dateline`（那是 SE 的私有词 `se:`），不加 `epub:type`，类名按 `04` §4.8。

**前缀声明**：`z3998:` 词必须在 `<html>` 上声明 `epub:prefix="z3998: http://www.daisy.org/z3998/2012/vocab/structure/"`，**只能写在 `<html>` 上，不能写在 `<body>` 上**（§6.1）。不想声明前缀则不加 `epub:type`，只留 class。

**对话**：每个说话人一段 `<p>`，不要用 `<br/>` 合并成一段。

### 5.8 其他元素

| 元素 | 规则 |
|---|---|
| `<hr/>` | 主题转换，即小节间的"* * *""◇"；两阶：高层级转换用标题，轻度转换用 `hr`；`<hr class="ornament"/>` 样式化；不用 `hr` 做装饰性边线，边线用 CSS `border` |
| `<img>` | `alt` 必有；尺寸用 CSS（`max-width:100%; height:auto`）；**文字不得以图片呈现**（文字图应还原为文字，生僻字可用字体） |
| `<svg>` 内联 | 包含则 manifest 需 `svg`；须有 `<title>`/`aria-label` |
| `<math>` | MathML；manifest 需 `mathml`；见 `05` 的公式处理 |
| `<audio>/<video>` | 须 `controls`；`<source type>`；提供回退文本/链接 |
| `<iframe>`、`<object>`、`<embed>` | 一般不用；`object` 仅用于带回退的资源 |
| `<script>` | 默认移除或标记；若保留须 `scripted` 并保证无脚本时内容仍可读 |
| `<form>` | 极少数；会使文档 `scripted` |
| `<details>/<summary>` | 渲染不稳定【需实测】，避免用于核心内容 |
| `<canvas>`、`<button>` 等 | 不建议 |

## 6. `epub:type` 与 DPUB-ARIA role

### 6.1 机制

- `epub:type`：EPUB 结构语义词表，**增强**元素语义，不能改变元素本质（`section` 可标 `chapter`；`p` 不能"变成"列表项）。值可多个，空格分隔；使用前声明 `xmlns:epub`。
- `role`：ARIA 角色；DPUB-ARIA 提供 `doc-*` 系列，辅助技术据此提供"跳到注释/章节"等功能。**两者互补，推荐并存**：`epub:type` 给阅读系统（弹注、地标、翻页逻辑）；`role="doc-*"` 给辅助技术与 Web 工具。规范不强制并存，但对有对应 `doc-*` 角色的值，并存是最大化可访问性的做法。【补】
- `epub:type` 可用于 `body/section/aside/div/a/li/span/nav/ol/ul/h*` 等多数元素；role 与元素的兼容性按 ARIA in HTML 约定（§4.2）。
- **词表优先序**：先用 EPUB 结构语义词表（SSV）；SSV 没有再用 Z39.98（`z3998:`）。同一语义两个词表都有时用 SSV 的值。**软件只生成 SSV 与 `z3998:` 的值，不用 `se:` 等私有词表**；输入中已声明前缀的其他词表值原样保留，不报错、不改写（SE 4.3.2）。
- **`z3998:` 前缀**：用到 `z3998:` 值，必须在 `<html>` 上写 `epub:prefix="z3998: http://www.daisy.org/z3998/2012/vocab/structure/"`（且已声明 `xmlns:epub`）。**`epub:prefix` 只能写在 `<html>` 根元素上**，写在 `<body>` 上报 `RSC-005` + `OPF-028`；用了 `z3998:` 而未声明报 `OPF-028`（error），规则引擎自动补声明。已有前缀声明时在其后追加，不覆盖（SE 4.3.3）。
- 未声明前缀、拼写错误的值 → `OPF-`/`RSC-005` 提示（词表未定义的无前缀值会被视为错误，提示"未知 epub:type"）。
- 同一元素上 `epub:type` 值过多（>3）通常是误用。

## 7. 注释：noteref + footnote / endnote

> 本工具的默认输出是**全书一个书末尾注文件**（`endnotes` + `<ol><li id="note-N">` + 末尾 ↩ 回链），做法同 Standard Ebooks，详见 `04_排版样式模板库.md` §4.12 注释。下文的脚注写法同样合法，用于理解和识别输入书。

### 7.1 标准结构

**脚注/弹注（本页或本章内）**

```xml
<p>……这是正文<a epub:type="noteref" role="doc-noteref" id="noteref-1" href="#note-1">1</a>，继续正文。</p>
...
<aside epub:type="footnote" role="doc-footnote" id="note-1">
  <p><a epub:type="backlink" role="doc-backlink" href="#noteref-1">1</a> 这里是注释内容。</p>
</aside>
```

**尾注（集中在章末或书末）**

```xml
<section epub:type="endnotes" role="doc-endnotes" id="endnotes">
  <h1>注释</h1>
  <ol>
    <li id="note-1">
      <p>注释内容。<a epub:type="backlink" role="doc-backlink" href="chapter-001.xhtml#noteref-1">↩</a></p>
    </li>
  </ol>
</section>
```

尾注 `li` 上**不写** `epub:type="endnote"` 与 `role="doc-endnote"`，两者均已弃用（§6.2）；`li` 位于 `endnotes` 容器内即可被识别。

### 7.2 规则（均可判定）

1. **`noteref` 是 `<a>`**，`href` 指向目标 `id`；目标是 `aside epub:type="footnote"`，或 `endnotes` 容器内的 `li`；一个注释可有多个引用，一个引用只指向一个注释。
2. **一一对应**：每个 `noteref` 都有目标；每条注释至少被一个 `noteref` 引用；孤儿注释与悬空引用都要报告。
3. **双向跳转**：注释内给出回链（`epub:type="backlink"`，**与** `role="doc-backlink"` 同写；`backlink` 是 SSV 词），读者读完回到原位。回链链接文本可以是编号本身或 `↩`，不应是"点击返回"。（弹注型阅读器自带关闭，但回链对不支持弹注的阅读器是必需的。）
4. **编号**：同一单位（章/书）内连续、无重复、与注释文本的编号一致；每章重新编号还是全书连续，保持全书统一；编号作为**链接文字**写阿拉伯数字（`1`），方括号 `[1]`、圆圈 `①` 样式由 CSS（`::before/::after` `content`）加；用 `<sup>` 或 CSS `vertical-align` 做上标均可（不要两者叠加造成二次缩小）。
5. **放置位置**【需实测】：
   - **同文件内**的 `noteref→footnote` 最稳；跨文件（章内引用、书末集中尾注）也合规，但部分阅读器的"弹注"仅识别同文件目标。
   - 脚注放章末（`<section epub:type="footnotes">` 已弃用，用无 epub:type 的容器 `<div class="footnotes">` 或直接并排多个 `aside`），或紧跟被引用段落之后。不支持弹注的阅读器会把 `aside` 按流显示，章末集中是最自然的降级。
   - 全书大量长注释，适合尾注集（`endnotes`）：**不按章分组**，全书一个连续编号的列表，不加章子标题（SE 做法）。读者从注释回到正文靠回链，不靠分组。
6. **不要隐藏** `aside`：`display:none` 会让辅助技术看不见，阅读系统自会处理弹注显示；若确需视觉隐藏须保留给 AT（见 `03`）。【更正】原书"aside 必须不显示"并非规范要求。
7. 注释内容也是正文级内容：多段注释、含引文的注释保留块结构（多个 `<p>`、`blockquote`），不压成一个 `p`；注释里的链接、强调照常写。回链放在最后一个块里；末块不是 `p`（如 `blockquote`）时，回链单独成一段（SE 7.E，见 `04` §4.12）。
8. `href` 使用文件相对路径 + 片段（`chapter-001.xhtml#note-1`），目标 `id` 不可被拆分/合并破坏（§2.2）。
9. 私有弹注实现（`<a class="…footnote"><img/></a>`，注文放 `alt`）不是标准，**迁移**为 §7.1 结构：把 `alt` 文字取出作为注释正文，`<img>` 去掉，`alt` 置空。

### 7.3 id 命名约定

新生成的注释一律用 `noteref-N`（引用）与 `note-N`（注释），N 为**全书流水号**，从 1 起；纯 ASCII、字母开头，合并拆分文件时不冲突（SE 5.1.2）。同一条注被多处引用时，第 1 处用 `noteref-N`，第 2 处起用 `noteref-N-2`、`noteref-N-3`，回链指向第 1 处。**输入书里已有的 id**（`nr-…`、`fn-…`、`en-…` 之类）是外部链接目标，**一律不改**；只有重建注释结构时才统一为上述写法，并同步全书的 `href`。

### 7.4 从旧写法转换（自动化）

序号形式多样：`①②…`、`[1]`、`(1)`、`〔1〕`、上标 `<sup>1</sup>`。流程：①识别候选引用与注释段；②按章统计序号序列，检查连续性并配对；③生成 §7.1 结构并插入回链；④配对失败（缺号、重号、数量不等）**停止自动，列出候选**。注释内部的跨段延续（注文多段）需保持同一 `aside`/`li`。**B 级（需复核）**。

## 8. 分页标记与语言标注

### 8.1 pagebreak（保留纸书页码）

```xml
<span epub:type="pagebreak" role="doc-pagebreak" id="p234" aria-label="234" title="234"></span>
```

- 空元素，放在**该页内容开始处**；`id` 唯一，在 page-list nav 里被引用（`01` §6.4）。
- 只用于有纸书页码的书；不要把正文里手敲的"— 12 —""第 12 页"行当页码保留，应转换为 pagebreak 或删除。

### 8.2 语言标注

| 场景 | 写法 |
|---|---|
| 全文语言 | `<html xml:lang="zh-Hans" lang="zh-Hans">`（两个属性**同写、值相同**；缺一在 XHTML/HTML 解析下行为不一致，EpubCheck 对不一致报错）。**值以原书 `dc:language` 为准**（原书用 `zh-CN` 就写 `zh-CN`）；新生成时简体 `zh-Hans`、繁体 `zh-Hant`（`01` §4.1） |
| 片段外文 | `<span lang="en" xml:lang="en">EPUB</span>` 或 `<p lang="fr" xml:lang="fr">…`；与主语言不同时才写 |
| 文言/古籍 | `lang="lzh"`，古诗词区块可加 |
| 繁简混合书 | 按段落/章节标 `zh-Hans`/`zh-Hant`，字体回退见 `03` |
| 方向 | `dir="rtl"` 仅用于 RTL 文种 |

- 语言码必须合法 BCP 47（`zh-CN`、`zh-Hans`、`en-US`；**下划线 `zh_CN` 错误**）。
- 全局语言应与 OPF `dc:language` 一致（`01` §4.1）；每个内容文档根元素均应有 `lang`。
- 英文夹杂的中文书不需要给每个英文单词包 `<span lang>`（GDP、iPhone、人名拉丁转写极多，逐词标注噪声大）。**可检测的阈值**：拉丁字母连续串达到 2 个词、或含非 ASCII 拉丁字符、或被《》包住的外文书名，才自动标 `lang`；按文字脚本判别语言码，不确定时交大模型/用户；短缩写与常见品牌不标。整段、整个书名、整句照常标（SE 5.3）。
- **语言标注上提**：同一块内所有子元素都是同一种外语时，把 `lang`/`xml:lang` 写在该块容器上（如整个 `blockquote`），不在每段、每个 `span` 上重复（SE 5.3）。

## 10. 链接与 id 规范

### 10.1 链接

- 站内链接一律**相对路径**，相对于当前文档（`../images/a.png`、`chapter-002.xhtml#s3`）；禁止绝对路径、`file:`、盘符、`C:\`。
- `href` 目标必须存在于 manifest；若是内容文档，必须在 spine（`01` §5.4）；片段 `#id` 必须在目标文档存在（`RSC-012`）。
- 站内链接**大小写与 zip 条目完全一致**；URL 编码规则同 `01` §2.3（空格 `%20`，`&` 写 `&amp;`）。
- 外链：`https://…`；`mailto:`、`tel:` 可用；外链样式用 CSS，不用"点此"类链接文字；外链文本含 URL 时可 `<wbr/>`。
- 链接文本要有意义（AT 会单独朗读链接列表）：不要用"这里""点击"；脚注引用的编号是例外。
- 不要把整段文字做成链接；一个 `<a>` 不跨块级。
- `<a>` 不嵌套；`<a>` 不含 `<div>`（HTML5 虽允许透明内容模型，但对阅读器兼容性差，避免）。
- 内部跳转（目录、脚注）目标尽量是语义元素本身的 `id`（标题/section/aside），避免空 `<a id/>`。
- 目录页、nav、书签依赖的 id **不得在后续处理中自动改名**；若必须改，全书同步更新。

### 10.2 id

- 合法 NCName：`[A-Za-z_][A-Za-z0-9._-]*`；不得以数字开头（`1-2` 是常见的错）；不得含空格、冒号、`#`；中文 id 虽 XML 合法但不建议。
- **文件内唯一**；合并文件时重名需重命名（后缀 `-2`）并同步所有指向它的 `href`、`aria-labelledby`、`aria-describedby`、`headers`、`for`、`list`、CSS `#id` 选择器、SVG `url(#id)`。
- 语义命名：`chapter-003`、`s1-2`、`p234`，不用 `a1 a2 a3…` 无意义自增或 Word 导出的 `_Toc123456`（可保留，但在重建目录后不再需要的可清理）。
- 不被任何链接/CSS/脚本/aria 引用的 id 默认**保留**（作者可能为外部引用预留）；仅在用户选择"精简"时清理。

**新生成 id 的规则**（只约束我们**新生成**的 id；存量 id 不改名、不清理，只要求文件内唯一）（SE 5.1）：

1. **克制**：新生成的 id 只用于链接目标——nav 条目、noteref/backlink、pagebreak、loi/lot 引用、术语引用。其余元素不加 id。
2. **根 `section`** 的 id = 文件名主干（§4.1 第 10 条）；嵌套的小节需要进 nav 或被链接时才补 id。
3. **专用写法**：注释 `noteref-N`/`note-N`（§7.3）；插图 `figure-N`、表格 `table-N`（全书流水号，从 1 起，仅在被 loi/lot 或正文交叉引用时生成）；术语表词条 `term-N`；分页标记 `p<页码>`（§8.1）；被链接的诗行 `<诗所在 section id>-line-N`（行号不含标题行，不主动生成）。
4. **通用生成式**（无专用写法时）：`<所属 section id>-<元素名>-<N>`，N 在该 section 内按文档序从 1 起，如 `chapter-003-blockquote-2`。
5. **全书唯一**：新生成的 id 靠 section 前缀自然达到全书唯一，拆分合并不冲突；冲突时在前面加最近 section 的 id。幂等：相同输入产生相同 id，不每次新建。
6. **不作 CSS 钩子**：id 不用来挂样式（§5.2、`03` §10）。
- `section`/标题的 id 要稳定：同一章的重复处理（幂等）不应每次生成新 id。

## 11. 对优化软件的含义

可自动检测：

- XML 良构（解析失败的文件列表与行号）；未定义实体（`&nbsp;` 等）；非法控制字符；根元素 `xmlns`/`xmlns:epub`；`<title>` 缺失或为空；`lang`/`xml:lang` 缺失或不一致；DOCTYPE 非 `html`。
- 废弃元素/属性（`font/center/big/strike/rb/rtc`、`align/valign/bgcolor/border/width` 表格属性、`<a name>`）。
- id 重复/非法 NCName；`href` 目标缺失；`a`/`img` 缺 alt；非法嵌套（`p` 含块、`ul` 含非 `li`）。
- 标题层级：跳级、同级不一致、`section` 无标题、一文件多个最高级标题、标题过长/句末标点、伪标题特征。
- 注释：`noteref` 无目标、`footnote` 与尾注 `li` 无引用、无回链、序号不连续；尾注 `li` 上多余的 `endnote`/`doc-endnote`（弃用）。
- `epub:type` 值是否在词表、与元素/role 是否兼容、文件角色（文件名/标题）与类型是否一致；弃用值清单；**用了 `z3998:` 而 `<html>` 无 `epub:prefix` 声明**，或 `epub:prefix` 写在 `<body>` 上；`afterword` 位于 `bodymatter` 之内（仅警告）；`bodymatter` 起点指向半书名页。
- 同一 `figure` 里 `alt` 与 `figcaption` 文本完全相同（info，不自动改）。
- 文件大小超阈值；文件过碎（< 阈值且无标题）。
- 伪排版指纹（§9 第 1–5、7–9、11–15、18–22 项）。

可自动修复：

- 序列化为严格 XHTML（实体、自闭合、引号、大小写、命名空间、DOCTYPE、补 title、补 `lang/xml:lang`）。
- 空段、连续 `br`、段首空白缩进、废弃元素/属性、空 `<a id>` 迁移、`<p>` 内块级元素提升。
- 将行内样式提取为 class（合并同声明）；`<center>/<font>/align` → class。
- 补全 `epub:type`+`role`（文件角色明确时）、分区 `frontmatter/bodymatter/backmatter`、`pagebreak` 的 role/aria-label；补 `<html epub:prefix>` 的 `z3998:` 声明，并把误写在 `<body>` 上的挪到 `<html>`。
- 生成注释的回链、规范 id、与 nav 同步重建。
- 拆分/合并文件并更新链接/spine/nav。

需确认：

- 伪标题→`h` 的转换与层级；硬换行段落合并；手写序号→`ol`；`div`→`blockquote/figure`；脚注配对失败的候选；内容顺序调整；弃用 `epub:type` 的升级；删除封底广告页/空白页/手写目录页。

只提示：

- 图片文字、表格版式过宽、脚本/表单/iframe、`details`、私有扩展、对中文无意义的 `<i>`。
