# 05 图片与字体资源

> 基准：EPUB 3.3 及配套规范（Core、Reading Systems、Accessibility 1.1）。标记：【补】= 书外补充；【需实测】= 规范未保证、各阅读系统（RS）行为不一，不得当作结论；【书】= 来自原书且仍成立。

## 1 图像

### 1.1 媒体类型与地位（EPUB 3.3）

| 类型 | media-type | 地位 | 建议 |
|---|---|---|---|
| JPEG | `image/jpeg` | 核心媒体类型（Core Media Type，CMT） | 照片首选 |
| PNG | `image/png` | CMT | 线稿、截图、需要透明 |
| GIF | `image/gif` | CMT | 仅用于动画；静态图一律改 PNG-8 |
| SVG | `image/svg+xml` | CMT | 矢量图、示意图（见 1.6） |
| WebP | `image/webp` | CMT，EPUB 3.3 新增（RFC 9649）【补】 | 规范层面合法，但 RS 实际渲染不保证；默认不输出 WebP，作为可选 profile【需实测】 |
| AVIF、HEIC、JPEG XL、BMP、TIFF | — | 非 CMT | 必须转成 CMT；若保留须在 manifest 提供 `fallback` 链，通常直接转换 |

要点：
- CMT 资源 RS 必须支持，非 CMT 资源必须有 fallback，否则 EPUBCheck 报错。【补】CMT 仅规定"RS 应能处理"，不等于每个 RS 都已实现 WebP，旧 RS（2017 年前后）不支持。
- manifest 的 `media-type` 必须与文件真实格式一致。检测：用文件头魔数（JPEG `FF D8 FF`，PNG `89 50 4E 47`，GIF `GIF8`，WebP `RIFF....WEBP`）而不是扩展名；扩展名错（`.jpg` 实为 PNG）是常见缺陷。
- 书中原话"核心图像类型 JPEG/PNG/GIF/SVG"已过时：3.3 起加入 WebP。

### 1.2 格式选择

| 内容 | 格式 | 参数 |
|---|---|---|
| 照片、渐变、扫描彩图 | JPEG | quality 80–88（默认 85），4:2:0 色度抽样，baseline；渐进式 JPEG 多数 RS 可显示但【需实测】 |
| 线稿、流程图、文字截图、图表、≤256 色 | PNG-8（索引色） | 比 GIF 小；有半透明边缘（抗锯齿）时改 PNG-24 |
| 要求无损的截图/插画 | PNG-24（直接色） | 体积约 JPEG 的数倍，仅在必要时 |
| 黑白/灰度扫描页 | 灰度 8bit PNG，或 1/2/4bit 灰度 PNG | 文字扫描页用 JPEG 会产生振铃，优先 PNG |
| 动画 | GIF 或 APNG | APNG 不在 CMT 之内（PNG 规范外扩展），不依赖；动画一律视为装饰，必须有静态可读的替代信息 |
| 可缩放图形 | SVG | 见 1.6 |

【书】JPEG 不适合线条与文字（会糊）、PNG-8 比 GIF 小、BMP 不用。这些结论仍成立。

自动选型算法（可判定）：
1. 统计唯一颜色数 `n`、边缘锐利度（相邻像素差大于 32 的比例）。
2. `n ≤ 256` 或锐利像素比 > 30% → PNG（`n ≤ 256` 用 PNG-8）；否则 JPEG。
3. 转换后比较体积，若 PNG 比 JPEG 大 3 倍以上且图像为照片类，仍用 JPEG 并提示用户。
4. 有 alpha 通道 → 必须 PNG（或 WebP），见 1.7。

### 1.3 颜色与规格

- **颜色模式**：输出一律 RGB（sRGB）或灰度。CMYK JPEG 在不少 RS 会偏色或不显示【书·我】→ 检测 JPEG SOF 分量数 = 4（或 Adobe 标记）即转 sRGB。Lab、多通道、16bit/通道 → 转 8bit。
- **ICC**：非 sRGB profile（Adobe RGB、Display P3）先转 sRGB 再剥离 profile；已是 sRGB 可不嵌入 profile（RS 缺省按 sRGB 解释）。
- **EXIF**：先按 Orientation 旋转像素，再删除所有 EXIF/XMP/缩略图（含 GPS，隐私）。保留 ICC 之外的元数据没有阅读价值。
- **分辨率元数据（dpi）**：无意义，RS 只看像素与 CSS；不要拿 72/96 dpi 作为质量判据。
- **尺寸与体积建议**（【补】经验值，皆应做成可配置 profile，EPUB 规范本身不规定）：

| 项 | 默认值 | 超限处理 |
|---|---|---|
| 正文插图长边 | ≤ 2048 px（宽度 ≤ 1600 px 已足够手机和平板） | 等比缩小，不放大 |
| 单图体积 | ≤ 1 MB（警告 > 2 MB） | 降 quality 到 75 下限，或缩尺寸 |
| 全书图片总量 | 建议 ≤ 全书体积的 80%；整书 ≤ 50 MB（部分书店上架上限更低，以平台为准） | 告警 |
| 单图像素数 | ≤ 16 MP（部分 RS 解码内存受限，过大图会崩溃或空白）【需实测】 | 缩小 |
| 小图标/行内字符图 | ≥ 2 倍显示尺寸（高清屏），例如显示 1em=16px，则图 ≥ 64 px 高 | 放大不能提升质量，需重绘或改 SVG |

- **缩放原则**：只缩小不放大；缩小用 Lanczos/area 重采样；需同时保证 `width/height` 属性或 CSS 能让 RS 在图片加载前预留版面（避免回流）。
- **CSS 呈现**（详见 03）：`img{max-width:100%;height:auto}`；不写死 px 宽度；整页图 `max-height:100vh` 需【需实测】。

### 1.4 去白边（裁边）

原理：把近似背景色的外围像素视为边，取"内容像素"的外接矩形（bounding box），裁剪并留安全边距。【书】用 Photoshop 的"色彩范围 252 → 裁剪"，等价于阈值 252 的 bbox。

算法与阈值：
1. **背景色估计**：取四角各 8×8 区域及四边各 1 px 带的像素，求众数色 `bg`。四角不一致（差 > 12）视为无统一背景 → 不裁。
2. **内容掩膜**：像素与 `bg` 的最大通道差 `> T` 为内容。纯白扫描 `T=3`（对应书中 ≥252），JPEG 噪声大 `T=8–12`，泛黄扫描先估 `bg` 再用同样阈值。
3. **去噪**：对掩膜做一次 3×3 开运算，或要求某行/列至少有 `max(2, 0.2%×边长)` 个内容像素才算内容，避免灰尘点撑大 bbox。
4. **透明图**：用 alpha 通道，`alpha > 8` 为内容；不要用颜色判断。
5. **安全边距**：裁后四边各留 `max(4 px, 1%×短边)`；`bg` 不是白色时用 `bg` 色补边而不是白色。
6. **不裁的情形**：封面；整页插图（宽高均 ≥ 90% 版心）；本身带边框的图表（检测四边中点处存在连续深色线）；有 `<figure>` 且 CSS 依赖其比例的版面图；矢量图。
7. **保护阈值**：裁掉面积 > 50%、或宽高比变化 > 30%、或结果长边 < 64 px → 不自动应用，转为"建议"并展示前后对比。
8. 幂等：已裁图再次运行 bbox ≈ 全图，不应再改动（用安全边距容差判定，改动 < 4 px 视为无变化）。

### 1.5 alt 文本规范（含无障碍）

依据 HTML 与 EPUB Accessibility 1.1：每个 `<img>` 必须有 `alt` 属性。

| 图像类型 | alt 写法 |
|---|---|
| 内容性插图/照片 | 简述图像要传达的信息，一句话，建议 ≤ 125 字符；不写"图片""照片"前缀；不重复紧邻 `<figcaption>` 已有内容 |
| 装饰性（分隔花纹、背景、页眉图案） | `alt=""`（空串，不可省略属性）；可加 `role="presentation"` |
| 文字截图/文字图（生僻字图、艺术字标题） | alt = 图中完整文字，一字不差；生僻字图 alt 为该字本身（见 2） |
| 图表、地图、复杂示意图 | alt 给结论/概述；详细描述放 `<figcaption>`、紧随的 `<details>`，或 `aria-describedby` 指向的段落 |
| 公式图 | 改用 MathML；无法改时 alt 写 LaTeX 或读法 |
| 封面图 | `alt="封面：《书名》"`（封面页），或书名与作者 |
| 链接内的图 | alt 描述链接目的，而不是图像外观 |

检测：缺 `alt` 属性（错误）；`alt` 等于文件名或含 `.jpg/.png`（错误）；`alt` 为"图""图片""image""img"（警告）；`alt` 过长（> 250，警告）；大图 `alt=""` 且不在装饰容器中（提示）。【补】大模型可生成候选 alt，但必须标记为"AI 草稿"，由用户确认，不自动写入内容性图像。

### 1.6 SVG 用法

三种使用方式，限制不同：

| 方式 | 写法 | 限制 |
|---|---|---|
| 作为图像 | `<img src="a.svg" alt="…"/>` | 静态渲染，无脚本；SVG 内不得引用外部资源；字体需转曲或 SVG 内嵌 |
| 内联到 XHTML | `<svg xmlns="http://www.w3.org/2000/svg" viewBox="…" role="img" aria-label="…">`，manifest 中该 XHTML 项加 `properties="svg"` | 属 XHTML 内容文档，可用 CSS 继承 `currentColor`（夜间模式友好，见 1.7） |
| 独立 SVG 内容文档 | spine 项 `media-type="image/svg+xml"` | 3.3 中仍允许；RS 对其支持不如 XHTML，不建议 |

规则：
1. 必须有 `viewBox`；根元素 `width/height` 用 `100%` 或不写，不写死 px，否则在小屏被裁切或留空。
2. 含 `<script>` → manifest `properties="scripted"` 并不建议使用；`<foreignObject>` 只在 EPUB 允许的 HTML 子集内使用。
3. SVG 内文字：要么嵌入字体（`@font-face` 并加入子集，见 3），要么转为路径；依赖系统字体的 SVG 文字在不同 RS 字形不一。
4. 无障碍：`<title>`、`<desc>` 加 `role="img"` 与 `aria-labelledby`；`<img>` 引用时 alt 照常写。
5. 大型 SVG（>200 KB，或 path 节点 > 5000）渲染慢，建议栅格化并提示。
6. 清理：去 `<metadata>`、编辑器私有命名空间（`inkscape:`、`sodipodi:`）、注释；不要引入 `xlink:href` 外链。

### 1.7 透明图与夜间模式

问题：RS 夜间模式把页面背景变深，PNG/WebP/SVG 中的透明区域透出深底，黑色线条/文字（透明背景的线稿、公式图、生僻字图、签名）变得看不见；反之白色描边图在浅色模式下看不见。部分 RS 对图片整体反相或降亮度，部分不处理，结论各异【需实测】。

检测（可判定）：
1. 图像带 alpha 通道且透明像素占比 > 5%；
2. 不透明像素的平均亮度 `L < 0.25`（深色内容，夜间会消失）或 `L > 0.75`（浅色内容，日间会消失）；
3. 图像不在带显式背景色的容器内。

处理优先级：
1. **压平**：把图像合成到不透明背景（线稿默认白底，保留 4 px 边距），输出 PNG-8 或 JPEG；夜间模式下呈现为白色图块，可读，是最稳妥的做法。
2. **改内联 SVG**：线条图形和单色字形用 `fill="currentColor"`，自动跟随文字色。
3. **CSS 辅助**（【需实测】）：`@media (prefers-color-scheme: dark){ img.line{ background:#fff; } }` 给图加白色衬底；或 `filter:invert(1)` 反相，仅适用于纯黑线稿，会破坏有彩色的图。
4. 不要给图片写死 `background-color` 以外的色值作主题解法，也不要用 `mix-blend-mode`（支持不稳）。
5. 生僻字行内图：见 3.2，首选字体，其次 `currentColor` 的内联 SVG。

## 2 封面

### 2.1 封面图规格

规范不规定封面尺寸（EPUB 3.3 只要求 `cover-image` 是 CMT 图像）。下表为通用建议，各书店上架要求不同，应做成 profile 可配置：

| 项 | 建议 |
|---|---|
| 比例 | 竖版 3:4（0.75）到 1:1.6（0.625）；默认 1:1.6（对应 Kindle 官方推荐 1600×2560）【书·补】 |
| 像素 | 默认 1600×2560；最低短边 ≥ 1000，长边 ≥ 1600；书中参照：平板 1536×2048（3:4）、手机 1080×1920（9:16）、重制前 533×747 属不合格，最低基线 720×1280【书】 |
| 格式 | JPEG（sRGB，quality 85–90）为主；纯平面设计可 PNG |
| 体积 | ≤ 2 MB（通用）；预览图/缩略图另算 |
| 内容 | 含书名和作者的完整设计，不要用"仅条纹图"；不放网址、二维码、价格、推荐语水印 |

自适应：不裁切封面。需要改比例时，等比缩放后用取样背景色（四边众数）补边，或模糊放大的同图作底；复杂背景无法补边则保持原比例。【书】"以 2048×1536 母版缩放到宽 1080 再扩画布到 1920、上下用背景色填充"是同一思路。

封面质量检测：
- 短边 < 720 → 警告；< 480 → 错误（缩略图模糊）。
- 比例 `h/w` 不在 1.2–1.8 → 警告。
- 四边存在 > 3% 的纯白或纯黑条（去白边阈值同 1.4，但只告警不裁）。
- 缺失封面：manifest 无 `cover-image`（见 2.2）。

### 2.2 cover-image 与封面页写法

```xml
<!-- package document (见 01) -->
<item id="cover-image" href="images/cover.jpg" media-type="image/jpeg" properties="cover-image"/>
<item id="cover" href="text/cover.xhtml" media-type="application/xhtml+xml"/>
<!-- 兼容旧 RS 的 EPUB 2 写法，可保留，EPUB 3.3 不要求【补】 -->
<meta name="cover" content="cover-image"/>
```

规则：
- `cover-image` 属性：manifest 中**恰好一个**条目，类型须是 GIF/JPEG/PNG/SVG/WebP（CMT 图像）。多于一个是错误，零个是警告（书架无缩略图）。
- 封面页（可选，但推荐）放在 spine 第一项，`epub:type="cover"`，并在 nav 的 `landmarks` 中声明：`<a epub:type="cover" href="text/cover.xhtml">封面</a>`。
- 封面页不在目录（toc nav）中重复列出，可 `linear="yes"`（默认）；EPUB 3 不再使用 `<guide>`。

封面页写法（XHTML + 图片，推荐）：

```html
<body epub:type="cover">
  <section class="cover"><img src="../images/cover.jpg" alt="封面：《书名》"/></section>
</body>
```
```css
html,body{margin:0;padding:0;height:100%}
.cover{height:100%;text-align:center}
.cover img{max-width:100%;max-height:100%;width:auto;height:auto;object-fit:contain}
```
- `height:100%` 链路（html→body→容器）必须完整；`100vh` 在部分 RS 异常【需实测】。
- 备选：SVG 包装（经典写法，对旧 RS 稳）：`<svg xmlns="http://www.w3.org/2000/svg" xmlns:xlink="http://www.w3.org/1999/xlink" viewBox="0 0 1600 2560" preserveAspectRatio="xMidYMid meet"><image width="1600" height="2560" xlink:href="../images/cover.jpg"/></svg>`，该 XHTML 项 manifest 加 `properties="svg"`；`viewBox` 数值必须等于图片真实像素。
- 封面页 `<title>` 写书名；`alt` 不空。

### 2.3 安全区

封面可能被：letterbox（不同屏幕比例补边）、书架缩略图裁成 2:3 或方形、圆角遮罩、角标覆盖（进度、"新"）。设计与检测约定：
- **关键信息区**（书名、作者、重要图形）必须落在图像中央区域：左右各留 ≥ 8%、上下各留 ≥ 6%（【补】经验值）。
- 角落 10%×10% 不放关键信息。
- 书名文字高度 ≥ 图高的 1/20，缩到 120 px 宽缩略图时仍可辨认（自动检测难，只能做提示）。
- 重要内容不依赖出血延伸；背景延伸至边缘即可。
- 可自动检测：版面边缘附近（外 3%）存在高对比度文字块（OCR/文本检测）→ 告警。

## 3 生僻字

### 3.1 检测：CJK 码位表

以 Unicode 最新块表为准（Blocks-18.0.0，2026-07 核对；Unicode 15.1/17 新增的 Ext I、Ext J 在其中）。【补】新版本发布后更新此表，建议由 `unicodedata`/UCD `Blocks.txt` 在构建时生成，不要硬编码。

| 区段 | 范围 | 说明 | 分级 |
|---|---|---|---|
| CJK 统一表意文字 | U+4E00–U+9FFF | 基本区，常用字绝大部分在内（《通用规范汉字表》8105 字个别位于扩展区，以字表逐字核对为准）【补，需核实】 | L0 |
| 扩展 A | U+3400–U+4DBF | 6592 字，多数主流中文字体不全含 | L1 |
| 兼容表意文字 | U+F900–U+FAFF | 见 06 的 CHR-03，多为重复编码 | L1 |
| 扩展 B | U+20000–U+2A6DF | SIP（第 2 平面），RS 回落字体常无 | L2 |
| 扩展 C | U+2A700–U+2B73F | L2 |
| 扩展 D | U+2B740–U+2B81F | L2 |
| 扩展 E | U+2B820–U+2CEAF | L2 |
| 扩展 F | U+2CEB0–U+2EBEF | L2 |
| 扩展 I | U+2EBF0–U+2EE5F | Unicode 15.1 | L2 |
| 兼容表意文字补充 | U+2F800–U+2FA1F | L2 |
| 扩展 G | U+30000–U+3134F | TIP（第 3 平面），Unicode 13 | L3 |
| 扩展 H | U+31350–U+323AF | Unicode 15 | L3 |
| 扩展 J | U+323B0–U+3347F | Unicode 17 | L3 |
| 部首补充 / 康熙部首 | U+2E80–U+2EFF / U+2F00–U+2FDF | 常是 PDF/OCR 复制产生的"形近假字"，应映射回统一表意文字（06 CHR-04） | L1 |
| 笔画 / 表意文字描述符 | U+31C0–U+31EF / U+2FF0–U+2FFF（及 U+31EF） | 用 `⿰` 之类拼字描述缺字，属于缺字占位 | 告警 |
| 私用区 | U+E000–U+F8FF；U+F0000–U+10FFFF | 字形含义由具体字体决定，无法跨字体 | 告警 |
| 异体字选择符 | U+FE00–U+FE0F；U+E0100–U+E01EF | IVS，必须随基字保留，子集时 `cmap` 14 要保留 | 保留 |
| 占位符 | `□ ■ 〓 ▯ � ?`（行内孤立） | 缺字占位，需人工补字 | 告警 |

等级含义：L0 无需处理；L1/L2/L3 表示字体覆盖风险递增。字符串长度注意：JS 的 UTF-16 把 L2/L3 当两个码元，检测要按码点。

覆盖检查（可判定）：对书中使用的每个码点，检查"书内 CSS 能用到的字体栈"是否含该字形：
1. 解析内嵌字体的 `cmap`（含格式 12/14）。
2. 对系统/RS 字体无法判断，只能用"风险等级"推断：L0 默认安全；L1 视为中风险；L2/L3 视为高风险（系统无字体时显示空框或 `?`）。

### 3.2 处理优先级

1. **字体回落（成本最低）**：字体栈中追加覆盖该字的字体，写成 `unicode-range` 分段，避免影响其他字符：
   ```css
   @font-face{font-family:"RareHan";src:url(../fonts/rare.woff2) format("woff2");
     unicode-range:U+3400-4DBF,U+20000-2FA1F,U+30000-3347F}
   body{font-family:"BodyFont","RareHan",serif}   /* 末尾必须有通用族 */
   ```
   只写系统字体名（如 `"HanaMinB"`）不保证 RS 上存在，仅作辅助。
2. **子集嵌入（首选，生僻字确定可见）**：选一款含该字且许可允许嵌入的字体（需检查 fsType 与许可证，见 3.6），仅子集这些字，体积通常 < 100 KB。【书】书中 subFont 示例就是用来嵌入 SIP 生僻字。
   - 子集字体的字风要与正文接近（宋体书用宋体类字体）；字体未覆盖的字再进入第 3 步。
3. **图片字回退（最后手段）**：字库中均无该字，才做字形图。规则：
   - `<img class="rarefont" src="../images/rare-2a6a5.png" alt="𪚥"/>`，文件名含码点（十六进制小写）；没有码点（造字）时用 `rare-<内容哈希前 8 位>`。【书】原书命名 `RareFont943B.png`，不强制大小写，但应统一。
   - alt 必须是对应的字符本身（可复制、可搜索、可朗读）；确无 Unicode 码位时 alt 写读音或描述，如"（左言右秀）"。
   - 尺寸：以 256×256 或更高绘制（书中 128 px，现代高清屏偏低）；透明背景 PNG；或 SVG（`fill="currentColor"`，首选，夜间模式下自动变色）。
   - CSS：`img.rarefont{height:1em;width:auto;margin:0;padding:0;vertical-align:-0.12em}`；【书】用 `vertical-align:middle`，基线偏移 -0.12em【补，需实测校准】。
   - 夜间模式问题同 1.7：透明黑字在深底消失，须按 1.7 处理。
4. **不处理的情形**：PUA 字符（含义取决于特定字体，无法映射）→ 告警；`□`、`〓` 占位 → 告警并列出上下文，等人工补字，不要擅自用图片/字体"猜"。

处理决策表（每个码点一次）：
```
码点 ∈ L0                         → 无动作
码点 ∈ L1/L2/L3 且 已有内嵌字体含字 → 确认 font-family 已命中
否则，若存在许可允许的候选字体含字   → 方案 2（子集嵌入 + unicode-range 回落）
否则                              → 方案 3（图片字，alt=字）
```

## 4 字体

### 4.1 何时嵌入

嵌入字体的代价：体积（中文字体全量 5–20 MB）、版权、渲染差异、RS 允许用户覆盖字体。结论：
- **不嵌入**：正文使用 RS 默认字体（用户可自由切换）；仅写字体栈 `font-family:serif` 之类的通用族。这是默认策略。
- **应嵌入**：书中使用了系统常见字体中没有的字：生僻字（见 3）、特殊标题字体（艺术字、楷体题词）、诗歌/古籍专用字体、竖排标点所需的特定 OpenType 特性。
- **可选嵌入**：全书统一的特定宋体/楷体版面，代价是体积；仅在用户明确要求时嵌入，且必须子集化。
- 嵌入就必须配字体栈回落：`font-family:"SubsetKai","Kaiti SC","KaiTi",serif`，末尾通用族。

### 4.2 格式与 media-type

| 格式 | media-type（3.3 CMT） | 说明 |
|---|---|---|
| TrueType（.ttf） | `font/ttf`（旧：`application/font-sfnt`、`application/x-font-ttf`） | 兼容最广 |
| OpenType（.otf，CFF/TT） | `font/otf`（旧：`application/vnd.ms-opentype`） | 兼容广 |
| WOFF | `font/woff`（旧：`application/font-woff`） | 压缩 TTF/OTF |
| WOFF2 | `font/woff2` | Brotli 压缩，体积最小；EPUB 3.3 RS 规范要求 RS 支持 TrueType、OpenType、WOFF、WOFF2 经 `@font-face` 引用 |
| TTC/OTC 字体集合 | 非 CMT | 不可直接嵌入，须抽取单个字体 |
| EOT、SVG 字体、Type1 | 非 CMT | 不使用 |

建议：默认输出 **WOFF2**（体积通常比 TTF 小 30–50%），`@font-face` 写 `format("woff2")`；兼容 profile 可同时输出 TTF/OTF 并列在 `src` 里，但会增加体积，仅在需要时。旧媒体类型字符串（`application/x-font-ttf`、书中例）应改为 `font/ttf`，EPUBCheck 对废弃类型给出警告。"RS 支持 WOFF2"为规范要求，但老 RS 可能不支持【需实测】。

可变字体（Variable Font）：先用 fonttools `instancer` 固定到所需字重/宽度再子集；是否直接嵌入可变字体在各 RS 表现不一【需实测】。

### 4.3 子集化原理：按 CSS 确定每个字体覆盖的字符

目标：对每个 `@font-face`，求出"书中可能用该字体渲染的字符集"，只保留这些字形。流程：

1. **解析样式**：收集所有来源，按 CSS 层叠顺序：外链（`<link rel="stylesheet">`）、`@import`、`<style>`、行内 `style`；处理 `@media`（保守：全部并入）；`!important`；选择器特异性（id > class/属性/伪类 > 元素）与出现顺序。
2. **计算每个文本节点的 font-family**：对每个元素算出最终 `font-family` 值（含继承：`font-family` 默认继承），得到字体栈 `[F1, F2, …]`。`font` 简写、`inherit/initial` 要展开。文本节点归属于其父元素。
3. **伪元素与生成内容**：`::before/::after{content:"…"}`、`counter()`、`attr()`、列表项目符号（`list-style-type` 生成的字符）、`::first-letter`、`::first-line` 的字符要加入集合；`text-transform:uppercase` 会改变字符，需先映射。
4. **匹配 `@font-face`**：对栈中每个 family 在 `@font-face` 表里按 `font-weight`、`font-style` 找到具体字体面（同一 family 多个面时，粗体用 bold 面，找不到则 RS 合成伪粗体）；若有 `unicode-range`，只取范围内字符。
5. **字符分配（保守策略）**：对节点中的每个字符 `c`，沿栈从左到右找第一个"能渲染 `c`"的字体：内嵌字体用 `cmap` 查；系统字体或通用族无法得知覆盖，只能假定它能渲染。因此：栈中有内嵌字体且排在系统字体之前 → 该字符加入该内嵌字体；内嵌字体排在系统字体之后 → RS 可能不会走到它，但为应对系统字体缺字的回落，仍把字符加入。最终规则：**把字符加入栈上所有内嵌字体**，宁多勿漏；若某内嵌字体自己缺该字，记入缺失清单（见第 8 步）。
6. **加入固定字符**：ASCII 0x20–0x7E、全部本书用到的标点、书中的数字、空格 U+0020/U+00A0/U+3000；`.notdef`；可选的 GB 常用字补充（见保险集）。
7. **附加来源**：nav 文档、NCX 标题（RS 的目录界面常用正文字体）、`<title>`、SVG `<text>`、MathML `<mtext>`、`alt` 不渲染，无需加入。
8. **失败保护**：字体缺字时子集器记录缺失码点，反馈到 3.2 的回落/图片字流程；不能静默丢字。
9. **保险集**（可选）：为避免用户后续编辑或 RS 重排，对**正文字体**按 GB2312 一级字 3755 字再加一遍，仅在体积预算内。

规范化前置：文本规范化（06）必须在子集化之前完成，否则全角→半角、引号转换后新出现的字符缺字。

判定输出：每个内嵌字体一份"字符清单 + 来源节点数 + 缺失字符"报告，便于审阅。

### 4.4 子集工具参数与 OpenType 特性

使用 fonttools `pyftsubset`（或 API `fontTools.subset`）：

```bash
pyftsubset Font.otf --text-file=chars.txt --flavor=woff2 \
  --layout-features='vert,vrt2,vkna,vhal,valt,vpal,vkrn,ruby,locl,ccmp,kern,palt,halt,hwid,fwid,pwid,jp78,jp90,trad,smpl,hojo,nlck' \
  --glyph-names --notdef-outline --name-IDs='*' --name-languages='*' \
  --no-hinting --desubroutinize --ignore-missing-glyphs
```

要点：
- **默认会丢特性**：`pyftsubset` 默认只保留少量布局特性，竖排与字形替换可能消失，需显式列出；【书·我】`vert`/`vrt2` 书中已提到。
- **应保留的特性**（CJK）：
  - 竖排：`vert`（竖排字形替换，如竖排标点）、`vrt2`（含旋转，部分字体用）、`vkna`、`vhal`、`vpal`、`vkrn`、`valt`；缺 `vert`，竖排时标点不会变位置。
  - `ruby`：注音假名/拼音所用字形（日语字体常见），RS 的 ruby 排版可通过 `font-variant-east-asian: ruby` 启用。
  - `locl`（区域字形，zh-Hans/zh-Hant/ja 等字形选择）、`ccmp`（组合）、`kern`、`palt/halt/chws`（标点压缩）。
  - `hwid/fwid/pwid/qwid`、`jp78/jp90/trad/smpl`（字形变体）；仅在 CSS 用了 `font-feature-settings`/`font-variant-east-asian` 时才需要。
- **IVS/cmap 14**：若正文用了异体字选择符，须保留 cmap 格式 14（fonttools 默认保留，但需检查 `--unicodes` 含基字）。
- **`--retain-gids`**：仅在需要稳定字形 ID 时用，默认不用（体积更小）。
- **hinting**：屏幕阅读多数 RS 对 CJK 字体 hint 不起作用，`--no-hinting` 可减 10–30%。
- **Name 表**：保留 `nameID 0/1/2/3/4/6/13/14`（版权、许可证），不要为了省体积删掉许可证条款。
- 输出再次验证：用子集字体在渲染器中对全部字符测试无 `.notdef`；对子集前后的 `cmap` 对比。
- 同一字体多个字重分别做子集（Regular/Bold），分别 `@font-face`。
- 文件名只用 ASCII、小写、无空格：`kaiti-subset.woff2`。

### 4.5 字体混淆（obfuscation）

字体混淆是 OCF 规范定义的轻度处理，不是加密，不改变授权状态；目的是防止在 EPUB 容器内被随手提取，并满足某些字体许可证对"不得提供可直接提取的字体"的要求。

- 声明位置：`META-INF/encryption.xml`：
  ```xml
  <encryption xmlns="urn:oasis:names:tc:opendocument:xmlns:container">
    <EncryptedData xmlns="http://www.w3.org/2001/04/xmlenc#">
      <EncryptionMethod Algorithm="http://www.idpf.org/2008/embedding"/>
      <CipherData><CipherReference URI="fonts/kaiti-subset.otf"/></CipherData>
    </EncryptedData>
  </encryption>
  ```
- **IDPF 算法**（`http://www.idpf.org/2008/embedding`）：取包的 unique-identifier（`dc:identifier` 中被 `package@unique-identifier` 指向的那一个）文本，去掉空白字符（U+0020、U+0009、U+000D、U+000A），UTF-8 编码后算 SHA-1，得 20 字节密钥；对字体文件前 1040 字节，逐字节异或密钥（循环，下标 `i%20`）。解混淆用同一操作。
- **Adobe 算法**（`http://ns.adobe.com/pdf/enc#RC`）：密钥来自 `urn:uuid:` 去掉前缀和 `-` 后的 16 字节，只处理前 1024 字节，循环使用 16 字节密钥；EPUB 3 规范不使用。仅在遇到旧书时读取。
- 注意：
  - 混淆在压缩之前基于原始字节进行；改 `dc:identifier` 后必须重新混淆，否则字体损坏。【补】优化软件如果改动了 unique-identifier，须处理所有混淆字体。
  - 只能对字体资源使用混淆；其他资源混淆不属于规范。
  - 许可证要求"不得可提取"时，混淆不足以作为合规保证，只是行业惯例；以字体许可为准。
  - 优化软件处理已混淆字体：先解混淆 → 子集 → 若原书有混淆则重新混淆（需要 identifier）；没有 encryption.xml 的书不要擅自添加。
  - `mimetype` 与 `encryption.xml` 以外的 DRM（如 Adobe ADEPT、Apple FairPlay）不处理，遇到整体加密的书直接拒绝。

### 4.6 版权与 fsType

OS/2 表 `fsType`（嵌入许可位）：

| 位值 | 含义 | 对 EPUB 的处理 |
|---|---|---|
| 0x0000 | 安装式嵌入（Installable） | 可嵌入 |
| 0x0002 | 受限许可（Restricted），禁止嵌入 | **不得嵌入**；告警并让用户换字体 |
| 0x0004 | 预览与打印嵌入（Preview & Print） | 只读使用；电子书阅读属于只读显示，通常可嵌入【需核实许可文本】 |
| 0x0008 | 可编辑嵌入（Editable） | 可嵌入 |
| 0x0100 | 禁止子集化（No subsetting） | **不得子集化**，只能整体嵌入或不嵌入 |
| 0x0200 | 仅位图嵌入 | 不可用于矢量字体嵌入 |

规则（可判定）：
1. 嵌入前读取 `fsType`：含 0x0002 → 阻止；含 0x0100 → 禁止子集（自动流程直接拒绝，提示整体嵌入的体积代价）。
2. `fsType` 只是技术标志，法律上以许可协议（`name` 表 ID 13/14 的许可说明、随字体发布的 EULA/OFL）为准。商业字体（方正、汉仪等）个人购买一般仅限个人非商业使用【书】；将其嵌入对外发行的书需要电子书/嵌入授权。
3. 可放心内置的：SIL OFL 1.1 字体（思源宋体/黑体 Source Han / Noto CJK、霞鹜文楷 LXGW WenKai 等）与等效开源许可。【补】OFL 含"保留字体名称（Reserved Font Name）"条款：对字体做子集化可视为修改，若字体声明了保留名，发布修改版须改名；软件应读取 `name` 表版权声明并在子集输出中重命名字体族并写明来源与许可。【需核实具体字体的 RFN 声明】
4. 软件不得自动修改他人字体的 `fsType` 来绕过限制。书中（9.4）提到改许可位是为了让多看接受字体，此做法涉及版权，规范化工具只应对许可证允许修改的字体做，且提示用户。
5. 在书内记录字体来源与许可（可放在版权页或 `<meta>`/`dc:rights` 附录）。

### 4.7 体积预算（【补】经验值，可配置）

| 项 | 预算 |
|---|---|
| 单个中文正文字体子集（约 3000–6000 字，WOFF2） | 一般 200–800 KB；> 1.5 MB 告警 |
| 仅标题/题词/生僻字用的小字体 | < 100 KB |
| 全书字体总量 | ≤ 3 MB，且 ≤ 全书体积的 30%（图片极少的纯文字书，字体可占更高，需提示） |
| 字体数量 | ≤ 4 个字体面（Regular/Bold 各算一个） |
| 未子集的全字库 | 禁止（> 5 MB 一律告警，除非 `fsType` 禁止子集且用户确认） |

体积超限时的对策顺序：去重（相同字体不同路径只留一份）→ 合并字符集（同一字体多面共享）→ `--no-hinting` → WOFF2 → 删除不必要的 layout feature → 去掉保险字符集 → 减少字体数量 → 回退使用系统字体。

## 5 对优化软件的含义

可自动检测/修复（A）、建议确认（B）、仅告警（C）：

**图像**
- A：检查 manifest `media-type` 与文件魔数一致，并修正；非 CMT 格式转为 JPEG/PNG（WebP 视 profile）。
- A：CMYK/16bit/非 sRGB 转 8bit sRGB，剥离 EXIF，应用方向；PNG 重新压缩（PNG-8 候选）。
- A：缺失 `alt` 属性补成 `alt=""` 并标"待确认"；alt 为文件名则清空并提示。
- B：缩小超尺寸图；重编码超体积 JPEG；去白边（用 1.4 阈值，超保护阈值的转建议）。
- B：带 alpha 的深色/浅色图按 1.7 压平。
- C：宽高比异常、SVG 无 `viewBox`、含脚本或外链、装饰图缺 `alt=""`、大模型生成的 alt 草稿需人工确认。

**封面**
- A：补/修 `cover-image` 属性（只能一个，类型合法）；EPUB 2 `meta name="cover"` 同步；nav landmarks 加 `cover`。
- B：封面比例/尺寸自适应（补边）；封面页重写为 1.3 推荐写法。
- C：低分辨率、白边、关键信息超出安全区。

**生僻字**
- A：按 3.1 码位表统计 L1–L3、PUA、占位符，生成覆盖报告。
- B：能用开源字体覆盖的字走"子集嵌入 + `unicode-range` 回落"；无字库的字生成字形图建议（命名、alt、CSS 模板）。
- C：PUA、`□`/`〓`、表意描述符拼字。

**字体**
- A：旧 media-type 改 `font/*`；WOFF2 转换；TTC 拆分；文件名转 ASCII。
- A：按 4.3 构建每个字体的字符集并子集化，保留 4.4 特性，缺字报告。
- A：检查 `fsType`（0x0002 阻止、0x0100 禁止子集），读取许可证并写入报告。
- B：OFL 字体子集后改名；已混淆字体的解混淆—子集—重混淆流程；体积超预算的对策。
- C：商业字体授权不明、可变字体 RS 兼容、字体族缺回落通用族。
