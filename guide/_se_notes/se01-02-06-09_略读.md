## 第 1 章　代码风格（XHTML / CSS）

> 总判断：这一章几乎全是「序列化器输出格式」规则，不影响阅读效果，价值在于**输出稳定、可 diff、幂等**（07 §0.2 第 3 条要求修复幂等）。因此一律做成「序列化选项」，不作为质检规则报错；对用户原有内容只在我们改写的文件上套用。

### SE 1.1 第 1–2 条　XHTML 文件头：XML 声明 + 根元素
- SE 原规则：首行 `<?xml version="1.0" encoding="utf-8"?>`，次行 `<html xmlns=… xmlns:epub=… xml:lang="…">`；`utf-8` 小写。
- 我们现状：01 §6.2 nav 模板只有 `<!DOCTYPE html>` + `xmlns/xmlns:epub/xml:lang/lang`，无 XML 声明；A11Y-002 要求根上同时有 `lang` 与 `xml:lang`。
- 结论：修改后采用
- 落地：序列化器统一输出 `<?xml version="1.0" encoding="utf-8"?>` + `<!DOCTYPE html>` + 根元素（SE 无 DOCTYPE，我们保留，HTML5 合法）；`xml:lang` 与 `lang` 并写，值取自 `lang.primary`；`epub:prefix` 一律不写（我们不用非保留前缀，`z3998:` 也不用）；编码声明小写 `utf-8`。可作为 SEM 类的 auto 规则（已有则合并）。

### SE 1.1 第 4 条、1.1.2 第 2 条　标签名、属性名、属性值小写；语言标签仅国家子标签大写
- SE 原规则：标签、属性、命名空间、属性值全部小写；IETF 语言标签保持规范大小写（`en-US`）。
- 我们现状：无明确规则（02 §1 讲 XML 良构，未提大小写）。
- 结论：采用
- 落地：解析→序列化时标签/属性名天然规范化；值层面仅对 `epub:type`、`role`、`rel` 等枚举值转小写；`lang`/`xml:lang` 值按 BCP 47 规范大小写（`zh-Hans`、`zh-CN`）。注意：`id`/`class`/`href` 的值**不得**改大小写。

### SE 1.1.2 第 1 条　属性按字母序
- SE 原规则：元素属性按字母序排列。
- 我们现状：无。
- 结论：修改后采用
- 落地：序列化器选项 `xml.attr_order=alpha`（默认开）。属性顺序无语义，开启后输出稳定、幂等；只在写出的文件上生效，不单独产生「问题报告」。命名空间声明（`xmlns*`）置于最前。

### SE 1.1 第 5 条　仅含 phrasing content 的元素写成单行
- SE 原规则：`<p>` 等元素内容为行内内容时，开闭标签与文字之间无空白、不换行。
- 我们现状：无；02 §3 要求「一个自然段=一个 `<p>`，段内不含 `\n` 以外的硬换行」，方向一致。
- 结论：修改后采用
- 落地：序列化器对叶子块（见 07 §0.3 `@BLOCK`）输出单行、紧贴标签。**例外**：`pre`、`textarea`、`[xml:space=preserve]`、CSS `white-space:pre*` 的元素内部不动；块与块之间缩进只在「块级容器的子节点」处加，行内混排文本中的空白不得增删（中文行内空白敏感度低，但 `<span>` 之间的空格仍可能有意义）。

### SE 1.1.1 第 1–4 条　`<br/>` 的书写
- SE 原规则：`<br/>` 紧跟前面文字、后接换行；换行后缩进与上一行持平；闭合标签与最后一行同行；`<br/>` 前后都必须有文字（不得末尾孤立 `<br/>`）。
- 我们现状：02 §10 诗歌用 `<p class="stanza">` + 行间 `<br/>`，禁止 `<br/><br/>` 分段；无格式与「首尾孤立 br」规则。
- 结论：采用
- 落地：(1) 序列化格式照 SE（`行1<br/>⏎行2</p>`，续行不加缩进）；(2) 新增检测「块首/块尾孤立 `<br/>`」→ auto 删除（SEM 类，P1）；(3) 与现有「连续 `<br/><br/>` 重建为 `<p>`」规则并列，先处理连续 br，再处理首尾 br。

### SE 1.1 第 3 条　用 Tab 缩进
- SE 原规则：缩进用 Tab。
- 我们现状：无。
- 结论：修改后采用
- 落地：序列化选项 `xml.indent`，默认 Tab（体积最小、与 SE 一致，阅读器无差别）；允许配置为 2 空格。**不对用户原有文件做「仅为缩进」的重写**：只有当文件因其他修复而重新序列化时才统一缩进，避免产生满篇 diff。

### SE 1.2 第 1 条　CSS 文件头
- SE 原规则：前两行 `@charset "utf-8";` 与 `@namespace epub "http://www.idpf.org/2007/ops";`。
- 我们现状：04 / 07 CSS 类未见 `@charset` 要求【待核】。
- 结论：修改后采用
- 落地：我们生成/重写的 CSS：首行 `@charset "utf-8";`（必须为首字节开始、无 BOM、双引号，否则无效）；`@namespace epub …` **仅当**样式里确实用了 `[epub|type…]` 选择器时才写（SE 因大量使用 `epub:type` 选择器而固定写，我们的 `04` 模板以 class 为主，不需要）。对用户已有 CSS：缺 `@charset` 且含非 ASCII 字符时 suggest 补上。

### SE 1.2.1–1.2.2　CSS 书写格式
- SE 原规则：选择器各占一行、逗号紧贴；规则间恰一个空行；右花括号独占一行；每个声明独占一行、Tab 缩进；`prop: value;` 冒号后一空格；末条声明也带分号；选择器/属性/值小写。
- 我们现状：无。
- 结论：采用
- 落地：CSS 序列化器（`css.format=se`）：只用于 `04` 模板输出与「被修改过的用户 CSS」。用户 CSS 中的注释、`@font-face`、`@media` 须保留；`url()` 与字符串内的大小写不得小写化；自定义属性（`--x`）名区分大小写。

### SE 1.2.2 第 2 条　声明按字母序「尽量」
- SE 原规则：属性尽可能按字母序；若需覆盖前一声明则例外。
- 我们现状：无。
- 结论：修改后采用
- 落地：仅对**我们自己的模板**（04）排序；**不对用户 CSS 重排**。理由：中文排版常见「回退声明在前、新声明在后」（如 `writing-mode` 前缀、`text-emphasis` 前缀、`hanging-punctuation`），简写/展开属性的先后也有语义，自动排序易破坏层叠。

### SE 1.2.2 第 6 条　数值省略前导 0（`.5em`）
- SE 原规则：`margin: .5em`，不写 `0.5em`。
- 我们现状：无；04 模板通常写 `0.5em`。
- 结论：修改后采用（低优先）
- 落地：仅作为生成模板的书写习惯，不做检测规则，不改用户 CSS。收益只是几字节，且与本项目「中文排版易读」的模板维护无关，可忽略。

### SE 1.2.2 字体小节　字号：孤立改字号用 `larger/smaller`；不小于 `1em`
- SE 原规则：单独调整字号时用关键字 `larger`/`smaller`；彼此相邻对比的几级字号可用具体单位；字号尽量不小于 `1em`。
- 我们现状：A11Y-013 / STY-008 要求不锁字号、避免仅 `px`；具体单位以 03 为准【待核】。
- 结论：修改后采用
- 落地：采纳「相对单位、不用 px 锁死」与「孤立缩放用关键字」。**不采纳「不小于 1em」**：中文书的注释、题注、页眉、小号署名常为 `.85em–.9em`，以 03 的字号层级为准；该条不入检测。

**本章跳过**：1.3 SVG（同 XHTML 规则；我们不做 SVG 封面/书名页）、「Commits and Commit Messages」（SE 的 git 工作流，与本软件无关）、`se clean`/`se lint` 工具本身。

## 第 2 章　文件布局与命名

> 总判断：SE 的目录树（`src/epub/text|css|images`、`LICENSE.md`、`onix.xml`、`images/cover.svg` 等）是 git 仓库工作树，我们处理的是现成 EPUB，容器内路径沿用 01 §2.3 的「小写 ASCII + 分目录」策略即可。有价值的是**章节文件命名约定**与**lint 豁免文件**。

### SE 2.1　目录职责划分（text / css / images 分开）
- SE 原规则：正文 XHTML 在 `text/`，样式在 `css/`，图片在 `images/`；`toc.xhtml` 与 `content.opf` 在 `epub/` 根。
- 我们现状：01 §2.3 已有「`text/ images/ styles/ fonts/` 分目录」（用 `styles` 而非 `css`）。
- 结论：采用（已具备，无需改动）
- 落地：无。仅确认：目录名是习惯，不是规范要求，且重命名/移动须同步全书引用（01 §2.3 已写）。

### SE 2.2 第 1 条　文件名中的数字不补前导 0
- SE 原规则：`chapter-1.xhtml`，不写 `chapter-01`。
- 我们现状：01 §2.3 规定「序号补零 `chapter-001.xhtml`，保证字典序=阅读序」。
- 结论：不采用（与我们的目标冲突）
- 落地：保留补零。SE 能不补零是因为其工具按 spine 而非文件名排序；我们要兼容用户在文件管理器、旧阅读器、`zip` 列表里按文件名看到阅读序。**但补零位数应由全书章数决定**（`max(2, ceil(log10(N+1)))`，而不是固定 3 位），在 01 §2.3 补一句。

### SE 2.2 第 3–5 条　分部与章的命名
- SE 原规则：分部文件 `part-N`/`book-N`；章节 `chapter-N`；若各部内章号重新计数用 `chapter-X-N`（X=部号），章号连续则 `chapter-N`；极短篇（诗集）整书一个文件。
- 我们现状：01 §2.3 只有通用字符集策略和 `chapter-001`、`part-1`、`appendix-a` 示例，无「分部时章如何命名」规则。
- 结论：修改后采用
- 落地：在 01 §2.3 增补命名表：`part-NN`（卷/部/编/篇）、`chapter-NN`（章/回/节）；章号在各部内重计 → `chapter-PP-NN`（两段均补零且同宽）；章号连续 → `chapter-NNN`。中文对应：卷、部、编→`part`；章、回→`chapter`；`book-N` 仅用于原书自称「Book/卷」且与 part 并存时。属 STR 类重命名，**默认 suggest**（呼应 01 §2.3「书无问题仅命名不雅默认不改」）。

### SE 2.2 第 6–8 条　前后辅文按「类型」命名，同类多个加 `-N`
- SE 原规则：frontmatter/backmatter 文件名取自文件**类型**而非标题（《作者的话》→`preface.xhtml`）；同类多个 `preface-1`、`preface-2`。
- 我们现状：01 §6.3 landmarks 已用 `epub:type` 词表；命名策略里无「类型→文件名」映射。
- 结论：采用
- 落地：新增映射表（以 epub:type 为基准，中文标题关键词→文件名）：序/前言/自序/代序→`preface`；后记/跋→`afterword`；引言/导论→`introduction`；致谢→`acknowledgments`；附录→`appendix-N`；参考文献→`bibliography`；索引→`index`；版权页→`copyright-page`；目录页→`toc`（但 nav 文档用 `nav.xhtml`）；注释集→`endnotes`。同类多个按出现序 `-N`。识别依据与 landmarks 自动生成共用同一套「文件角色」推断，避免两处各写一份。

### SE 2.2 第 2 条　短篇/散文按作品标题（URL-safe）命名
- SE 原规则：文集中的单篇用其标题 slug 命名（`the-variable-man.xhtml`）。
- 我们现状：无。
- 结论：修改后采用（默认关闭）
- 落地：中文标题 slug 须拼音转写，易出错且长。默认文集单篇用 `chapter-NN`（或 `story-NN`）；提供选项 `name.slug=pinyin`（依赖拼音库，生成后做冲突检测与长度截断 ≤ 100 字节）。属 P2。

### SE 2.2 第 9 条　插图命名 `illustration-N`
- SE 原规则：非封面图片文件名为 `illustration-N`，N 按出现次序。
- 我们现状：01 §2.3 只定字符集；RES 类里有「按内容改扩展名」，无按用途命名。
- 结论：采用
- 落地：重命名图片时：封面→`cover.<ext>`；正文图→`image-NNN.<ext>` 或 `illustration-NNN.<ext>`（按文档出现序，同图多处引用只命名一次）；公式图/装饰图可用 `deco-N`。属 RES 重命名，同步改全部引用（01 §2.3 已列清单）。默认 suggest。

## SE 2.3　`se-lint-ignore.xml`（按书豁免）

### 它是什么
SE 的 `se lint` 是启发式检查，会误报。作者可在**书籍仓库根目录**放一个 `se-lint-ignore.xml`，对该书声明「这些检查码在这些文件上不要报」。文件可选；不存在即无豁免。

### 格式（手册原文）
```xml
<?xml version="1.0" encoding="utf-8"?>
<se-lint-ignore>
	<file path="introduction.xhtml">
		<ignore code="t-002">
			<reason>Punctuation is deliberately placed outside of quotes in this ebook to prevent confusion with mathematical symbols and formulas.</reason>
		</ignore>
	</file>
	<file path="tractatus-logico-philosophicus.xhtml">
		<ignore code="s-021">
			<reason>The &lt;title&gt; tag is accurate; the work title appears in the half title.</reason>
		</ignore>
		<ignore code="t-002">
			<line>3</line>
			<line>18</line>
			<reason>…</reason>
		</ignore>
	</file>
</se-lint-ignore>
```
- 根元素 `<se-lint-ignore>` → 若干 `<file path="…">`（相对仓库根的路径；**支持 shell 风格通配**，如 `chapter-*.xhtml`）→ 每个 file 下若干 `<ignore code="…">`。
- `<ignore>` 含：零或多个 `<line>`（行号，限定到具体行）；**恰好一个** `<reason>`（必填的人话理由，供后来者审阅）。
- 空文件即 `<se-lint-ignore></se-lint-ignore>`。

### 匹配粒度
- 三层：**文件（含 glob）× 规则码 × 可选行号**。没有「全书只按规则码」的写法（要全书豁免须写 `path="*"` 之类通配，手册未明说【按 glob 语义推断】）；没有选择器/XPath 粒度。
- 一条 `ignore` 只对应一个 code；同一 code 要豁免多个文件需重复写，或用 glob。
- 理由是强制字段：不写理由不合格。

### 我们做「按书豁免」时的借鉴与改造
1. **三要素保留**：`{规则 ID, 文件范围, 理由}`，理由**必填**（审阅/回看用），与 07 §0.2 第 5 条的 `{rule_id, file, selector}` 对齐，并补上 `reason`。
2. **文件范围支持 glob**（沿用 shell 风格），并明确「省略 file = 全书」，比 SE 更省事。
3. **不要以行号为主定位**。SE 的行号稳定是因为人工维护源码；我们的工具会**重序列化**文件，行号随时变化。改用 `selector`（CSS/XPath，07 已有 `selector` 字段）或「文本锚点」（含该片段的前后各 N 字）。行号仅作人工输入便利、不入持久化。
4. **路径要抗重命名**：本软件自己可能重命名文件（STR-013 / RES 重命名）。豁免记录存**原始路径**，并在每次运行时用「原路径→新路径」映射解析；或同时匹配 `epub:type`/标题等角色属性。输出新包后，生成新的豁免文件并同步改路径。
5. **存放位置**：不写进输出 EPUB（原则 4：不往别人的书里加东西；OPF 里放自定义 `<meta>` 也违背「只用标准词汇」）。做成**旁路文件**：`<书名>.epub.typeset-ignore.json`（与 EPUB 同目录），或用户配置目录下以「`dc:identifier` + 内容哈希」为键的存档。格式建议 JSON/YAML，不用 XML（我们是 Python/JS 工程，生态上 XML 并无优势），字段示例：
   ```json
   { "version": 1,
     "ignore": [
       { "rule": "TXT-014", "file": "text/poem-*.xhtml", "reason": "现代诗，保留半角省略号", "selector": null },
       { "rule": "TYP-003", "file": "text/cover.xhtml", "reason": "有意的全屏封面" },
       { "rule": "TXT-021", "reason": "科技书：千分位半角逗号（全书）" }
     ] }
   ```
6. **语义**：被豁免的问题不隐藏——在报告中降级为 `waived` 并带理由；对应 auto 修复**跳过**该范围，保证幂等。
7. **未使用的豁免**（规则不再触发/文件不存在）在报告里列为 `info`，提示清理（SE 手册未写，是我们的补充）。
8. **与配置项区分**：`indent.em`、`punct.profile` 这类「风格参数」不放在豁免里（07 §0.2 第 6 条）；豁免只用于「这一处是有意的例外」。
9. **交互**：UI 里「忽略此问题」一键写入，自动带上规则、文件、selector，并弹出必填的理由输入框。

## 第 6 章　目录 nav 与 landmarks（节选）

> 总判断：SE 的 toc/landmarks 规则可借鉴「条目文字如何从标题派生」和「landmarks 收哪些」。titlepage、imprint、colophon、uncopyright 的目录条目、标题页/版本页模板均跳过。

### SE 6.2.1 第 1–3 条　nav 结构：首个 nav 为 toc，内含标题 + `<ol>`
- SE 原规则：body 第一个子元素是 `nav[epub:type=toc]`，其首子元素为标题，次为 `<ol>`。
- 我们现状：01 §6.2 模板同样为 `nav` → `h1` → `ol`；`role="doc-toc"` 已有。
- 结论：采用（已具备）
- 落地：无。可在 07 里加检查「`nav[toc]` 的直接子节点仅为一个标题和一个 `ol`」（epubcheck 对此有 schema 约束，已覆盖，不必新增）。

### SE 6.2.1「`<li>` descendants」第 1–2 条　`li` 以 `a` 开头；有嵌套 `ol` 时 `a` 指向该节起点
- SE 原规则：每个 `li` 含 `a`，可选再含 `ol`；含嵌套 `ol` 时，`li` 的第一个子元素必须是指向该节起点的 `a`。
- 我们现状：01 §6.2 示例有此写法，但无显式规则；EPUB 规范允许用 `span` 做无链接的分组标题。
- 结论：修改后采用
- 落地：07 增加规则（STR 类，warning）：`li` 含子 `ol` 时首子应为 `a`（点击可达该部/卷首）；自动重建 nav 时「部」「卷」条目链接到 `part-N.xhtml`（或其首个章节）。仅当该分组确无落点页时才允许 `span`（保留原样，不强改）。

### SE 6.2.1「`<a>` descendants」　目录条目文字由标题派生，剥离语义标注
- SE 原规则：条目文字取标题（`h1–h6`）的内部 XHTML，但去掉 `title`/`subtitle`/序数等语义标注；有 `hgroup` 时取主标题，章节级丢弃副标题，卷/部/编级保留，主副标题用「冒号+空格」连接；目录里**不含**只在标题里用的语义。
- 我们现状：01 §6.2 要求「条目文字=目标位置的标题文字」，条目文本不含页码/点线/装饰符；未规定标题含序号/副标题/内联标注时怎么取。
- 结论：修改后采用
- 落地：在 01 §6.2 增补「条目文字生成」：(1) 取标题的**纯文本**，丢弃 `id`、`epub:type`、`role`、`class`、`<a epub:type=noteref>` 及其上标（标题里混入的注释引用要去掉）、`<sup>`；(2) 保留 `<ruby>`/`<rt>` 结构（注音对目录同样有用）或退化为基字，由配置决定；(3) 序号与标题分处不同元素时，以**一个空格**连接（如「第一章」+「开端」→「第一章 开端」，与现有 6.2 示例一致；是否用全角冒号可配置 `nav.subtitle_sep`，默认空格）；(4) 副标题：章节级丢弃，卷/部/编级保留（照搬 SE 判据）。此规则同时服务 07 STR 中「条目文字与标题一致」的比对（比对时先做同样的归一化）。

### SE 6.2.2 第 1–2 条　landmarks：第二个 nav，标题 + `ol`
- SE 原规则：toc 之后再放 `nav[epub:type=landmarks]`，首子标题，次子 `ol`。
- 我们现状：01 §6.3 已有且加 `hidden=""`、标题 `h2` 「导览」。
- 结论：采用（已具备）
- 落地：无。

### SE 6.2.2 `<li>` descendants 第 1 句　landmarks 只收「正文起点」与「主要参考性后置部分」
- SE 原规则：landmarks 条目只指向正文起点（bodymatter 起点，不含半书名页），或主要参考类后置部分（尾注、参考书目、术语表、索引、图表目录等）。依据 IDPF a11y 最佳实践。
- 我们现状：01 §6.3 示例含 cover、titlepage、toc、bodymatter；常用值表列了 `bibliography/index/glossary/acknowledgments` 等，但未限定「不要把所有章节都放进去」。
- 结论：修改后采用
- 落地：01 §6.3 增补：landmarks **不是第二份目录**——只收：`cover`、`titlepage`、`toc`、`bodymatter`（正文起点，仅一个）、以及 `endnotes`/`bibliography`/`glossary`/`index`/`loi`/`lot` 等参考类后置部分；`preface`/`foreword` 等序言类可选（SE 不收，我们保留为可选，因为中文书「序」常是读者想跳转的目标）。自动生成时：条目 ≤ 约 8，同一 `epub:type` 不重复（呼应 01 已有「同一 type 不应指向两个位置」）。

### SE 6.2.2「`<li>` descendants」第 1 条　landmarks 的 `epub:type` 取目标文件顶层 section 的**计算后**语义（含 body 继承）
- SE 原规则：`a` 的 `epub:type` = 该文件顶层 `section` 的 `epub:type`，并包含从 `<body>` 继承的值（如 `backmatter endnotes`）。
- 我们现状：01 §6.3 写「由文件角色（epub:type/文件名/标题关键字）推断」，未写继承。
- 结论：修改后采用
- 落地：生成 landmarks 时先读目标文档 `body` 与顶层 `section` 的 `epub:type`（合并 body 的 frontmatter/bodymatter/backmatter 分区值），再回退到文件名/标题关键字。**多值写法【需实测/需查规范】**：EPUB 3.3 对 landmarks 的 `epub:type` 是否允许多值未在我手上核对；为稳妥，落地时只写最具体的**一个**值（如 `endnotes`，分区值放不放视实测），并用 epubcheck 验证后再定。

### SE 6.2.2 第 3 条　正文起点条目：指向正文首文件，文字取 `dc:title`
- SE 原规则：整个正文作为一个条目，指向正文第一个文件，链接文字是元数据里的书名。
- 我们现状：01 §6.3 示例文字写「正文」。
- 结论：修改后采用（做成配置）
- 落地：配置项 `landmarks.bodymatter_label`，默认「正文」，可选 `title`（用 `dc:title`）。部分阅读器把 landmarks 文字直接显示在「开始阅读」入口，用书名更友好，但各阅读器行为不一【需实测】。无论哪种，`bodymatter` 必须指向**第一个正文文件**（跳过半书名页/序言类）。

**本章跳过**：6.1 title string（SE 书名页/版本页用的署名句式）、titlepage / imprint / colophon / uncopyright 页模板与其 ToC 条目、半书名页（half title）特例、罗马数字 `z3998:roman` 的目录标注（`z3998:` 是外部词表，中文书序号用汉字/阿拉伯数字，不适用）。

## 第 9 章　元数据（节选）

> 总判断：SE 元数据章绝大部分是其自家站点约定。通用价值集中在：标题块（main/subtitle/expanded）、贡献者块与 id 命名、manifest 排序与 id 约定、无障碍元数据的排序。网址、标识符、主题词、描述（abstract/description）、来源链接（Wikipedia/LoC）、版本控制、转录者/赞助者/制作者区块、可读性（`schema:wordCount`/`educationalLevel`）均跳过。

### SE 9.3　`dc:date` 是首发日期，不再改；`dcterms:modified` 才是每次更新
- SE 原规则：`dc:date` = 首次发布时间，发布后不变；`dcterms:modified` = 最后修改时间，经常变。
- 我们现状：01 §4.2 要求每次输出更新 `dcterms:modified`；未谈 `dc:date`。
- 结论：采用
- 落地：01 §4.2 补一句：**绝不改写/补造 `dc:date`**（它是原书出版信息，我们只是再加工者）；缺失也不生成。`dcterms:modified` 继续每次写当前 UTC。07 里的 PKG 修复限定为「仅更新 modified」。

### SE 9.4（Books without subtitles / with subtitles）　标题块：main / subtitle / expanded 三条，各配 `file-as`
- SE 原规则：`dc:title id="title"` 配 `title-type=main`；副标题单列 `dc:title id="subtitle"` 配 `subtitle`；再有一条完整标题（`主标题: 副标题`）配 `expanded`；每条配 `file-as`（相同也写）。
- 我们现状：01 §4.3 示例已有 `title-type main/subtitle` 与 `display-seq`；§4.4 提示「`dc:title` 带分册后缀建议拆到 subtitle」。`expanded` 在取值表列出，未示例。
- 结论：修改后采用
- 落地：当原书 `dc:title` 形如「主标题：副标题」/「主标题——副标题」且用户确认（suggest）时，拆为三条：main、subtitle、expanded（`expanded` 保留原整串），顺序固定为 main→subtitle→expanded，`display-seq` 可省（由出现序决定，但我们已用 `display-seq`，保持一致）。`file-as`：西文标题写（去冠词 The/A）；**中文标题不强制**（01 §4.3 已写「可留空或拼音」），改与 SE「每条都写」不同，保留我们的写法。注意 EPUB 规定第一个 `dc:title` 为主标题，不可打乱。

### SE 9.4（Books with a more popular alternate title / multiple titles / numbers）　`short`、`dcterms:alternative`
- SE 原规则：常用简称用 `title-type=short`；曾用名用 `dcterms:alternative` refines 主标题；标题含数字/缩写时，加一条 `dcterms:alternative` 写出替代拼法（`80 Days`↔`Eighty Days`）以便检索。
- 我们现状：01 §4.3 取值表有 `short`；无「替代书名」规则。
- 结论：修改后采用（低优先，仅 suggest）
- 落地：对含阿拉伯数字或汉字数字的书名（《1984》/《一九八四》）、有常见简称的书名，**提示**用户是否添加 `dcterms:alternative`（或 `title-type=short`）；不自动生成。`dcterms:alternative` 作为 `refines` 属性的 epubcheck 兼容性【需实测】，如报错则退而用单独 `dc:title`+`title-type=short`。

### SE 9.8　`dc:language`：取全书主语言
- SE 原规则：`dc:language` 用 IETF 标签；多语种文件时取占主导的语言。
- 我们现状：A11Y-002 已要求；未写「混合语种取主语言」。
- 结论：采用
- 落地：在 A11Y-002 的「主语言探测」里注明：按**字符数**占比取主语言；中文书取 `zh-Hans`/`zh-CN`（与 `lang.primary` 一致）；他语种段落标 `lang`。

### SE 9.10　系列：`belongs-to-collection` 的 id 与 `collection-type`
- SE 原规则：`<meta property="belongs-to-collection" id="collection-N">`，同系列各书名称完全相同；必须配 `collection-type`（`set` 或 `series`）。
- 我们现状：01 §4.4 已有 `belongs-to-collection` 示例与嵌套系列说明。
- 结论：修改后采用（小补）
- 落地：01 §4.4 补：id 命名 `collection-N`；**必须**配 `collection-type`（`series` 为默认）；同一系列在各书中名称须逐字一致（套书导入/书库归并依赖它）。`schema:hasPart`/`schema:additionalType` 等 schema.org 扩展跳过。

### SE 9.11 / 9.12　贡献者通则：id 命名、多角色、`display-seq`、作者名取封面所见
- SE 原规则：作者 `dc:creator id="author"`（多人为 `author-1/2/…`），名字取「封面所见」；一人多角色用多条 `role` 且**角色按字母序**；仅一人时省略 `display-seq`；`file-as` 必写；`alternate-script` 写母语文字名。
- 我们现状：01 §4.3 示例用 `a1/c1/t1`；有 `role`/`file-as`/`alternate-script`/`display-seq` 取值表；规则说「`dc:creator` 可无 role」；中文作者 `file-as` 留空。
- 结论：修改后采用
- 落地：(1) 新生成的 id 用可读命名：`author`/`author-N`、`translator`/`translator-N`、`illustrator`、`editor` 等；**已有 id 不改**（可能被 `refines`、其他工具引用）。(2) 同一人多角色：多条 `role`，写出时按角色码字母序，幂等。(3) 单一同类贡献者不写 `display-seq`；多人才写。(4) `dc:creator`/`dc:contributor` 的**文本值取封面/书名页所见**，并（我们的补充，非 SE）建议清理「[日]」「（美）」「著」「译」等国别与职责后缀：保留原文入 `alternate-script`/不入，以用户确认为准，suggest。(5) `alternate-script` 仍须 `xml:lang`（01 已写）。

### SE 9.13　译者块与其角色
- SE 原规则：译者用 `dc:contributor id="translator"`（多人 `translator-N`），`role=trl`；同时注释者再加 `ann`。
- 我们现状：01 §4.3 规则「译者按【补】惯例放 `dc:contributor` 并标 `trl`」，已有。
- 结论：采用（已具备，补 `ann`）
- 落地：01 §4.3 注明「译者兼注释者→在同一人上追加 `ann` 角色」；与 SE 第 11 节「多角色字母序」配合，先写 `ann` 再写 `trl`。

### SE 9.16　其他贡献者：id 取角色全名，`ctb` 配 `display-seq=0`
- SE 原规则：序言作者、编者等用 `dc:contributor`，id 取角色英文全名（`writer-of-preface`）；署名并列的共同作者用 `ctb`，并 `display-seq=0` 以免进入全书署名。
- 我们现状：01 §4.3 `role` 取值表有 `aui`/`edt`/`ctb` 等；未涉 `display-seq=0` 的用法。
- 结论：修改后采用
- 落地：01 §4.3 补充：作序者 `aui`（序言）、`wpr`（SE 用；MARC 里 `wpr` 是 writer of preface，我们取值表已有 `aui`，二者都是合法 marc:relators，保留已有的，不替换）；仅在某一篇署名的合作者用 `ctb` 且 `display-seq=0`，使「署名行」只显示主要责任人。生成书名页/署名行时（若做）以 `display-seq≠0` 者为准。

### SE 9.20　manifest：按字母序；`id` = href 的文件名；`nav`/`cover-image`/`svg` 属性
- SE 原规则：manifest 按字母序；`id` 取 href 的 basename；含 SVG 的文件加 `properties="svg"`；目录文件 `nav`；封面图 `cover-image`。
- 我们现状：01 §5.1–5.2 已有 `properties` 推断（svg/mathml/scripted/remote-resources/nav/cover-image），不规定排序和 id 命名。
- 结论：修改后采用
- 落地：(1) **新生成**的 manifest 项按 `href` 字母序输出（稳定 diff，无语义影响）；对已有 manifest **不重排**，仅在整体重建（如合并坏 manifest，01 §10）时才排序。(2) 新建项的 `id` 取 href 的 basename **含扩展名**（`chapter-001.xhtml`，不丢扩展以免 `cover.jpg` 与 `cover.xhtml` 撞 id），并保证是合法 XML `NCName`：以字母/下划线开头（数字开头加前缀 `i-`），不含空格与 `%`，唯一。(3) 已有 id 不改，因 `spine/itemref`、`meta name="cover"`、`encryption.xml` 等会引用。(4) 关于 `svg` 属性：EPUB 规范中它标记**内嵌 `<svg>` 元素**的内容文档，而不是仅被 `<img>` 引用 SVG 文件的文档；SE 的措辞偏宽，我们仍按 01 §5.2「解析 XHTML 推断」为准。

### SE 9.21　spine：阅读顺序自动猜测不可靠，必须人工复核
- SE 原规则：工具猜 spine 次序，「输出从不 100% 正确，须人工复核」。
- 我们现状：01 §11 与 07 已规定「spine 重排」属须用户确认项；STR 规则中 spine 顺序默认保持。
- 结论：采用（印证现有原则，无需改动）
- 落地：无新增。在 01 §11 补一句理由即可：自动重排 spine 只在「书原本无 spine / spine 明显错乱」时 suggest，附预览，不 auto。

### SE 9.22　无障碍元数据：按属性分组、固定组序、组内按值字母序
- SE 原规则：无障碍元数据按属性分组，组序固定：`a11y:certifiedBy`、`schema:accessMode`、`schema:accessModeSufficient`、`schema:accessibilityFeature`、`schema:accessibilityHazard`、`schema:accessibilitySummary`；每组内按文本值字母序。目标是符合 EPUB Accessibility 规范。
- 我们现状：01 §7 示例顺序与此基本一致（缺 `certifiedBy` 在最前）；07 A11Y-003 只检存在性，不检顺序；不规定组内排序。
- 结论：采用
- 落地：(1) 序列化器写出 OPF 时按此组序、组内按值排序（幂等，无语义影响）；(2) 07 A11Y-003 备注「写入时的排列」，不作 warning；(3) `a11y:certifiedBy` 属于保留前缀 `a11y`，无需声明 prefix，且**未经评估不得写**（01 §7 已有，保持）。SE 本章只给了排序与「向 Accessibility 规范看齐」，**没有给具体取值**，所以我们 01 §7 / A11Y-003 的取值与推断逻辑保持不变，不受影响。

> **顺带发现（非 SE 来源，值得核对）**：01 §7 示例把符合性声明写成 `<link rel="dcterms:conformsTo" href="https://www.w3.org/TR/epub-a11y-11#wcag-2.1-aa"/>`，而 07 A11Y-003 写的是值为 `EPUB Accessibility 1.1 - WCAG 2.1 Level AA` 的字符串形式。按我对 EPUB Accessibility 1.1 的记忆，规范要求的是 `<meta property="dcterms:conformsTo">EPUB Accessibility 1.1 - WCAG 2.1 Level AA</meta>`（字符串值，非 `link`）。两份文档目前不一致，建议对照规范原文修正 01 §7（【需核对规范】）。

**本章跳过**：9.1 通用 URL 规则、9.2 标识符、9.5 制作说明、9.6 主题词（`dc:subject`、SE subjects）、9.7 摘要/描述、9.9 `dc:source` 与页面扫描来源、9.10 的 Wikipedia/LoC `schema:sameAs`、代码仓库 `schema:workExample`、`schema:wordCount`/`educationalLevel`、`schema:alternateName`、9.14–9.15 绘者/封面画家块（模式与作者块相同，已被 9.11 通则覆盖）、9.17–9.19 转录者/赞助者/制作者块；这些都是 SE 站点自有的发布与溯源体系，且多依赖其网址与标识符，不适用于「别人已有的书」。
